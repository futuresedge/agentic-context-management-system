## SUMMARY
This is the meta-template: the template used to create all other templates
in the DLMS corpus. It defines the required structure, schema fields, sections,
and validation rules that every template document must conform to. It is
self-referential — this document was created using the structure it defines.

## TARGET_DOC_TYPE
template

## SCHEMA

### Frontmatter_Fields
All fields are YAML frontmatter. All 19 core fields are required unless
marked nullable. Fields must appear in the canonical order defined below.
Additional doc-type-specific fields may follow audit_ref.

FIELD_01:
  name:        doc_id
  type:        string
  required:    true
  nullable:    false
  format:      DLMS-YYYY-NNNN
  immutable:   true (after first assignment)
  description: Unique system-assigned document identifier.
  constraints:
    - Assigned by Naming Convention Enforcer before Author Agent activates
    - Globally unique across all doc_types and all years
    - Never reused even after archival
    - Governed by Naming Convention Policy R01

FIELD_02:
  name:        doc_type
  type:        enum
  required:    true
  nullable:    false
  immutable:   true (after first approved version)
  values:      [policy, procedure, standard, pattern, sla, specification,
                reference, report, taxonomy, template]
  description: The document type. Determines which template is applied.
  constraints:
    - Must match the TARGET_DOC_TYPE of the assigned template
    - Governed by Document Schema Policy FIELD_02

FIELD_03:
  name:        status
  type:        enum
  required:    true
  nullable:    false
  values:      [draft, under_review, approved, superseded, archived]
  transitions:
    draft:        [under_review]
    under_review: [draft, approved]
    approved:     [superseded, archived]
    superseded:   [archived]
    archived:     []
  write_authority: Status Transition Agent only (post-creation)
  description: Current lifecycle status of this document version.

FIELD_04:
  name:        version
  type:        string
  required:    true
  nullable:    false
  format:      MAJOR.MINOR.PATCH
  start_value: 0.1.0 (all bootstrap documents)
  first_approved: 1.0.0
  write_authority: Version Control Agent
  versioning_rules:
    major: Structural — section added, removed, or renamed; field added
           or removed; breaking change to any consumer.
    minor: Content — rules updated, values revised, non-breaking additions.
    patch: Correction — typo, formatting, or factual fix with no
           semantic change.
  constraints:
    - Governed by Naming Convention Policy R13
    - A new version produces a new file; prior version files are immutable

FIELD_05:

  type:        timestamp
  required:    true
  nullable:    false
  format:      ISO 8601 with timezone offset (e.g. 2026-03-08T10:00:00+11:00)

  immutable:   true (after creation)

### Additional_Fields
Doc-type-specific fields beyond the 19 core fields are defined in the
relevant template. They must follow audit_ref in the frontmatter. They
must not duplicate or redefine any core field. Field names use
lowercase_snake_case.

Section headings are machine-readable keys (UPPER_SNAKE_CASE at ## level).

SUMMARY:
  heading:     ## SUMMARY
  required:    true
  position:    1 (immediately after closing ---)
  description: >
    A dense, factual summary of what this template defines, what it is
    used for, and what documents it produces.
  constraints:
    - Exactly 2–3 sentences
    - No narrative prose or contextual explanation
    - Must stand alone as a complete description

TARGET_DOC_TYPE:
  heading:     ## TARGET_DOC_TYPE
  required:    true
  position:    2
  description: >
    The single doc_type enum value that this template applies to.
  constraints:
    - Single value only
    - Must be one of the approved doc_type enum values

SCHEMA:
  heading:     ## SCHEMA
  required:    true
  position:    3
  description: >
    Complete specification of all frontmatter fields for documents
    created from this template. Uses the field specification format

  required_subsections:
    - "### Frontmatter_Fields" — all 19 core fields plus any additional fields

REQUIRED_SECTIONS:
  heading:     ## REQUIRED_SECTIONS
  required:    true
  position:    4
  description: >
    The complete ordered list of body sections that every document
    created from this template must contain.
  constraints:
    - Each entry specifies: heading, required, position, description,

    - Section headings are UPPER_SNAKE_CASE
    - Order is prescriptive

OPTIONAL_SECTIONS:
  heading:     ## OPTIONAL_SECTIONS
  required:    true
  position:    5
  description: >
    Sections that may appear in documents but are not required.
  constraints:
    - Each entry specifies: heading, description, when_to_include, position
    - If no optional sections exist, this section contains the
      value: none

VALIDATION_RULES:
  heading:     ## VALIDATION_RULES
  required:    true
  position:    6
  description: >
    Explicit, testable rules that documents created from this template
    must satisfy. Used by Template Validator and Stage Verifiers.
  rule_schema:
    id:          string — V prefix, two-digit sequential number (V01, V02…)
    rule:        string — declarative statement of what must be true
    test:        string — how to verify compliance; agent-parseable
    checked_by:  string — which agent performs the check
  constraints:
    - Minimum 3 validation rules
    - Every REQUIRED_SECTION must be covered by at least one rule
    - No validation rule may have a null id, rule, test, or checked_by

CHANGE_LOG:
  heading:     ## CHANGE_LOG
  required:    true
  position:    last (no body content after this section)
  description: >
    Ordered record of all versions, newest first. One entry per version.
  format:      "- v[version] | [YYYY-MM-DD] | [agent_id] | [change summary]"
  constraints:
    - Newest version appears first
    - Every version must have exactly one entry
    - Entries are immutable once written
    - Change summary is sufficient to understand what changed
      without reading a diff

## VALIDATION_RULES

V01:
  rule:     Every template document must contain all seven REQUIRED_SECTIONS
            in the prescribed order.
  test:     >
    Sections SUMMARY, TARGET_DOC_TYPE, SCHEMA, REQUIRED_SECTIONS,
    OPTIONAL_SECTIONS, VALIDATION_RULES, and CHANGE_LOG are all present
    and appear in that sequence.
  checked_by: Template Validator

V02:
  rule:     TARGET_DOC_TYPE must contain exactly one value drawn from
            the approved doc_type enum.
  test:     >
    TARGET_DOC_TYPE value IN [policy, procedure, standard, pattern, sla,
    specification, reference, report, taxonomy, template] AND is a
    single value.
  checked_by: Template Validator

V03:
  rule:     SCHEMA must define all 19 core frontmatter fields. No core
            field may be omitted or redefined with a conflicting type
            or constraint.
  test:     >
    All 19 fields (doc_id through audit_ref) are present in the SCHEMA
    Frontmatter_Fields subsection. No field type contradicts the
    Document Schema Policy definition.
  checked_by: Template Validator; Agent Format Validator

V04:
  rule:     REQUIRED_SECTIONS must include SUMMARY, at least one
            doc-type-specific content section, and CHANGE_LOG.
  test:     >
    REQUIRED_SECTIONS list includes heading == '## SUMMARY' AND
    heading == '## CHANGE_LOG' AND len(entries) >= 3.
  checked_by: Template Validator

V05:
  rule:     VALIDATION_RULES must contain a minimum of 3 rules.
            Every section named in REQUIRED_SECTIONS must be referenced
            in at least one validation rule's test field.
  test:     >
    len(VALIDATION_RULES) >= 3 AND for each section in REQUIRED_SECTIONS
    there exists at least one rule R where R.test references that section.
  checked_by: Template Validator

V06:
  rule:     Every rule in VALIDATION_RULES must specify id, rule, test,
            and checked_by. No field may be null or absent.
  test:     >
    For all R in VALIDATION_RULES:
    R.id != null AND R.rule != null AND R.test != null
    AND R.checked_by != null AND R.id matches regex ^V\d{2}$
  checked_by: Template Validator

V07:
  rule:     template_id must be 'self' (this document only), 'bootstrap'
            (Wave-1 only), or the template_id alias of an approved template.
  test:     >
    (template_id == 'self' AND doc_id == DLMS-2026-0002) OR
    (template_id == 'bootstrap' AND doc_id IN wave-1-bootstrap-list) OR
    (template_id IN approved-template-registry AND
     referenced template has status: approved)
  checked_by: Naming Convention Enforcer; Approval Gate Agent

V08:
  rule:     CHANGE_LOG must contain exactly one entry per document version,
            ordered newest-first. Entry format must be strictly observed.
  test:     >
    len(CHANGE_LOG entries) == len(version history) AND
    CHANGE_LOG[0].version == current version AND
    all entries match format: "- v[semver] | [YYYY-MM-DD] | [agent_id] | [summary]"
  checked_by: Storage Verifier; Version Control Agent

V09:
  rule:     The OPTIONAL_SECTIONS section must be present even if no
            optional sections are defined. In that case it must contain
            exactly the value 'none'.
  test:     >
    OPTIONAL_SECTIONS section exists AND
    (contains at least one section definition OR value == 'none')
  checked_by: Template Validator

## NOTES
This meta-template is self-referential: it was created using the structure
it defines. The 'self' value for template_id is reserved exclusively for
this document (DLMS-2026-0002).

v0.2.0 corrects the core field count from 16 to 19 by formally incorporating
dependencies, agent_path, and audit_ref as named core fields in the SCHEMA
section, consistent with Document Schema Policy (DLMS-2026-0004).

The retention_class values RC-1 through RC-7 are placeholders until the
Retention Schedule (Wave 5) formally defines each class.
