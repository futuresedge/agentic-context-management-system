## SUMMARY
This procedure governs the onboarding of any Governance Layer agent instance
— the twelve always-on agents that enforce document governance across the
DLMS independently of the stage pipeline. Each Governance Layer agent writes
to exactly one designated artefact; this exclusivity is a structural control
enforced during onboarding. The primary outputs are a validated operational
agent instance and a pair of onboarding audit events.

## SCOPE

Applies to:
- All twelve Governance Layer (Tier 2) agents listed in the table below
- sysadmin:dlm-sysadmin as procedure owner and separation verifier
- Audit Trail Agent as recipient of onboarding audit events

The twelve Governance Layer agents and their designated write targets:

| Agent | Functional sub-group | Designated write target |
|---|---|---|
| DoD Registry Agent | DoD/Template | Stage DoD registry |
| Template Manager | DoD/Template | Versioned template drafts |
| Template Version Controller | DoD/Template | Template version history |
| Template Validator | DoD/Template | Template compliance reports |
| Naming Convention Registry Agent | Naming/Index | naming-conventions document |
| Naming Convention Enforcer | Naming/Index | Naming validation results |
| Master Index Agent | Naming/Index | master-index.md |
| Type Index Agent | Naming/Index | index-by-type.md |
| Status Index Agent | Naming/Index | index-by-status.md |
| Tag Index Agent | Naming/Index | index-by-tag.md |
| Dependency Index Agent | Naming/Index | dependency-graph.md |
| Metrics Aggregator | Analytics | Lifecycle performance reports |

Excludes:
- Stage pipeline agents (Tiers 4–10): covered by their stage-specific
  onboarding procedures (DLMS-2026-0084 through DLMS-2026-0089)
- DLM System Orchestrator (Tier 1): covered by DLMS-2026-0081
- Any agent not listed in the table above

Executed by:
- The onboarding agent (self-check steps): S02, S03, S05, S06, S08
- sysadmin:dlm-sysadmin: retrieval, sub-group policy loading, exclusive
  access confirmation, and separation verification (S01, S04, S07)

## PREREQUISITES

P01: DLMS-2026-0014, DLMS-2026-0015, and DLMS-2026-0016 are status: approved
     or provisionally in effect.
     Additionally, for each functional sub-group:
     - DoD/Template agents: DLMS-2026-0041 (Definition of Done Policy) and
       DLMS-2026-0065 (Template Governance Policy) are in effect.
     - Naming/Index agents: DLMS-2026-0003 (Naming Convention Policy),
       DLMS-2026-0018 (Metadata Standard Policy), and DLMS-2026-0019
       (Taxonomy Policy) are in effect.
     - Analytics agents: no sub-group-specific policy prerequisite beyond
       DLMS-2026-0014/0015/0016.
     Verified by: sysadmin:dlm-sysadmin. Failure → D01.

P02: The agent's designated context package exists and contains: (a) the
     agent's designated write target schema; (b) references to
     DLMS-2026-0015 and DLMS-2026-0016; (c) the sub-group-specific policy
     references required by P01.
     Verified by: sysadmin:dlm-sysadmin. Failure → E01.

P03: Audit Trail Agent is reachable and accepting events. Verified by: test
     ping to Audit Trail Agent endpoint. Failure → E03.

## STEPS

S01: Retrieve context package.
  action: Retrieve this agent's designated context package and confirm it
          satisfies P02. Record context_package_retrieved_at (ISO 8601).
          Note the agent's designated write target for use in S04.
  actor:  sysadmin:dlm-sysadmin
  reads:  designated context package
  writes: (none — verification only)
  on_failure: → E01

S02: Validate context boundary.
  action: Confirm the READS list is limited to: (a) this agent's designated
          write target schema; (b) audit event schema (DLMS-2026-0015);
          (c) the sub-group-specific governance policy references required
          by P01. Confirm the NEVER list excludes all corpus documents not
          explicitly listed in READS, including the write targets of other
          Governance Layer agents. Any resource outside the permitted READS
          set renders the boundary invalid, per DLMS-2026-0016.
  actor:  Onboarding agent (self-check); verified by sysadmin:dlm-sysadmin
  reads:  context boundary specification within context package
  writes: boundary validation result (internal)
  on_failure: → D02

S03: Load sub-group governing policies into context.
  action: Load the sub-group-specific policy references into the agent's
          active working context:
          - DoD/Template agents: DLMS-2026-0041, DLMS-2026-0065
          - Naming/Index agents: DLMS-2026-0003, DLMS-2026-0018,
            DLMS-2026-0019
          - Analytics agent: no sub-group-specific policies beyond universal
          All agents load DLMS-2026-0014, DLMS-2026-0015, DLMS-2026-0016.
  actor:  Onboarding agent
  reads:  policy references from context package
  writes: active policy context (internal)
  on_failure: → E01 (if a required policy is not retrievable)

S04: Confirm exclusive write access.
  action: Confirm no other active Governance Layer agent instance is assigned
          the same designated write target as this agent. Exclusivity is
          checked by querying the Governance Layer agent registry for the
          write target. If a duplicate write target assignment is found, this
          instance must not proceed to S05.
  actor:  sysadmin:dlm-sysadmin
  reads:  Governance Layer agent registry; this agent's designated write
          target (noted in S01)
  writes: (none — verification only)
  on_failure: → D04

S05: Emit onboarding-start audit event.
  action: Write an onboarding-start event to the audit trail per
          DLMS-2026-0015. Required fields: agent_id, tier = 2,
          onboarding_procedure_ref = "DLMS-2026-0082",
          write_target (the agent's designated write target), timestamp
          (ISO 8601).
  actor:  Onboarding agent
  reads:  DLMS-2026-0015 (audit event schema)
  writes: audit-trail.log (onboarding-start event)
  on_failure: → E03

S06: Confirm artefact format.
  action: Demonstrate this agent can produce a structurally conformant
          output for its designated write target by generating a
          zero-content test artefact against the target schema. The test
          artefact must pass format validation without being persisted to the
          actual write target. For Template Validator specifically: confirm
          it can parse a known-conformant template and emit a valid
          compliance report with outcome: pass.
  actor:  Onboarding agent
  reads:  designated write target schema from context package
  writes: test artefact (internal, discarded after validation)
  on_failure: → E02

S07: Template Validator separation check.
  action: If this agent is the Template Validator: confirm its agent_id is
          distinct from the active Template Manager's agent_id, per
          DLMS-2026-0014 R01. No single agent instance may both author and
          validate templates. For all other Governance Layer agents: this
          step is a no-op; record "N/A — not Template Validator" and proceed.
  actor:  sysadmin:dlm-sysadmin
  reads:  Template Manager's agent_id from Governance Layer agent registry
  writes: separation confirmation note (internal)
  on_failure: → D03 (Template Validator only)

S08: Emit onboarding-complete audit event.
  action: Write an onboarding-complete event to the audit trail per
          DLMS-2026-0015. Required fields: agent_id, tier = 2,
          onboarding_procedure_ref = "DLMS-2026-0082",
          write_target, outcome [success | failure],
          separation_check_applicable (boolean),
          timestamp (ISO 8601).
  actor:  Onboarding agent
  reads:  DLMS-2026-0015 (audit event schema)
  writes: audit-trail.log (onboarding-complete event)
  on_failure: → E03

## DECISION_POINTS

D01: If P01 fails (any required policy not approved or provisionally in
     effect for this agent's sub-group) → halt. Notify sysadmin:dlm-sysadmin.
     Do not proceed until all required policies are in effect.

D02: If S02 fails (context boundary contains resources outside the permitted
     READS set) → halt. Do not initiate the agent. Notify
     sysadmin:dlm-sysadmin for context package correction before
     re-attempting from S01.

D03: If S07 fails for the Template Validator (same agent_id as Template
     Manager) → halt. Escalate to sysadmin:dlm-sysadmin. Two separate agent
     instances must be provisioned before either can be onboarded.

D04: If S04 finds a duplicate write target assignment → halt. Notify
     sysadmin:dlm-sysadmin. The conflict must be resolved by deactivating
     the duplicate instance before this agent proceeds to S05.

## OUTPUTS

| Artefact | Produced by step | Written to | Consumed by |
|---|---|---|---|
| Operational Governance Layer agent with validated context boundary | S02–S03 | internal agent state | Stage pipeline; DLM System Orchestrator |
| onboarding-start audit event | S05 | audit-trail.log | Audit Trail Agent; Agent Behaviour Analyst (CI) |
| onboarding-complete audit event | S08 | audit-trail.log | Audit Trail Agent; sysadmin:dlm-sysadmin |

## ERROR_CONDITIONS

E01: Context package unavailable or incomplete.
  condition:    Context package path is unreachable, or required policy
                references for this agent's sub-group are absent.
  likely_cause: Corpus not yet populated; incorrect context package path;
                sub-group policy not yet authored.
  resolution:   sysadmin:dlm-sysadmin provides corrected context package
                or defers onboarding until prerequisites are satisfied.

E02: Artefact format validation fails.
  condition:    Agent cannot produce a structurally conformant output for
                its designated write target schema in S06.
  likely_cause: Write target schema not loaded into context; agent
                capability misconfiguration.
  resolution:   Halt. Log failure in onboarding-complete audit event with
                outcome: failure. Escalate to sysadmin:dlm-sysadmin for
                capability review before re-attempting.

E03: Audit trail unreachable.
  condition:    S05 or S08 cannot write to audit-trail.log.
  likely_cause: Audit Trail Agent offline; message bus fault.
  resolution:   Halt at the failing step. Alert sysadmin:dlm-sysadmin.
                Do not mark onboarding complete. Retry only after Audit
                Trail Agent is confirmed reachable and both events are
                written.
