## SUMMARY
This template defines the structure of a Definition of Done completion record
for the Approval stage gate. The Approval Gate Agent must produce a completed
record immediately before setting a document status to approved. Every
mandatory checklist item must pass, and the approver identity must be
independently verifiable against DLMS-2026-0014.

## TARGET_DOC_TYPE
dod-approval-record

## PURPOSE
The Approval DoD is the final gate before a document achieves approved status
and its version increments to 1.0.0. It confirms that the review process was
complete, the approver is structurally independent from the verifier and
author, and that the status transition and version fields will be set
correctly. Once this DoD passes, the Approval Gate Agent writes the approval
fields and queues the audit event.

## RECORD_SCHEMA

### Header_Fields

FIELD_01:
  name:        dod_id
  type:        string
  required:    true
  nullable:    false
  format:      DOD-approval-{doc_id}-{version}
  example:     DOD-approval-DLMS-2026-0030-0.1.0
  description: Unique identifier for this DoD completion record. Immutable.

FIELD_02:
  name:        doc_id
  type:        string
  required:    true
  description: The DLMS doc_id of the document being evaluated.

FIELD_03:
  name:        doc_version
  type:        string
  required:    true
  format:      MAJOR.MINOR.PATCH
  description: The pre-approval version of the document (e.g. 0.1.0). The
               approved version (1.0.0) is set after this DoD passes.

FIELD_04:
  name:        stage
  type:        string
  required:    true
  value:       approval
  description: Fixed value. Identifies this as an Approval stage DoD record.

FIELD_05:
  name:        evaluated_by
  type:        string
  required:    true
  description: agent_id of the Approval Gate Agent completing this record.
  constraints:
    - Must differ from created_by and verified_by (DLMS-2026-0014 R02, R03)

FIELD_06:
  name:        evaluated_at
  type:        datetime
  required:    true
  format:      ISO 8601 with timezone
  description: Timestamp when the DoD evaluation was completed.

### Checklist_Items

Each item carries three sub-fields:
  result:    pass | fail
  mandatory: true | false   (fail on a mandatory item = hard block on approval)
  notes:     string | null  (required when result is fail)

ITEM_01:
  id:          CI-APPROVAL-01
  label:       Review DoD passed with verdict: pass
  check:       A DoD-review-record exists for this doc_id and doc_version
               with attestation.verdict == pass.
  mandatory:   true
  governed_by: DLMS-2026-0025 (DoD Template — Review)

ITEM_02:
  id:          CI-APPROVAL-02
  label:       Synthesis artefact reviewed by Approval Gate Agent
  check:       The Approval Gate Agent has read the synthesis artefact
               produced in the review session. Reference to the synthesis
               artefact is recorded in notes.
  mandatory:   true
  governed_by: DLMS-2026-0017

ITEM_03:
  id:          CI-APPROVAL-03
  label:       No blocking verdicts remain unresolved
  check:       The synthesis artefact contains no fail verdicts that have
               not been formally resolved or escalated.
  mandatory:   true
  governed_by: DLMS-2026-0017

ITEM_04:
  id:          CI-APPROVAL-04
  label:       Approver independent from verifier
  check:       evaluated_by (approver) differs from the document's
               verified_by field value. (DLMS-2026-0014 R02)
  mandatory:   true
  governed_by: DLMS-2026-0014 R02

ITEM_05:
  id:          CI-APPROVAL-05
  label:       Approver independent from author
  check:       evaluated_by (approver) differs from the document's
               created_by field value. (DLMS-2026-0014 R03)
  mandatory:   true
  governed_by: DLMS-2026-0014 R03

ITEM_06:
  id:          CI-APPROVAL-06
  label:       Document status is under_review prior to approval
  check:       The document's current status field value is under_review.
               The transition under_review → approved is the only valid
               transition to the approved state.
  mandatory:   true
  governed_by: DLMS-2026-0004

ITEM_07:
  id:          CI-APPROVAL-07
  label:       Version will increment correctly on approval
  check:       After approval, version will be set to 1.0.0 (for first
               approval) or the correct MAJOR.0.0 increment for a
               re-approval after a major structural change.
  mandatory:   true
  governed_by: DLMS-2026-0004

ITEM_08:
  id:          CI-APPROVAL-08
  label:       approved_at and approved_by will be set correctly
  check:       The Approval Gate Agent confirms it will write non-null
               values to approved_at (current timestamp) and approved_by
               (its own agent_id) immediately upon DoD passage.
  mandatory:   true
  governed_by: DLMS-2026-0004, DLMS-2026-0018

ITEM_09:
  id:          CI-APPROVAL-09
  label:       Approval audit event queued
  check:       An approval-granted audit event has been prepared for the
               Audit Trail Agent and will be submitted upon DoD passage.
  mandatory:   true
  governed_by: DLMS-2026-0015

### Attestation_Block

attestation:
  dod_id:          {value from Header FIELD_01}
  verdict:         pass | fail
  blocking_items:  list of ITEM IDs where result: fail AND mandatory: true
                   (empty list [] when verdict is pass)
  observations:    list of ITEM IDs where result: fail AND mandatory: false
                   (empty list [] when no non-mandatory items failed)
  signed_by:       agent_id — must match evaluated_by
  signed_at:       ISO 8601 datetime

## ADVANCEMENT_RULE

Approval is granted if and only if:
  attestation.verdict == pass
  (i.e. all 9 mandatory items have result: pass)

After DoD passage the Approval Gate Agent immediately:
  1. Sets status to approved
  2. Sets version to 1.0.0 (or correct major increment)
  3. Sets approved_at to current timestamp
  4. Sets approved_by to its own agent_id
  5. Submits the approval audit event to the Audit Trail Agent

## VALIDATION_RULES

V01: dod_id matches DOD-approval-{doc_id}-{version}.
V02: stage value is exactly "approval".
V03: verdict is "pass" or "fail" only.
V04: When verdict is "fail", blocking_items is non-empty.
V05: When verdict is "pass", blocking_items is an empty list [].
V06: All 9 checklist items are recorded.
V07: evaluated_by is pairwise distinct from both created_by and verified_by.
