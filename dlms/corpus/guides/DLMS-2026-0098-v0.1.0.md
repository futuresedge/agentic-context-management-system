## SUMMARY

This procedure governs the Storage and Versioning stage of the DLMS document
lifecycle: from Indexing stage handoff through context curation, DoD
establishment, version assignment, access manifest creation, version registry
update, independent verification, and handoff to the Distribution stage. The
Version Control Agent applies semver versioning logic per DLMS-2026-0038
(Document Versioning Policy); the Access Control Agent reads the access rule
set from DLMS-2026-0044 to produce the recipient access manifest that feeds
downstream Distribution routing. The primary outputs are the versioned
document artefact, storage-verification.md (stage gate artefact), and
storage-metrics.md (performance record).

## SCOPE

Agents active in this stage:

| Pipeline Position | Agent | Output Artefact |
|---|---|---|
| P01 | Storage-Versioning Orchestrator | (coordination only) |
| P02 | Context Curator (Storage) | storage-context.md |
| P03 | DoD Agent (Storage) | storage-dod.md |
| P04 | Version Control Agent | version-log.md; doc-[id]-v[n]-agent.md |
| P05 | Access Control Agent | access-manifest.md |
| P06 | Version Registry Updater | version-registry entry |
| P07 | Storage Verifier | storage-verification.md; storage-learnings.md |
| P08 | Storage Metrics Agent | storage-metrics.md |

Excludes:
- Indexing, Approval Gate, Review, and Creation stage agents
- Distribution, Archival stage agents

Executed by:
- agent:storage-versioning-orchestrator: pipeline coordination, CI
  dispatch, and handoff (S01, S09, S10)
- Stage agents: own designated pipeline steps (S02–S08)
- sysadmin:dlm-sysadmin: escalation recipient for E02, E03, E04, E05

## PREREQUISITES

P01: All Storage stage agents are onboarded per DLMS-2026-0087 (Storage and
     Versioning Stage Agent Onboarding Procedure). If any agent instance is
     not onboarded, defer pipeline activation. Failure → E02.

P02: DLMS-2026-0014 (Verification Independence Policy),
     DLMS-2026-0015 (Audit Trail Policy), DLMS-2026-0016 (Agent Context
     Boundary Policy), DLMS-2026-0037 (Document Status Transition Policy),
     DLMS-2026-0038 (Document Versioning Policy),
     DLMS-2026-0041 (Definition of Done Policy),
     DLMS-2026-0043 (Quality Threshold Policy),
     DLMS-2026-0044 (Access Control Policy), and
     DLMS-2026-0059 (Storage Stage SLA) are in effect.
     Verified by: agent:storage-versioning-orchestrator. Failure → E02.

P03: Storage DoD template (DLMS-2026-0027 — TMPL-dod-storage-001) is
     loaded and accessible for DoD Agent (Storage). Failure → E01.

P04: Audit Trail Agent is reachable and accepting log entries. Failure → E03.

P05: Indexing stage verification record is present: indexing-verification.md
     with outcome = pass. If absent or outcome ≠ pass, reject intake and
     halt. Failure → E05.

## STEPS

S01: Receive handoff from Indexing stage and validate prerequisites.
  action: Storage-Versioning Orchestrator receives the Storage intake
          artefacts (indexing-verification.md + metadata-final.md +
          approved document artefact). Confirm P05: indexing-verification.md
          outcome = pass. Log receipt to Audit Trail Agent.
  actor:  agent:storage-versioning-orchestrator
  reads:  indexing-verification.md; metadata-final.md; approved document
          artefact
  writes: audit log entry
  on_failure: → E05

S02: Context Curator (Storage) produces storage context package.
  action: Context Curator (Storage) reads designated context sources for
          this storage run and produces storage-context.md. READS limited
          to designated context sources per DLMS-2026-0016. Context scope
          includes doc_id, current version, doc_type, access class, and
          governing policy references; does not include document body
          content.
  actor:  agent:context-curator-storage
  reads:  designated context sources (doc_id, version, doc_type,
          confidentiality class, governing policies — scoped per
          DLMS-2026-0016)
  writes: storage-context.md
  on_failure: → E02

S03: DoD Agent (Storage) produces storage-dod.md.
  action: DoD Agent (Storage) loads DLMS-2026-0027 (TMPL-dod-storage-001)
          and records the Definition of Done checklist for this storage
          instance. Establishes acceptance criteria the Storage Verifier
          will evaluate independently. DoD Agent MUST NOT pre-evaluate
          storage outputs (DLMS-2026-0014 R01).
  actor:  agent:dod-storage
  reads:  DLMS-2026-0027; storage-context.md
  writes: storage-dod.md
  on_failure: → E02

S04: Version Control Agent assigns version and produces versioned artefact.
  action: Version Control Agent reads the approved document artefact and
          its current version record. Determines the version bump type per
          DLMS-2026-0038 (Document Versioning Policy):
            major (X.0.0): structural change — new sections, reorganisation
                           of body structure, or schema change
            minor (0.X.0): content change — new substantive content,
                           updated policy logic, or scope expansion
            patch (0.0.X): correction — typo fix, minor clarification,
                           metadata-only update
          Produces version-log.md per DLMS-2026-0051 (TMPL-version-log-001)
          recording the bump rationale. Produces the versioned document
          artefact doc-[id]-v[n]-agent.md (e.g. DLMS-2026-0001-v0.1.0.md).
          Human-facing variant (doc-[id]-v[n]-human.md) is reserved for
          future rendering; not populated at v0.x.
  actor:  agent:version-control
  reads:  approved document artefact; current version record;
          DLMS-2026-0038; storage-context.md
  writes: version-log.md; doc-[id]-v[n]-agent.md
  on_failure: → E02

S05: Access Control Agent produces access manifest.
  action: Access Control Agent reads DLMS-2026-0044 (Access Control Policy)
          and DLMS-2026-0045 (Confidentiality Classification Policy) to
          determine the applicable access rule set for this document's
          confidentiality class. Produces access-manifest.md per
          DLMS-2026-0052 (TMPL-access-manifest-001) listing authorised
          recipient roles. The access manifest feeds Distribution stage
          recipient routing.
  actor:  agent:access-control
  reads:  storage-context.md; DLMS-2026-0044; DLMS-2026-0045
  writes: access-manifest.md
  on_failure: → E02

S06: Version Registry Updater records version entry.
  action: Version Registry Updater reads version-log.md and
          doc-[id]-v[n]-agent.md confirmation and appends a version entry
          to the DLMS version registry. Entry records: doc_id, version,
          bump type, bump rationale, and storage timestamp.
  actor:  agent:version-registry-updater
  reads:  version-log.md; doc-[id]-v[n]-agent.md (path and version
          confirmation)
  writes: version-registry entry for this doc_id and version
  on_failure: → E02

S07: Storage Verifier evaluates against DoD.
  action: Storage Verifier independently evaluates whether S04–S06 outputs
          satisfy all acceptance criteria in storage-dod.md. Reads
          doc-[id]-v[n]-agent.md, version-log.md, access-manifest.md, and
          storage-dod.md. Produces storage-verification.md (outcome: pass |
          fail) per DLMS-2026-0030 (TMPL-verification-001) and
          storage-learnings.md per DLMS-2026-0034 (TMPL-learnings-001).
          Storage Verifier MUST NOT be DoD Agent (Storage) or Version
          Control Agent (DLMS-2026-0014 R01).
  actor:  agent:storage-verifier
  reads:  doc-[id]-v[n]-agent.md; version-log.md; access-manifest.md;
          storage-dod.md
  writes: storage-verification.md; storage-learnings.md
  on_failure: → E02
  [D01] storage-verification outcome = fail → E01.

S08: Storage Metrics Agent records stage performance.
  action: Storage Metrics Agent reads storage-verification.md, version-
          log.md, and audit trail logs for this pipeline run. Records:
          elapsed stage time, version bump type applied, access class
          assigned, DoD pass/fail outcome, and SLA variance against
          DLMS-2026-0059. Produces storage-metrics.md.
  actor:  agent:storage-metrics
  reads:  storage-verification.md; version-log.md; audit trail log entries
          for this pipeline run
  writes: storage-metrics.md
  on_failure: → E02

S09: CI dispatch.
  action: Dispatch storage-metrics.md and storage-learnings.md to the CI
          quality monitor queue. Dispatch storage-verification.md to CI
          monitor scope. CI feedback consumed by Tier 13 per
          DLMS-2026-0076 (CI Cycle Policy).
  actor:  agent:storage-versioning-orchestrator
  reads:  storage-metrics.md; storage-learnings.md; storage-verification.md
  writes: CI queue entries (external to this stage's write scope)
  on_failure: log warning and continue (non-blocking)

S10: Handoff to Distribution stage.
  action: Pass storage-verification.md, doc-[id]-v[n]-agent.md, and
          access-manifest.md to the Distribution stage intake queue.
          Log handoff to Audit Trail Agent. Distribution Stage SOP
          (DLMS-2026-0099) is triggered on receipt.
  actor:  agent:storage-versioning-orchestrator
  reads:  storage-verification.md (confirm outcome = pass before handoff)
  writes: handoff artefact to Distribution queue; audit log entry
  on_failure: → E02

## DECISION_POINTS

D01: Storage Verifier returns fail (at S07).
  condition: storage-verification.md outcome = fail.
  action:    → E01. Do not advance to S08 or S09. Halt pipeline.

## OUTPUTS

| Artefact | Produced by | Purpose |
|---|---|---|
| storage-context.md | Context Curator (Storage) | Scoped context for this storage run |
| storage-dod.md | DoD Agent (Storage) | Acceptance criteria for this storage instance |
| version-log.md | Version Control Agent | Version bump record and rationale |
| doc-[id]-v[n]-agent.md | Version Control Agent | Versioned canonical document artefact |
| access-manifest.md | Access Control Agent | Authorised recipient list for Distribution routing |
| storage-verification.md | Storage Verifier | Independent DoD evaluation (stage gate artefact) |
| storage-learnings.md | Storage Verifier | Lessons and observations for CI feedback |
| storage-metrics.md | Storage Metrics Agent | Stage performance record |

## ERROR_CONDITIONS

E01: DoD failure.
  condition: Storage Verifier returns outcome = fail (D01).
  action:    Halt pipeline. Log to Audit Trail Agent with failure reasons
             from storage-verification.md. Escalate to
             sysadmin:dlm-sysadmin. Document does not advance to
             Distribution stage until storage defects are remediated.

E02: Agent unavailable or pipeline step failure.
  condition: Any stage agent fails to produce its designated output.
  action:    Halt pipeline at failure point. Log to Audit Trail Agent
             including step identifier and agent ID.
             agent:storage-versioning-orchestrator escalates to
             sysadmin:dlm-sysadmin.

E03: Audit Trail Agent unreachable.
  condition: Audit Trail Agent does not respond at S01 or any subsequent
             audit log step.
  action:    Halt pipeline immediately (DLMS-2026-0015 R01). Escalate to
             sysadmin:dlm-sysadmin.

E04: Version conflict.
  condition: Version Control Agent detects an existing artefact at the
             computed version identifier (e.g. doc-[id]-v0.1.0.md already
             exists with different content).
  action:    Halt pipeline. Log conflict to Audit Trail Agent. Escalate to
             sysadmin:dlm-sysadmin for manual version resolution before
             re-run.

E05: Missing Indexing stage prerequisite.
  condition: indexing-verification.md absent or outcome ≠ pass.
  action:    Reject intake. Log to Audit Trail Agent. Return signal to
             Indexing stage. Do not begin Storage stage processing under
             any circumstances.

## REVIEW_SCHEDULE

This procedure is reviewed whenever DLMS-2026-0038 (Document Versioning
Policy) or DLMS-2026-0044 (Access Control Policy) are updated, and at
each major SLA renegotiation for DLMS-2026-0059. Minimum annual review
by agent:storage-versioning-orchestrator and sysadmin:dlm-sysadmin.
