## SUMMARY

This procedure governs the runtime context delivery pipeline: from receipt
of a context delivery request through document retrieval, four independent
parallel validation passes, compression, and independent delivery verification,
to delivery of a compressed-context.bundle to the requesting agent. It
implements the Context Delivery SLA (DLMS-2026-0062) and enforces the
five-way agent separation constraint (four validators plus Delivery Verifier
as distinct instances). The primary outputs are compressed-context.bundle
(the delivered context package) and delivery-verification.md (the independent
verification record).

## SCOPE

Agents active in this procedure:

| Position | Agent | Output Artefact |
|---|---|---|
| A01 | Context Request Handler | context-request.md |
| A02 | Document Retrieval Agent | retrieved-documents.bundle |
| A03 | Recency Validator | recency-validation.md |
| A04 | Accuracy Validator | accuracy-validation.md |
| A05 | Completeness Validator | completeness-validation.md |
| A06 | Format Validator | format-validation.md |
| A07 | Context Compressor | compressed-context.bundle |
| A08 | Delivery Verifier | delivery-verification.md |

Five-way separation constraint: All four validators (A03–A06) must be
distinct agent instances from each other AND from the Delivery Verifier
(A08). No validator may read another validator's output. Delivery Verifier
reads only the aggregated delivery-ready signal — never individual validator
outputs. This constraint is mandated by DLMS-2026-0014 R01 and is hard
(non-negotiable; cannot be overridden by runtime conditions).

Excludes:
- Agent initialisation and onboarding (governed by DLMS-2026-0090; this
  procedure governs the runtime pipeline only)
- CI cycle agents and SysAdmin agents (governed by their own SOPs)
- Any agent that is not one of A01–A08 listed above

Executed by:
- agent:context-request-handler: request intake and validation (S01)
- agent:document-retrieval: document retrieval (S02)
- agent:recency-validator, agent:accuracy-validator,
  agent:completeness-validator, agent:format-validator: parallel validation
  (S03–S06)
- agent:context-compressor: compression (S07)
- agent:delivery-verifier: independent final verification (S08)
- sysadmin:dlm-sysadmin: M03 breach escalation recipient; procedure owner

## PREREQUISITES

P01: All context delivery agents (A01–A08) are onboarded and initialised per
     DLMS-2026-0090 (Context Delivery Agent Onboarding Procedure). This
     procedure governs the runtime pipeline only; for agent initialisation,
     see DLMS-2026-0090. Failure → E02.

P02: DLMS-2026-0014 (Verification Independence Policy), DLMS-2026-0015
     (Audit Trail Policy), DLMS-2026-0016 (Agent Context Boundary Policy),
     and DLMS-2026-0062 (Context Delivery SLA) are in effect.
     Verified by: sysadmin:dlm-sysadmin. Failure → procedure deferred.

P03: All four validators (A03–A06) are confirmed as distinct agent instances
     from each other AND from Delivery Verifier (A08). Per DLMS-2026-0014
     R01. Failure → E02.

P04: Audit Trail Agent is reachable and accepting log entries.
     Verified by: agent:context-request-handler at S01. Failure → E03.

P05: TMPL-creation-context-001 (DLMS-2026-0046) is accessible for context
     package structuring. Verified by: agent:context-request-handler.
     Failure → E02.

## STEPS

S01: Context Request Handler validates request and starts M01 clock.
  action: Context Request Handler receives the context delivery request.
          Validates that the request specifies only named specific file paths
          — no categories, wildcards, or "all documents of type X" patterns
          (DLMS-2026-0016 R04). Assigns a request_id. Starts the M01 latency
          clock (SLA target: delivery within 2 hours; warning threshold:
          90 minutes; breach threshold: 4 hours). Logs request receipt to
          Audit Trail Agent.
  actor:  agent:context-request-handler
  reads:  context delivery request artefact
  writes: context-request.md; audit log entry (request receipt, request_id,
          M01 clock start, timestamp)
  on_failure: → E03

S02: Document Retrieval Agent retrieves requested documents.
  action: Document Retrieval Agent reads context-request.md and retrieves
          all documents specified by name. Retrieves current approved versions
          unless historical comparison is explicitly required in the request.
          Per DLMS-2026-0016 R08: only the specific artefacts named in the
          request may be retrieved; no incidental document access. Produces
          retrieved-documents.bundle.
  actor:  agent:document-retrieval
  reads:  context-request.md; named document paths as specified in request
  writes: retrieved-documents.bundle
  on_failure: → E02

S03: Recency Validator evaluates document currency.
  action: Recency Validator reads retrieved-documents.bundle and evaluates
          whether each document meets recency requirements: no superseded
          documents; no archived documents unless historical comparison is
          explicitly scoped; version timestamps within acceptable bounds.
          Produces recency-validation.md with per-document result (pass/fail)
          and aggregate outcome. Must not read any other validator's output.
  actor:  agent:recency-validator
  reads:  retrieved-documents.bundle
          NEVER: accuracy-validation.md; completeness-validation.md;
          format-validation.md
  writes: recency-validation.md
  on_failure: → E02

S04: Accuracy Validator evaluates factual correctness.
  action: Accuracy Validator reads retrieved-documents.bundle and evaluates
          whether each document's content is internally consistent and
          consistent with its stated dependencies. Produces accuracy-
          validation.md with per-document result and aggregate outcome.
          Activates concurrently with S03, S05, S06. Must not read any
          other validator's output.
  actor:  agent:accuracy-validator
  reads:  retrieved-documents.bundle
          NEVER: recency-validation.md; completeness-validation.md;
          format-validation.md
  writes: accuracy-validation.md
  on_failure: → E02

S05: Completeness Validator evaluates required policy coverage.
  action: Completeness Validator reads retrieved-documents.bundle and
          evaluates whether the context package satisfies the M03 required
          policy coverage obligation: every document with a doc_type and
          template_assignment must have its governing policy included in the
          package. Produces completeness-validation.md with M03 compliance
          flag, per-document coverage result, and aggregate outcome. Activates
          concurrently with S03, S04, S06. Must not read any other validator's
          output. Any M03 fail is a direct breach regardless of other outcomes.
  actor:  agent:completeness-validator
  reads:  retrieved-documents.bundle
          NEVER: recency-validation.md; accuracy-validation.md;
          format-validation.md
  writes: completeness-validation.md
  on_failure: → E02

S06: Format Validator evaluates schema and structural compliance.
  action: Format Validator reads retrieved-documents.bundle and evaluates
          whether each document conforms to its assigned template schema:
          frontmatter field completeness, required section headings,
          UPPER_SNAKE_CASE heading convention, and body section ordering.
          Produces format-validation.md with per-document result and aggregate
          outcome. Activates concurrently with S03, S04, S05. Must not read
          any other validator's output.
  actor:  agent:format-validator
  reads:  retrieved-documents.bundle
          NEVER: recency-validation.md; accuracy-validation.md;
          completeness-validation.md
  writes: format-validation.md
  on_failure: → E02

  [D01] Validator outcomes (evaluated once all four validators complete):
    - all four aggregate outcomes = pass → S07
    - any aggregate outcome = fail:
        - If failure is recoverable (artefact-level re-retrieval feasible):
          agent:document-retrieval re-retrieves the failed artefact(s) and
          the relevant validator(s) re-run for those artefacts only.
        - If failure is irrecoverable (document unavailable, status
          incompatible, or structural failure cannot be resolved by retrieval
          alone): → E01. Partial delivery is prohibited.
    - M03 fail (completeness): → E04 post-delivery M03 breach protocol
      applies if M03 failure is detected after compressed-context.bundle
      is delivered.

S07: Context Compressor produces compressed context package.
  action: Context Compressor reads all four validation artefacts
          (recency-validation.md, accuracy-validation.md,
          completeness-validation.md, format-validation.md) and
          retrieved-documents.bundle. Applies token budget constraints to
          produce the minimum viable subset of context that satisfies all
          validation pass criteria. For each excluded artefact, logs an M02
          exclusion flag. Produces compressed-context.bundle structured per
          DLMS-2026-0046 (TMPL-creation-context-001) conventions.
          Progressive disclosure applies: load skill files on demand per
          context-engineering-approach.md; do not front-load full document
          bodies where skill-file references suffice.
  actor:  agent:context-compressor
  reads:  retrieved-documents.bundle; recency-validation.md;
          accuracy-validation.md; completeness-validation.md;
          format-validation.md
  writes: compressed-context.bundle
  on_failure: → E02

S08: Delivery Verifier performs independent verification.
  action: Delivery Verifier reads the aggregated delivery-ready signal (a
          structured summary flag produced by agent:context-compressor
          indicating all four validators passed and the compression is
          complete). MUST NOT read individual validator outputs
          (recency-validation.md, accuracy-validation.md, completeness-
          validation.md, format-validation.md) — this is a hard constraint
          per DLMS-2026-0014 R01. Produces delivery-verification.md with
          outcome: approved or rejected. Delivery Verifier must be a distinct
          agent instance from all four validators AND from
          agent:context-compressor.
  actor:  agent:delivery-verifier
  reads:  aggregated delivery-ready signal (not individual validator outputs)
          NEVER: recency-validation.md; accuracy-validation.md;
          completeness-validation.md; format-validation.md
  writes: delivery-verification.md
  on_failure: → E02

  [D02] Delivery Verifier outcome:
    - approved → S09
    - rejected → E01 (delivery failure; do not deliver compressed-context.bundle)

S09: Deliver compressed-context.bundle to requesting agent.
  action: Deliver compressed-context.bundle to the requesting agent or
          orchestrator. M01 latency clock stops at the curated_at timestamp
          recorded in the bundle. Log delivery completion to Audit Trail Agent.
  actor:  agent:context-request-handler
  reads:  compressed-context.bundle; delivery-verification.md
  writes: audit log entry (delivery completion, request_id, M01 stop,
          curated_at timestamp)
  on_failure: → E02

S10: Dispatch SLA metrics to CI monitoring queue.
  action: Dispatch M01, M02, and M03 metrics for this delivery request to
          the Context Delivery Metrics Collector and the CI cycle queue, to
          be consumed by the next CI cycle's Quality Monitor and Performance
          Monitor. M01: actual latency against 2-hour target. M02: proportion
          of retrieved artefacts successfully included in compressed bundle
          (target: ≥95% per CI cycle). M03: required policy coverage
          compliance flag (100% zero-tolerance; single failure = breach;
          two consecutive cycles below 100% triggers critical corrective
          directive from sysadmin:dlm-sysadmin).
  actor:  agent:context-request-handler
  reads:  delivery-verification.md; M01/M02/M03 metric values
  writes: SLA metrics dispatch (to Context Delivery Metrics Collector and
          CI queue)
  on_failure: → E03

## DECISION_POINTS

D01: Validator outcome evaluation.
  condition: Do all four validators (A03–A06) report aggregate outcome = pass?
  if_true:   proceed to S07.
  if_false:  Attempt recovery via targeted re-retrieval for recoverable
             failures. If irrecoverable: → E01. Partial delivery is
             prohibited under all circumstances.

D02: Delivery Verifier outcome.
  condition: Does delivery-verification.md report outcome = approved?
  if_true:   proceed to S09.
  if_false:  → E01 (delivery failure; compressed-context.bundle must not be
             delivered).

## ERROR_CONDITIONS

E01: Delivery failure — validator fail irrecoverable or Delivery Verifier
     rejected.
  condition: (a) One or more validators report aggregate outcome = fail and
             the failure cannot be resolved by targeted re-retrieval; OR
             (b) Delivery Verifier (agent:delivery-verifier) reports outcome
             = rejected.
  likely_cause: (a) Document unavailable, status incompatible (e.g.,
                archived or superseded without replacement), or structural
                non-conformance unresolvable by retrieval. (b) Delivery
                Verifier detects inconsistency in the aggregated delivery-
                ready signal.
  resolution: Do NOT deliver compressed-context.bundle. Log delivery failure
              to Audit Trail Agent with request_id and failure reason.
              Notify requesting agent and sysadmin:dlm-sysadmin. Re-evaluate
              request scope: the requesting agent or orchestrator must revise
              the request to remove unavailable or non-qualifying documents,
              then re-submit to S01.

E02: Agent unavailable or artefact production failure.
  condition: Any agent (A01–A08) fails to produce its required output
             artefact.
  likely_cause: Agent runtime failure; onboarding not completed (P01 gap);
                upstream artefact unavailable.
  resolution: Log failure to Audit Trail Agent. Notify sysadmin:dlm-sysadmin.
              Halt the pipeline at the failed step. Do not proceed to
              downstream steps. Restore agent availability and re-initiate
              from the failed step.

E03: Audit Trail Agent unreachable.
  condition: Audit Trail Agent cannot accept log entries at S01 or S10.
  likely_cause: Audit Trail infrastructure failure.
  resolution: HALT immediately. Do not proceed with any pipeline step. Notify
              sysadmin:dlm-sysadmin. Per DLMS-2026-0015: no step executes
              without a reachable Audit Trail.

E04: M03 breach detected post-delivery.
  condition: M03 required policy coverage failure is detected after
             compressed-context.bundle has been delivered to the requesting
             agent.
  likely_cause: Completeness Validator failed to flag a missing governing
                policy; or a governing policy was removed from the corpus
                after retrieval but before delivery.
  resolution: Log M03 breach event to Audit Trail Agent with request_id and
              cycle_id. Notify requesting agent that the delivered context
              package may be incomplete. Initiate re-request protocol: a
              corrected context package must be produced and delivered within
              the M01 window from breach detection. Notify sysadmin:dlm-
              sysadmin. If this is the second consecutive cycle with an M03
              breach: sysadmin:dlm-sysadmin must issue a critical corrective
              directive before the next CI cycle proceeds.

## NOTES

This procedure covers the runtime context delivery pipeline only. Agent
initialisation, capability loading, and onboarding are governed by
DLMS-2026-0090 (Context Delivery Agent Onboarding Procedure). The two
documents are complementary: DLMS-2026-0090 governs how agents are prepared;
this procedure governs how those agents operate at runtime.

Progressive disclosure principle (from context-engineering-approach.md):
Context Compressor must not front-load full document bodies when a referenced
skill file or section pointer will suffice. Minimum viable context is the
operative standard; compression must preserve completeness (M03) while
minimising token cost. Skill files are loaded on demand, not pre-loaded.
