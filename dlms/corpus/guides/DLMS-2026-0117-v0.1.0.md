## SUMMARY
This SOP specifies the complete operational sequence for creating a new DLMS
agent class via the Tier 15B pipeline, from initial dispatch through registry
update. It translates the 7-stage workflow of DLMS-2026-0108 into concrete
step-by-step instructions for sysadmin:dlm-sysadmin and the agent-creation-
orchestrator, including all approval gates, TypeDB artefact checks, and
independence assertions required at each stage.

## SCOPE

Applies to:
- All new_agent creation workflows initiated by sysadmin:dlm-sysadmin
- The full Tier 15B pipeline (STEP_01 through STEP_07 + DoD evaluation)
- sysadmin:dlm-sysadmin as invoking principal and human approval authority

Covers also: documentation of human approval gates (STEP_APPROVE) that
fall between STEP_01 and STEP_02 — the only gate requiring human action.

Excludes:
- retire_agent workflows (governed by DLMS-2026-0110)
- Agent onboarding after creation (see DLMS-2026-0116)
- Emergency or expedited creation without full pipeline compliance

## PREREQUISITES

P01: sysadmin:dlm-sysadmin has identified a capability gap not covered by
     any existing active agent_class entity. Confirmed via roster.list.

P02: The Nexus MCP server is operational. All agentcreation.* and roster.*
     tools return 200 on probe.

P03: A proposed role_id has been assigned following the slug convention
     `/^[a-z][a-z0-9-]+$/` and has been confirmed unique via roster.get.

P04: A problem_statement (2–5 sentences) and evidence_of_need (reference to
     a valid CI report or SysAdmin directive doc_id) have been prepared by
     sysadmin:dlm-sysadmin before dispatch.

## STEPS

S01: Dispatch to agent-request-handler.
  action:  Invoke the agent-creation-orchestrator with dispatch context:
           role_id, request_type: new_agent, requesting_principal,
           problem_statement, evidence_of_need, urgency, affected_tiers.
           The orchestrator invokes agent-request-handler (STEP_01).
           agent-request-handler writes `agent-request-record` to TypeDB via
           agentcreation.writeRequest. Result must be PASS.
  actor:   sysadmin:dlm-sysadmin (dispatch); agent-creation-orchestrator +
           agent-request-handler (execution)
  reads:   dispatch context
  writes:  TypeDB agent_artefact: artefact_type agent-request-record
  gate:    proposed_role_id not in active or retired agent_class entities
  on_failure: → D01

S02: HUMAN GATE — Request approval.
  action:  sysadmin:dlm-sysadmin reviews the agent-request-record in TypeDB
           (retrieve via agentcreation.getArtefact). If approved:
           (a) set approval_artefact_id in the request record content, and
           (b) update status to "approved" via agentcreation.writeRequest update.
           This is the ONLY step in the creation workflow that requires human
           action. No automation may simulate or skip this gate.
  actor:   sysadmin:dlm-sysadmin (sole approver)
  reads:   TypeDB agent-request-record for this role_id
  writes:  approval_artefact_id and status: approved in request record
  gate:    Human decision — DLMS-2026-0108 R02. Cannot be automated.
  on_failure: → D02 (if rejected); workflow terminates if rejected

S03: Dispatch to agent-problem-analyst.
  action:  Orchestrator invokes agent-problem-analyst (STEP_02). Agent reads
           the approved agent-request-record via agentcreation.getArtefact,
           analyses the capability gap against the active roster, and writes
           `agent-problem-analysis` to TypeDB. Result must be PASS with
           recommendation: proceed_with_creation.
  actor:   agent-creation-orchestrator + agent-problem-analyst
  reads:   TypeDB agent-request-record; roster.list; referenced evidence doc
  writes:  TypeDB agent_artefact: artefact_type agent-problem-analysis
  gate:    agent-request-record exists with approval_artefact_id non-null
  on_failure: → D03

S04: Dispatch to agent-specification-author.
  action:  Orchestrator invokes agent-specification-author (STEP_03). Agent
           reads the agent-problem-analysis via agentcreation.getArtefact and
           authors an agent specification conforming to DLMS-2026-0113 (all 8
           sections, all 14 NR requirements). Writes `agent-spec` to TypeDB.
           Result must be PASS.
  actor:   agent-creation-orchestrator + agent-specification-author
  reads:   TypeDB agent-problem-analysis; DLMS-2026-0111; DLMS-2026-0113
  writes:  TypeDB agent_artefact: artefact_type agent-spec
  gate:    agent-problem-analysis exists in TypeDB for this role_id
  on_failure: → D04

S05: Dispatch to agent-specification-reviewer.
  action:  Orchestrator invokes agent-specification-reviewer (STEP_04).
           Reviewer must be a different actor than specification author
           (DLMS-2026-0108 R05). Reviewer reads agent-spec via
           agentcreation.getArtefact and evaluates all 14 NR requirements.
           Writes `agent-spec-review` to TypeDB. Result must be PASS.
           If FAIL: return to S04 with findings; author must revise spec.
  actor:   agent-creation-orchestrator + agent-specification-reviewer
  reads:   TypeDB agent-spec for this role_id
  writes:  TypeDB agent_artefact: artefact_type agent-spec-review
  gate:    agent-spec exists; reviewer_actor_id ≠ author_actor_id in spec
  on_failure: → D05 (if FAIL with findings); → D06 (if identity conflict)

S06: Dispatch to agent-instruction-author.
  action:  Orchestrator invokes agent-instruction-author (STEP_05). Agent
           reads the PASS-reviewed spec via agentcreation.getArtefact and
           translates it to `.github/agents/{role_id}.agent.md` per
           DLMS-2026-0114 FORMAT_A. Must self-count body tokens ≤ 440.
           Writes both: (a) the .agent.md file to `.github/agents/`, and
           (b) `agent-instruction-record` to TypeDB via
           agentcreation.writeInstruction. Result must be PASS.
  actor:   agent-creation-orchestrator + agent-instruction-author
  reads:   TypeDB agent-spec; TypeDB agent-spec-review (result: PASS)
  writes:  .github/agents/{role_id}.agent.md;
           TypeDB agent_artefact: artefact_type agent-instruction-record
  gate:    agent-spec-review exists with result: PASS in content
  on_failure: → D07

S07: Dispatch to agent-specification-verifier.
  action:  Orchestrator invokes agent-specification-verifier (STEP_06).
           Verifier must be a different actor than instruction author
           (DLMS-2026-0108 R07). Verifier reads the deployed .agent.md file
           and the agent-spec and evaluates all 7 VC criteria. Writes
           `agent-verification-record` to TypeDB. Result must be PASS.
           If FAIL: return to S06 with findings; author must revise file.
  actor:   agent-creation-orchestrator + agent-specification-verifier
  reads:   .github/agents/{role_id}.agent.md; TypeDB agent-spec
  writes:  TypeDB agent_artefact: artefact_type agent-verification-record
  gate:    agent-instruction-record exists; verifier_actor_id ≠ instruction author_actor_id
  on_failure: → D05 (if FAIL with findings); → D06 (if identity conflict)

S08: Dispatch to agent-registry-updater.
  action:  Orchestrator invokes agent-registry-updater (STEP_07). Agent
           executes three atomic writes: (1) roster.write — inserts
           agent_class entity to TypeDB; (2) agentcreation.updateRegistry —
           adds tool-access-registry rows; (3) sysadmin.writeGovernanceDoc —
           appends agent entry to dlms-agent-roster.md. All three must
           succeed or all roll back. Emits agent_deployed audit event.
  actor:   agent-creation-orchestrator + agent-registry-updater
  reads:   TypeDB agent-verification-record (result: PASS); TypeDB agent-spec;
           .github/agents/{role_id}.agent.md
  writes:  TypeDB agent_class entity; tool-access-registry.md; dlms-agent-roster.md
  gate:    agent-verification-record exists with result: PASS in content
  on_failure: → E01

S09: Evaluate DoD — Agent Creation Stage.
  action:  agent-creation-orchestrator assembles the DoD completion record
           per DLMS-2026-0115, evaluating all 7 gates. Issues attestation.
           verdict must be "pass" (all 6 mandatory gates pass) before the
           agent is considered fully created and the pipeline closes.
           Submits DoD record to audit trail.
  actor:   agent-creation-orchestrator
  reads:   All TypeDB agent_artefact entities for this role_id; TypeDB
           agent_class entity; .github/agents/{role_id}.agent.md
  writes:  DoD completion record (audit event)
  gate:    All GATE-01 through GATE-06 must result: pass for verdict: pass
  on_failure: → D08

S10: Initiate onboarding.
  action:  sysadmin:dlm-sysadmin triggers Tier 15B Agent Onboarding Guide
           (DLMS-2026-0116) for the newly created agent.
  actor:   sysadmin:dlm-sysadmin
  reads:   (none — handoff only)
  writes:  (onboarding procedure generates its own audit event)

## DECISION_POINTS

D01: request_type validation fails or proposed_role_id conflicts.
  action:  agent-request-handler returns FAIL with findings. Review the
           dispatch context for formatting errors or duplicate role_id.
           Correct and re-dispatch.

D02: sysadmin:dlm-sysadmin rejects the request.
  action:  Update agent-request-record status to "rejected" in TypeDB.
           Workflow terminates. Record rejection reason. No further action.

D03: Problem analysis returns FAIL or recommendation is not proceed_with_creation.
  action:  If recommendation is "modify_existing": escalate to
           sysadmin:dlm-sysadmin to re-evaluate whether modification of an
           existing agent satisfies the need. Creation workflow suspended.
           If FAIL due to analysis error: return findings to analyst; retry.

D04: Specification authorship returns FAIL.
  action:  Review failed NR requirements in findings. Return to
           agent-specification-author with problem analysis and specific
           failure reasons. Iterate S04 until result: PASS.

D05: Review or verification returns FAIL with findings.
  action:  Return findings to the authoring agent (agent-specification-author
           for S05 fails; agent-instruction-author for S07 fails). Author
           must revise the artefact and re-submit. Reviewer/verifier evaluates
           the revised artefact; a new artefact entity is written to TypeDB
           (prior artefact is retained as audit evidence).

D06: Identity independence check fails (reviewer == author or verifier == author).
  action:  Escalate to sysadmin:dlm-sysadmin. Re-assign actor_id to the
           reviewer or verifier role such that independence is satisfied.
           Do not proceed until independence is confirmed.

D07: Instruction file authoring returns FAIL (token count, format, or content issue).
  action:  If token count exceeds 440: extract content to a SKILL.md companion
           per DLMS-2026-0114 FORMAT_B. If format violation: correct per
           failing V rule. If content invention (content not from spec): remove
           and re-submit. Iterate S06 until result: PASS.

D08: DoD verdict is FAIL (one or more mandatory gates fail).
  action:  Identify the failing GATE IDs. Return to the corresponding step
           (S01–S08) and remediate. Each re-evaluation produces a new DoD
           record; prior records are retained as audit evidence.

## ESCALATION

E01: agent-registry-updater triple-write fails (partial commit or rollback).
  action:  Do NOT treat a partial write as a success. Verify which of the three
           targets (TypeDB, tool-access-registry, dlms-agent-roster.md) was
           written and which was not. Roll back any partial writes manually if
           required. Escalate to sysadmin:dlm-sysadmin for investigation.
           Re-run S08 only after all three targets are confirmed clean.
