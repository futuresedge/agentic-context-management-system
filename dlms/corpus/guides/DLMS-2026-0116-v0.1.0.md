## SUMMARY
This procedure governs the operational onboarding of any agent in the Tier 15B
team (agent-creation-orchestrator through agent-retirement-coordinator) following
initial deployment or re-activation. It confirms that each agent's context
boundary is correctly scoped, TypeDB tool access is operational, required SKILL.md
files are reachable, and independence constraints are understood before the agent
participates in any live creation or retirement workflow.

## SCOPE

Applies to:
- All 9 Tier 15B agent roles: agent-creation-orchestrator, agent-request-handler,
  agent-problem-analyst, agent-specification-author, agent-specification-reviewer,
  agent-instruction-author, agent-specification-verifier, agent-registry-updater,
  agent-retirement-coordinator
- sysadmin:dlm-sysadmin as procedure owner and verification actor
- The Nexus MCP server as the runtime that provides agentcreation.* and roster.*
  tool access

Excludes:
- Initial creation of a new Tier 15B agent via the Agent Creation Operating SOP
  (DLMS-2026-0117) — this procedure applies after the agent has been registered
- Onboarding of Tier 15 Nexus Infrastructure agents (separate procedure)
- Any modification to agent specifications or instruction files during onboarding

## PREREQUISITES

P01: The target agent's `agent_class` entity exists in TypeDB with
     `agent_status: active`. Verified via roster.get (role_id).
     Failure → D01.

P02: The instruction file `.github/agents/{role_id}.agent.md` exists and
     has not been modified since verification (DLMS-2026-0115 GATE-05 passed).
     Verified by: sysadmin:dlm-sysadmin. Failure → D02.

P03: The Nexus MCP server is running and `agentcreation.getArtefact`,
     `agentcreation.writeRequest` (or the role-appropriate write tool),
     and `roster.get` all return 200. Failure → E01.

P04: The tool-access-registry entry for this role_id is present in
     `dlms/registry/tool-access-registry.md` with the correct permitted
     tools per DLMS-2026-0108. Verified by: sysadmin:dlm-sysadmin.
     Failure → D03.

P05: Required SKILL.md files are reachable at their declared paths.
     For roles that reference `.github/skills/agent-creation-patterns/SKILL.md`:
     confirm file exists. For agent-instruction-author: also confirm
     `.github/skills/instruction-file-authoring/SKILL.md`. For
     agent-specification-verifier: also confirm
     `.github/skills/spec-verification-criteria/SKILL.md`.
     Failure → D04.

## STEPS

S01: Confirm roster presence.
  action:  Call roster.get with the target role_id. Confirm agent_status == "active"
           and tier is correct per DLMS-2026-0108.
  actor:   sysadmin:dlm-sysadmin
  reads:   TypeDB agent_class entity via roster.get
  writes:  (none — verification only)
  on_failure: → D01

S02: Validate instruction file integrity.
  action:  Read `.github/agents/{role_id}.agent.md`. Confirm (a) frontmatter
           tools[] matches the tool-access-registry entry, (b) body begins
           with READS:/WRITES:/NEVER: context declaration, (c) body token
           count is ≤ 440 per DLMS-2026-0114 V10. Log any discrepancy.
  actor:   sysadmin:dlm-sysadmin
  reads:   .github/agents/{role_id}.agent.md
  writes:  validation result (internal)
  on_failure: → D02

S03: Verify MCP tool access.
  action:  Invoke `agentcreation.getArtefact` with mode 1 (role_id + artefact_type:
           agent-request-record) using a test role_id that is known to have no
           artefacts. Confirm the tool returns null without error. This confirms
           the gateway and TypeDB connection are operational for this role.
  actor:   sysadmin:dlm-sysadmin
  reads:   Nexus MCP server response
  writes:  (none — read-only probe; no audit event on null read)
  on_failure: → E01

S04: Confirm independence constraints.
  action:  For roles subject to independence requirements (agent-specification-reviewer,
           agent-specification-verifier), confirm the actor_id assigned to this
           instance is registered as distinct from the instances assigned to
           agent-specification-author and agent-instruction-author respectively.
           Independence is enforced at write time by the gate; this step is
           a pre-onboarding documentation check only.
  actor:   sysadmin:dlm-sysadmin
  reads:   actor_id assignments from agent_class entities in TypeDB
  writes:  (none — documentation verification only)
  on_failure: → D05

S05: Verify SKILL.md reachability.
  action:  Confirm all SKILL.md files referenced in the instruction file's
           SKILL_REFS section (if present) exist at their declared paths.
           For the three shared Tier 15B skills: confirm presence at
           `.github/skills/agent-creation-patterns/SKILL.md`,
           `.github/skills/instruction-file-authoring/SKILL.md`, and
           `.github/skills/spec-verification-criteria/SKILL.md`.
  actor:   sysadmin:dlm-sysadmin
  reads:   SKILL_REFS entries in instruction file; filesystem paths
  writes:  (none)
  on_failure: → D04

S06: Emit onboarding audit event.
  action:  Write agent_onboarded audit event to the audit trail. Required fields:
           agent_id = "agent:{role_id}", tier = 15B, onboarding_procedure_ref =
           "DLMS-2026-0116", onboarded_at (ISO 8601),
           onboarded_by = "sysadmin:dlm-sysadmin".
  actor:   sysadmin:dlm-sysadmin via Nexus audit tool
  reads:   (none)
  writes:  audit event in TypeDB
  on_failure: → E02

## DECISION_POINTS

D01: agent_status is not active or agent_class entity does not exist.
  action:  Check whether the agent creation workflow completed successfully
           via DLMS-2026-0117. If GATE-06 was not reached, the agent cannot
           be onboarded. Escalate to sysadmin:dlm-sysadmin.
  continue: only after agent_status == "active" is confirmed

D02: Instruction file is absent or fails integrity check.
  action:  If file is absent: re-run agent-instruction-author step in
           DLMS-2026-0117. If file fails token count: return to
           agent-instruction-author for refactoring (DLMS-2026-0114).
  continue: only after V10 and all other integrity checks pass

D03: Tool-access-registry entry missing or incorrect.
  action:  Return to agent-registry-updater to re-run STEP_02 of the
           creation workflow (agentcreation.updateRegistry).
  continue: only after registry entries are confirmed

D04: SKILL.md file missing at declared path.
  action:  Create the missing SKILL.md at the declared path per DLMS-2026-0114
           FORMAT_B. If it is one of the three shared Tier 15B skills, check
           `.github/skills/` directory for existence.
  continue: only after all SKILL_REFS paths resolve

D05: Independence constraint cannot be verified.
  action:  If actor_id conflict exists (e.g. specification-reviewer and
           specification-author share the same actor_id), escalate to
           sysadmin:dlm-sysadmin for actor_id re-assignment. Do not activate
           the agent until independence is resolvable at runtime.
  continue: only after actor_id distinctness is documented

## ESCALATION

E01: Nexus MCP server unreachable or tool returns unexpected error.
  action:  Escalate to sysadmin:dlm-sysadmin for infrastructure diagnosis
           per DLMS-2026-0104 (Nexus Infrastructure Deployment Procedure).
  continue: only after MCP server is confirmed operational

E02: Audit event cannot be written.
  action:  Log the failure; retry once. If retry fails, escalate to
           sysadmin:dlm-sysadmin. Onboarding is not complete until audit
           event is recorded.
  continue: only after audit event is confirmed written
