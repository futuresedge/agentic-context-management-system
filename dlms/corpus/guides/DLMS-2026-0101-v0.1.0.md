## SUMMARY

This procedure governs the end-to-end SysAdmin operations cycle: from receipt
of a sysadmin briefing (SBR-) or escalation trigger, through directive
issuance, independent verification, change application, and activity reporting,
to dispatch of the sysadmin-activity-report.md that seeds the next CI cycle.
It covers both routine cadence operation and reactive escalation paths within a
single unified STEPS sequence with decision branches per operating mode. The
primary outputs are cd-[YYYY-NNNN].md (change directive), sysadmin-
verification.md (DoD verification records), and sysadmin-activity-report.md
(cycle completion record).

## SCOPE

Agents active in this procedure:

| Position | Agent | Primary Output Artefact |
|---|---|---|
| A01 | DLM SysAdmin Agent | cd-[YYYY-NNNN].md |
| A02 | SysAdmin Verifier | sysadmin-verification.md (×2) |
| A03 | Policy Manager | updated policy documents |
| A04 | SLA Manager | updated SLA policies |
| A05 | Rules & Patterns Agent | updated rules/patterns artefacts |
| A06 | Guide Curator | updated corpus/guides artefacts |
| A07 | Configuration Controller | system-configuration.md |
| A08 | DoD Custodian | updated DoD templates (0024–0029) |
| A09 | SysAdmin Activity Monitor | sysadmin-activity-report.md |

Excludes:
- All Tier 13 CI pipeline agents (governed by DLMS-2026-0102)
- All stage-pipeline agents (governed by their respective Stage SOPs,
  DLMS-2026-0094 through DLMS-2026-0100)
- Tier 2 Governance Layer agents (governed by DLMS-2026-0093)
- The CI Cycle Orchestrator (trigger source, not participant in this procedure)

Executed by:
- sysadmin:dlm-sysadmin: change window authorisation (S06); escalation
  acknowledgement (S08); procedure oversight and E-condition resolution
- agent:dlm-sysadmin: directive issuance (S02–S03)
- agent:sysadmin-verifier: independent DoD verification (S04, S07)
- Governance change agents (A03–A08): change application (S06)
- agent:sysadmin-activity-monitor: cycle completion reporting (S09)

## PREREQUISITES

P01: SysAdmin Verifier Agent (agent:sysadmin-verifier) is confirmed as a
     distinct agent instance from DLM SysAdmin Agent (agent:dlm-sysadmin).
     These agents must never share identity per DLMS-2026-0014 R01.
     Verified by: sysadmin:dlm-sysadmin. Failure → E04.

P02: DLMS-2026-0076 (CI Cycle Policy), DLMS-2026-0078 (SLA Breach Response
     Policy), DLMS-2026-0079 (Change Management Policy), and DLMS-2026-0080
     (SysAdmin Escalation Policy) are in effect.
     Verified by: sysadmin:dlm-sysadmin. Failure → procedure deferred.

P03: TMPL-change-directive-001 (DLMS-2026-0074) and
     TMPL-sysadmin-briefing-001 (DLMS-2026-0073) are accessible.
     Verified by: agent:dlm-sysadmin. Failure → E04.

P04: Audit Trail Agent is reachable and accepting log entries.
     Verified by: sysadmin:dlm-sysadmin. Failure → E04 (halt; non-negotiable
     per DLMS-2026-0015).

P05: For routine triggers: a sysadmin-briefing.md (SBR-) from the completed
     CI cycle is present and flagged as ready-for-sysadmin.
     For escalation triggers: an escalation_event record containing
     escalation_event.id, cycle_id, and R01 rule reference is present.
     Verified by: sysadmin:dlm-sysadmin.

## STEPS

S01: Receive trigger; classify operating mode.
  action: Receive and validate the trigger event. Confirm that either a
          sysadmin-briefing.md (SBR-) has been received or one or more
          R01(a–f) escalation conditions have been raised. Log receipt to
          Audit Trail Agent. Proceed to D01 to determine the operating mode.
  actor:  sysadmin:dlm-sysadmin
  reads:  trigger event (SBR- artefact reference or escalation_event record)
  writes: audit log entry (trigger receipt, timestamp, mode classification)
  on_failure: → E04

  [D01] Trigger classification:
    - SBR- received only (routine cadence) → S02
    - Escalation event only (no SBR-) → S08
    - SBR- received AND escalation_carried_forward=true on SBR- → S02 (then
      S08 after S07 if escalation path not yet resolved)

S02: DLM SysAdmin Agent reads sysadmin-briefing.md.
  action: DLM SysAdmin Agent reads the sysadmin-briefing.md artefact (its
          sole designated input per DLMS-2026-0016 and DLMS-2026-0093).
          Evaluates each recommendation item for acceptance, deferral, or
          rejection. Must not read any other artefact, including CI pipeline
          outputs, policy documents, or prior directives.
  actor:  agent:dlm-sysadmin
  reads:  sysadmin-briefing.md (SBR-) — sole input; NEVER reads CI pipeline
          artefacts directly
  writes: internal evaluation (not yet a formal artefact)
  on_failure: → E04

S03: DLM SysAdmin Agent issues change directive.
  action: DLM SysAdmin Agent produces cd-[YYYY-NNNN].md per
          TMPL-change-directive-001 (DLMS-2026-0074). Each recommendation
          item is classified as accepted, deferred, or rejected with an
          explicit rationale and assigned priority. If R01(b) or R01(c)
          escalation is present (per D01 flag from S01), the CD- MUST
          include a remediation item or an explicit no-action rationale for
          the escalation trigger (DLMS-2026-0080 R04). Change directives
          that fail this requirement route to E03.
  actor:  agent:dlm-sysadmin
  reads:  sysadmin-briefing.md (SBR-); TMPL-0074 schema
  writes: cd-[YYYY-NNNN].md
  on_failure: → E04

S04: SysAdmin Verifier performs post-CD- DoD verification (first invocation).
  action: SysAdmin Verifier reads the CD- artefact and the procedure DoD
          checklist (derived from DLMS-2026-0080 verification rules). Produces
          sysadmin-verification.md with outcome: pass or fail. This agent must
          be distinct from agent:dlm-sysadmin (DLMS-2026-0014 R01).
  actor:  agent:sysadmin-verifier
  reads:  cd-[YYYY-NNNN].md; DLMS-2026-0080 DoD checklist
  writes: sysadmin-verification.md (first instance, labelled post-cd)
  on_failure: → E04

  [D02] SysAdmin Verifier post-CD- outcome:
    - pass → S05
    - fail → E01 (DoD failure on directive; CD- must be revised before
      proceeding)

S05: Evaluate whether accepted changes exist.
  action: Review cd-[YYYY-NNNN].md to determine whether any items are
          classified as accepted (i.e., require a change to be applied).
          If no items are accepted, skip directly to S09.
  actor:  sysadmin:dlm-sysadmin
  reads:  cd-[YYYY-NNNN].md
  writes: (none — routing decision only)
  on_failure: → E04

  [D03] Accepted changes present in CD-:
    - yes → S06
    - no (all items deferred or rejected) → S09

S06: Authorise change window and apply changes.
  action: sysadmin:dlm-sysadmin authorises the change window by logging a
          change-window-open audit event BEFORE any change is applied
          (DLMS-2026-0079 R03). Designated governance agents apply changes
          per the CD- assignment list: Policy Manager updates policy
          documents; SLA Manager updates SLA policies; Rules & Patterns Agent
          updates rules and patterns artefacts; Guide Curator updates
          corpus/guides; Configuration Controller updates system-configuration.md
          (exclusive write lock; config-change-log.md required); DoD Custodian
          updates DoD templates (DLMS-2026-0024–0029) as applicable. Each
          agent reads only its designated input scope per DLMS-2026-0016.
  actor:  sysadmin:dlm-sysadmin (change window authorisation);
          agent:policy-manager, agent:sla-manager, agent:rules-patterns,
          agent:guide-curator, agent:configuration-controller,
          agent:dod-custodian (change application — as assigned in CD-)
  reads:  cd-[YYYY-NNNN].md; each agent reads its assigned change scope
  writes: updated artefacts per CD- assignments; audit log entry
          (change-window-open event)
  on_failure: → E02

S07: SysAdmin Verifier performs post-change DoD verification (second invocation).
  action: SysAdmin Verifier performs independent verification of the applied
          changes. Reads the updated artefacts and the CD- assignments;
          produces a second sysadmin-verification.md (labelled post-change)
          with outcome: pass or fail. This is the same agent instance as S04
          but a new, independent invocation.
  actor:  agent:sysadmin-verifier
  reads:  updated change artefacts (as listed in CD-); cd-[YYYY-NNNN].md
  writes: sysadmin-verification.md (second instance, labelled post-change)
  on_failure: → E04

  [D04] SysAdmin Verifier post-change outcome:
    - pass → log change-window-close audit event; proceed to S08 (if
      escalation path pending from D01) or S09
    - fail → E02 (1-hour escalation window; change window remains open;
      no re-open until sysadmin:dlm-sysadmin authorises corrective action)

S08: Escalation path — acknowledge and resolve.
  action: sysadmin:dlm-sysadmin acknowledges the escalation event within the
          4-hour window required by DLMS-2026-0080. The acknowledgement cites
          escalation_event.id and cycle_id. Apply D05 to determine whether
          the escalation type requires a remediation item in the CD-. If the
          cycle is blocked (D06 — R01(f): no CD- has been issued within 2 days
          of SBR- delivery), acknowledge and confirm that a CD- must be issued
          before the CI cycle can complete. Log acknowledgement to Audit Trail
          Agent. Continue to S09.
  actor:  sysadmin:dlm-sysadmin
  reads:  escalation_event record; cd-[YYYY-NNNN].md (if already issued)
  writes: escalation acknowledgement audit log entry
  on_failure: → E04

  [D05] Escalation trigger type:
    - R01(b) (immediate-priority recommendation) or R01(c) (critical anomaly)
      → CD- MUST contain a remediation item or explicit no-action rationale
      before the escalation event is closed. If not present → E03.
    - R01(a), R01(d), R01(e), or R01(f) → acknowledge per standard
      escalation window; no additional CD- constraint beyond normal procedure.

  [D06] Cycle breach check (applicable when D01 routes to escalation path):
    - R01(f) active (no CD- in 2 days of SBR-): acknowledge cycle breach;
      CI cycle cannot complete until CD- is issued. Trigger standard S03 if
      CD- has not yet been issued.

S09: SysAdmin Activity Monitor produces activity report.
  action: SysAdmin Activity Monitor reads the completed CD-, both
          sysadmin-verification.md artefacts (post-cd and post-change), and
          directive completion logs. Produces sysadmin-activity-report.md
          summarising all actions taken, verification outcomes, deferred items,
          and any unresolved escalation events.
  actor:  agent:sysadmin-activity-monitor
  reads:  cd-[YYYY-NNNN].md; sysadmin-verification.md (both instances);
          directive completion logs
  writes: sysadmin-activity-report.md
  on_failure: → E04

S10: Dispatch activity report to CI cycle queue.
  action: sysadmin:dlm-sysadmin confirms sysadmin-activity-report.md is
          complete and dispatches it to the next CI cycle queue. Log dispatch
          event to Audit Trail Agent. Procedure complete.
  actor:  sysadmin:dlm-sysadmin
  reads:  sysadmin-activity-report.md
  writes: audit log entry (cycle dispatch, timestamp)
  on_failure: → E04

## DECISION_POINTS

D01: Trigger classification.
  condition: What type of trigger initiated this procedure?
  if_true:   SBR- received (routine) → S02.
  if_false:  Escalation event only (no SBR-) → S08. If both SBR- and
             escalation_carried_forward=true → S02 first, then S08 after S07.

D02: SysAdmin Verifier post-CD- outcome.
  condition: Does sysadmin-verification.md (post-cd) report outcome = pass?
  if_true:   proceed to S05.
  if_false:  → E01. CD- must be revised; return to S03 after correction.

D03: Accepted changes in CD-.
  condition: Does cd-[YYYY-NNNN].md contain at least one accepted item?
  if_true:   proceed to S06.
  if_false:  skip to S09 (no change window required).

D04: SysAdmin Verifier post-change outcome.
  condition: Does sysadmin-verification.md (post-change) report outcome = pass?
  if_true:   log change-window-close; proceed to S08 (if escalation pending) or S09.
  if_false:  → E02. Change window remains open; 1-hour escalation window applies.

D05: Escalation type.
  condition: Is the escalation trigger R01(b) (immediate-priority
             recommendation) or R01(c) (critical anomaly)?
  if_true:   CD- must include a remediation item or explicit no-action
             rationale before escalation event is closed. Failure → E03.
  if_false:  Standard acknowledgement; no additional CD- constraint.

D06: Cycle breach check.
  condition: Is R01(f) active — no CD- has been issued within 2 days of SBR-
             delivery?
  if_true:   Acknowledge cycle breach; CI cycle blocked until CD- is issued.
             Trigger S03 if CD- not yet produced.
  if_false:  No cycle breach; continue normal escalation acknowledgement at S08.

## ERROR_CONDITIONS

E01: Post-CD- DoD verification failure.
  condition: SysAdmin Verifier reports outcome = fail on sysadmin-
             verification.md (post-cd).
  likely_cause: CD- is malformed, missing required fields, or contains an
                item that violates DLMS-2026-0079 or DLMS-2026-0080 rules.
  resolution: Return to S03. DLM SysAdmin Agent revises cd-[YYYY-NNNN].md
              to address all failed DoD criteria. Repeat S03→S04 cycle.
              If failure persists after revision, escalate to
              sysadmin:dlm-sysadmin for manual review.

E02: Post-change verification failure.
  condition: SysAdmin Verifier reports outcome = fail on sysadmin-
             verification.md (post-change).
  likely_cause: One or more governance agents applied changes incorrectly
                or incompletely relative to CD- assignments.
  resolution: Change window remains open. sysadmin:dlm-sysadmin has a 1-hour
              window to authorise corrective action. Corrective changes are
              applied and S07 is re-invoked. If the corrective change still
              fails, escalate via DLMS-2026-0078 (SLA Breach Response Policy).

E03: CD- missing escalation remediation for R01(b) or R01(c).
  condition: CD- has been issued but does not contain a remediation item or
             explicit no-action rationale while D05 is active.
  likely_cause: DLM SysAdmin Agent omitted the escalation response item when
                constructing the CD-.
  resolution: Return to S03. CD- must be revised to include the required
              remediation item or no-action rationale before S04 is re-run.
              Log revision requirement to Audit Trail Agent.

E04: Audit Trail Agent unreachable or critical prerequisite failure.
  condition: Audit Trail Agent is not reachable; or a P01–P04 prerequisite
             cannot be satisfied; or a required artefact (SBR- or escalation
             record) is missing.
  likely_cause: Audit Trail infrastructure failure; onboarding incomplete;
                upstream CI pipeline issue.
  resolution: HALT. Do not proceed with any step. Notify sysadmin:dlm-sysadmin
              immediately. Restore Audit Trail Agent connectivity or resolve
              prerequisite before re-initiating the procedure. Per
              DLMS-2026-0015: no procedure step executes without a reachable
              Audit Trail.
