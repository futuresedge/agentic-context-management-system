## SUMMARY
This procedure governs the onboarding of any one of the six stage
orchestrator agent instances — the Tier 3 agents that receive document
routing events from the DLM System Orchestrator and manage all subordinate
agents within their respective stage. A stage orchestrator must register
itself with the DLM System Orchestrator and confirm reachability of all
subordinate agents before it can accept documents. The primary outputs are
an operational orchestrator registered in the routing table and a pair of
onboarding audit events.

## SCOPE

Applies to:
- All six stage orchestrators listed in the table below
- sysadmin:dlm-sysadmin as procedure owner and separation verifier
- DLM System Orchestrator (Tier 1) for registration in S06
- Audit Trail Agent as recipient of onboarding audit events

The six stage orchestrators, their governed agents, and their SLA references:

| Orchestrator | Stage ID | SLA policy | DoD template | Subordinate tier |
|---|---|---|---|---|
| Creation Orchestrator | creation | DLMS-2026-0057 | DLMS-2026-0024 | Tier 4 (7 agents) |
| Review & Approval Orchestrator | review | DLMS-2026-0058 | DLMS-2026-0025 | Tier 5 (11 agents) |
| Indexing & Classification Orchestrator | indexing | (see note) | DLMS-2026-0027 | Tier 7 (12 agents) |
| Storage & Versioning Orchestrator | storage | DLMS-2026-0059 | DLMS-2026-0026 | Tier 8 (7 agents) |
| Distribution Orchestrator | distribution | DLMS-2026-0060 | DLMS-2026-0028 | Tier 9 (7 agents) |
| Archival Orchestrator | archival | DLMS-2026-0061 | DLMS-2026-0029 | Tier 10 (7 agents) |

Note: The Indexing & Classification stage has no dedicated SLA policy; its
quality constraints are governed by DLMS-2026-0018 (Metadata Standard Policy)
and DLMS-2026-0019 (Taxonomy Policy). The Indexing Orchestrator loads those
two policies in place of an SLA reference.

Excludes:
- Onboarding of subordinate stage agents (Tiers 4–10): covered by their
  dedicated onboarding procedures (DLMS-2026-0084 through DLMS-2026-0089)
- DLM System Orchestrator (Tier 1): covered by DLMS-2026-0081
- Governance Layer agents (Tier 2): covered by DLMS-2026-0082
- Any agent not listed in the table above

Executed by:
- Stage orchestrator (self-check steps): S02, S03, S04, S05, S06, S08
- sysadmin:dlm-sysadmin: retrieval, separation verification (S01, S07)

## PREREQUISITES

P01: DLMS-2026-0014, DLMS-2026-0015, and DLMS-2026-0016 are status: approved
     or provisionally in effect. Additionally: DLMS-2026-0041 (Definition of
     Done Policy) is in effect. For stage orchestrators with an SLA policy
     (all except Indexing): the relevant stage SLA policy is available.
     Verified by: sysadmin:dlm-sysadmin. Failure → D01.

P02: This stage orchestrator's designated context package exists and
     contains: (a) the stage_id for this orchestrator; (b) the subordinate
     agent roster for this stage (agent_ids and endpoints); (c) the
     designated DoD template reference (per table above); (d) the relevant
     SLA policy reference or metadata standard policy references (for
     Indexing); (e) references to DLMS-2026-0015 and DLMS-2026-0016.
     Verified by: sysadmin:dlm-sysadmin. Failure → E01.

P03: Audit Trail Agent is reachable and accepting events. Verified by: test
     ping with positive acknowledgement. Failure → E03.

P04: DLM System Orchestrator (Tier 1) is active. The routing registration
     in S06 requires the Tier 1 orchestrator to be operational to receive
     the registration event. Verified by: sysadmin:dlm-sysadmin via Tier 1
     status check. Failure → defer S06 until Tier 1 is active; steps S01–S05
     and S07–S08 may proceed without Tier 1 being active, but the stage
     orchestrator may not accept documents until S06 succeeds.

## STEPS

S01: Retrieve context package.
  action: Retrieve this stage orchestrator's designated context package and
          confirm it satisfies P02. Note the stage_id, DoD template ref,
          SLA policy ref (or metadata standard refs for Indexing), and
          subordinate agent roster.
  actor:  sysadmin:dlm-sysadmin
  reads:  designated context package
  writes: (none — verification only)
  on_failure: → E01

S02: Validate context boundary.
  action: Confirm the READS list is limited to: (a) subordinate agent roster
          for this stage; (b) the designated DoD template schema; (c) the
          relevant SLA policy or metadata standard policies; (d) audit event
          schema (DLMS-2026-0015). Confirm the NEVER list excludes: document
          body content of documents in transit; other stages' routing tables;
          other stages' subordinate agent rosters. Per DLMS-2026-0016.
  actor:  Stage orchestrator (self-check); verified by sysadmin:dlm-sysadmin
  reads:  context boundary specification within context package
  writes: boundary validation result (internal)
  on_failure: → D02

S03: Load governing policies and stage configuration into context.
  action: Load into active working context: DLMS-2026-0014, DLMS-2026-0015,
          DLMS-2026-0016, DLMS-2026-0041, and the stage-specific references
          from P01. Record: stage_id, dod_template_ref, sla_ref (or
          metadata_policy_refs for Indexing).
  actor:  Stage orchestrator
  reads:  policy references from context package
  writes: active policy context and stage configuration (internal)
  on_failure: → E01 (if a required policy or template is not retrievable)

S04: Emit onboarding-start audit event.
  action: Write an onboarding-start event to the audit trail per
          DLMS-2026-0015. Required fields: agent_id, stage_id, tier = 3,
          onboarding_procedure_ref = "DLMS-2026-0083", timestamp (ISO 8601).
  actor:  Stage orchestrator
  reads:  DLMS-2026-0015 (audit event schema)
  writes: audit-trail.log (onboarding-start event)
  on_failure: → E03

S05: Confirm subordinate agent reachability.
  action: For each agent_id in the subordinate agent roster (from context
          package), send a pings to confirm the agent is reachable and
          its onboarding status is active or in-progress. Record per agent:
          agent_id, reachable (boolean), onboarding_status, checked_at
          (ISO 8601). An agent counts as reachable if it acknowledges
          within 30 seconds.
          Note: subordinate agents may be onboarding concurrently. A
          status of in-progress is acceptable. An agent that has not yet
          begun onboarding is flagged as unavailable.
  actor:  Stage orchestrator
  reads:  subordinate agent roster from context package
  writes: reachability log (internal)
  on_failure: If zero subordinates reachable → halt; see E02.
              If some unavailable → continue; log in S08; notify
              sysadmin:dlm-sysadmin. The stage orchestrator may begin
              accepting documents only for agent-complete pathways.

S06: Register with DLM System Orchestrator.
  action: Dispatch a registration event to the DLM System Orchestrator
          (Tier 1) containing: this_stage_id, orchestrator_agent_id,
          endpoint, timestamp. Confirm the System Orchestrator's routing
          table now includes this stage. If Tier 1 is not yet active,
          defer this step per P04; mark step as pending and emit an audit
          note; proceed to S07.
  actor:  Stage orchestrator
  reads:  DLM System Orchestrator routing table endpoint (from context
          package)
  writes: Registration event to DLM System Orchestrator; routing table
          entry (within Tier 1)
  on_failure: → E04 (if Tier 1 is active but rejects the registration)

S07: Confirm separation criterion.
  action: Confirm this stage orchestrator's agent_id is distinct from the
          agent_id of the DoD Agent assigned to this stage (Tier 4–10
          DoD Agent per the subordinate roster). No orchestrator may serve
          as its own stage's DoD gatekeeper, per DLMS-2026-0014 R01.
  actor:  sysadmin:dlm-sysadmin
  reads:  DoD Agent agent_id from subordinate roster (S05 reachability log)
  writes: separation confirmation note (internal)
  on_failure: → D03

S08: Emit onboarding-complete audit event.
  action: Write an onboarding-complete event to the audit trail per
          DLMS-2026-0015. Required fields: agent_id, stage_id, tier = 3,
          onboarding_procedure_ref = "DLMS-2026-0083",
          outcome [success | failure],
          subordinates_reachable (array of agent_ids confirmed in S05),
          subordinates_unavailable (array or empty),
          tier1_registration_complete (boolean, false if deferred per P04),
          timestamp (ISO 8601).
  actor:  Stage orchestrator
  reads:  DLMS-2026-0015 (audit event schema); reachability log from S05
  writes: audit-trail.log (onboarding-complete event)
  on_failure: → E03

## DECISION_POINTS

D01: If P01 fails (any required policy not approved or provisionally in
     effect) → halt. Notify sysadmin:dlm-sysadmin. Do not proceed.

D02: If S02 fails (context boundary includes resources outside the permitted
     READS set) → halt. Do not initiate the orchestrator. Notify
     sysadmin:dlm-sysadmin for context package correction before
     re-attempting from S01.

D03: If S07 fails (orchestrator agent_id == DoD Agent agent_id for this
     stage) → halt. Escalate to sysadmin:dlm-sysadmin. Two separate agent
     instances must be provisioned before either can be onboarded.

## OUTPUTS

| Artefact | Produced by step | Written to | Consumed by |
|---|---|---|---|
| Operational stage orchestrator with active subordinate roster | S03–S05 | internal agent state | DLM System Orchestrator; all subordinate Tier 4–10 agents |
| Routing table entry in DLM System Orchestrator | S06 | Tier 1 routing table | DLM System Orchestrator |
| onboarding-start audit event | S04 | audit-trail.log | Audit Trail Agent; Agent Behaviour Analyst (CI) |
| onboarding-complete audit event | S08 | audit-trail.log | Audit Trail Agent; sysadmin:dlm-sysadmin |

## ERROR_CONDITIONS

E01: Context package unavailable or incomplete.
  condition:    Context package is unreachable, or required references
                (subordinate roster, DoD template, SLA/standard policies)
                are absent.
  likely_cause: Corpus not yet populated; incorrect context package path;
                stage-specific policy or template not yet authored.
  resolution:   sysadmin:dlm-sysadmin provides corrected context package
                or defers onboarding until all prerequisites are available.

E02: All subordinate agents unreachable.
  condition:    Zero agents in the subordinate roster return positive
                acknowledgements in S05.
  likely_cause: Tier 4–10 agents not yet deployed or onboarded for this
                stage; message bus not operational.
  resolution:   Halt S05 at zero-reachable condition. Notify
                sysadmin:dlm-sysadmin. Do not proceed to S06 for live
                document acceptance. Onboarding may complete with
                subordinates_unavailable = full roster; the orchestrator
                must not route live documents until at least one subordinate
                pathway is complete.

E03: Audit trail unreachable.
  condition:    S04 or S08 cannot write to audit-trail.log.
  likely_cause: Audit Trail Agent offline; message bus fault.
  resolution:   Halt at the failing step. Alert sysadmin:dlm-sysadmin.
                Do not mark onboarding complete. Retry only after both
                required events are written.

E04: DLM System Orchestrator rejects stage registration.
  condition:    Tier 1 is active but returns a rejection or non-acknowledgement
                to the registration event in S06.
  likely_cause: Routing table already contains a conflicting entry for this
                stage_id (duplicate orchestrator instance); Tier 1 version
                mismatch.
  resolution:   Halt. Notify sysadmin:dlm-sysadmin. Do not accept documents
                until the conflict is resolved and a successful registration
                acknowledgement is received.
