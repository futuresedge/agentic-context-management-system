## SUMMARY
This policy governs how the Learning Synthesizer aggregates Knowledge Base
entries into synthesis artefacts, when synthesis runs, what patterns are
identified, how outputs are routed, and what independence constraints apply.
It depends on Knowledge Base Contribution Policy (DLMS-2026-0063), which
defines the KB structure and entry lifecycle that this policy consumes. This
is a Tier 3 Operational Lifecycle policy.

## SCOPE
Applies to: Learning Synthesizer agent; all KB entries under the kb/
directory as structured by DLMS-2026-0063 R03; sysadmin:dlm-sysadmin as
recipient of critical synthesis escalations and the SysAdmin briefing queue.

Excludes: KB entry contribution (governed by DLMS-2026-0063); the creation
or content of individual learning records (governed by DLMS-2026-0034 and
the producing agent); action taken on synthesis recommendations — what the
SysAdmin or downstream agents do in response to a synthesis report is outside
this policy's scope; performance reporting (governed by Wave 12 templates and
Wave 13 CI policies).

Bootstrap exception: Until TMPL-learning-synthesis-001 (Wave 12) is
available, synthesis output is produced per the interim format specified in
R05. This exception is self-cancelling when Wave 12 is drafted.

## DEFINITIONS

CI cycle:
  The periodic continuous-improvement cycle during which stage agent work
  is collected, reviewed, and assessed. Each CI cycle has a CI_cycle_id
  that uniquely identifies it. The Learning Synthesizer runs synthesis
  once per CI cycle per R01.

cross-stage recurrence:
  A pattern identified in synthesis when the same finding_type appears in
  KB entries from two or more distinct stage values within the synthesis
  window. Indicates a problem that is not isolated to a single stage.

deferred synthesis:
  A synthesis that does not run in the current CI cycle because the minimum
  record threshold (R02) was not met. Accumulated entries remain in scope
  for the next synthesis cycle per R03.

frequency spike:
  A pattern identified in synthesis when a single finding_type slot contains
  an entry count that exceeds the mean entry count across all occupied slots
  plus one standard deviation. Indicates systemic recurrence of a specific
  problem type.

independence requirement:
  The constraint that the Learning Synthesizer must be a different agent
  instance from the KB Agent that contributed entries in the same CI cycle,
  per Verification Independence Policy (DLMS-2026-0014). Prevents the same
  agent from both writing to and summarising the KB in a single cycle.

synthesis window:
  The set of KB entries that Learning Synthesizer processes in a given
  synthesis cycle. Defined in R03.

unactioned critical/major:
  KB entries with severity: critical or severity: major whose source
  learning records still have a status that has not been fully resolved
  through downstream action. Identifies high-priority findings carrying
  the strongest signal for SysAdmin attention.

## RULES

### Synthesis_Trigger

R01:
  rule: >
    Learning Synthesizer runs exactly once per CI cycle. The synthesis run
    for cycle N must be triggered after KB Agent signals completion of all
    KB contribution events for cycle N. No mid-cycle synthesis is permitted.
    A synthesis run may not be triggered by any agent other than the CI
    cycle orchestration system or sysadmin:dlm-sysadmin.
  test: >
    For each CI_cycle_id: exactly one learning-synthesis-completed event
    (R09) exists with that cycle_id, and its timestamp is after the final
    kb-record-contributed event for the same cycle_id. Multiple synthesis
    events for the same cycle_id, or any synthesis event preceding the
    final contribution event for that cycle, are policy violations.
  checked_by: Audit Trail Agent; CI Cycle Orchestrator

R02:
  rule: >
    If fewer than 10 KB entries were contributed (outcome: new-entry or
    merged) in the current CI cycle, Learning Synthesizer must defer
    synthesis for that cycle. KB Agent logs a deferred-synthesis audit
    event containing: the current cycle's contribution count and the
    running total of accumulated deferred entries not yet included in
    any prior synthesis artefact. Entries accumulated from deferred
    cycles remain in scope for the next cycle's synthesis window per R03.
  test: >
    For any CI cycle where new-entry + merged outcomes < 10: a
    deferred-synthesis audit event exists for that cycle_id with the
    required counts, AND no learning-synthesis-completed event exists
    for that cycle_id.
  checked_by: KB Agent; Audit Trail Agent

### Synthesis_Scope

R03:
  rule: >
    The synthesis window for a given CI cycle covers: (a) all KB entries
    contributed (outcome: new-entry or merged) during the current CI cycle;
    and (b) all accumulated KB entries from prior deferred cycles that have
    not been included in any previous learning-synthesis-report artefact.
    The synthesis window excludes entries already covered in a prior
    synthesis artefact, even if those entries have since been updated.
  test: >
    For each synthesis run: Learning Synthesizer's input set == all entries
    from current cycle N + all entries from prior cycles where no
    synthesis artefact lists their CI_cycle_id. Entries already cited in
    a prior synthesis artefact must not appear in the current window.
  checked_by: Learning Synthesizer; Audit Trail Agent

R04:
  rule: >
    Learning Synthesizer must identify the following three pattern types
    from the synthesis window:
    (a) Frequency spike: a finding_type slot where the count of entries
      in the window exceeds (mean count per occupied slot) + 1 standard
      deviation. If all occupied slots have the same count, no frequency
      spike is present.
    (b) Cross-stage recurrence: a finding_type value that appears in
      entries from two or more distinct stage values within the window.
    (c) Unactioned critical/major: KB entries in the window whose severity
      is critical or major and whose source learning records have not been
      transitioned to a terminal status (actioned or dismissed) at the
      time of synthesis.
    The synthesis artefact must enumerate all identified patterns by type.
    If no instances of a pattern type are found, the pattern type is
    reported as empty.
  test: >
    For each synthesis artefact: it contains a pattern_list with entries
    for all three pattern types (a, b, c) — empty lists are valid.
    Any pattern present in the window that is absent from the artefact
    is a synthesis omission and must be flagged by the Audit Trail Agent
    on review.
  checked_by: Learning Synthesizer; Audit Trail Agent

### Output_Artefact

R05:
  rule: >
    Learning Synthesizer must produce exactly one learning-synthesis-report
    artefact per synthesis cycle. The artefact's template is
    TMPL-learning-synthesis-001 (see NOTES — Wave 12 forward reference).
    Until TMPL-learning-synthesis-001 is available, the interim artefact
    must contain at minimum: synthesis_artefact_id (format:
    LSR-{YYYY}-{NNNN}), CI_cycle_id, record_count_in_window,
    pattern_list (typed per R04 categories with entry details),
    and critical_escalation_list (learning_ids of unactioned critical
    entries requiring direct sysadmin notification per R06). The artefact
    must be produced before the cycle's synthesis is considered complete.
  test: >
    For each CI cycle with synthesis (not deferred): a
    learning-synthesis-report artefact with a valid LSR-YYYY-NNNN ID
    exists and its CI_cycle_id matches the current cycle. More than one
    artefact for the same CI_cycle_id is a production error.
  checked_by: Learning Synthesizer; Audit Trail Agent

### Action_Routing

R06:
  rule: >
    On completion of a synthesis cycle, Learning Synthesizer must route
    the learning-synthesis-report to the SysAdmin briefing queue.
    Additionally, for each entry identified in R04c (unactioned:
    severity critical) Learning Synthesizer must produce a direct
    notification event to sysadmin:dlm-sysadmin. The direct notification
    must identify: the learning_id, the source_doc_id, the finding, and
    the stage. SysAdmin briefing queue routing and direct notification
    for critical findings are both mandatory and independent — one does
    not substitute for the other.
  test: >
    For each synthesis artefact: a SysAdmin-briefing-queue routing event
    exists for the artefact. For each learning_id in the artefact's
    critical_escalation_list: a direct sysadmin notification event exists
    with the required four fields. Absence of either routing event is a
    Tier 3 violation.
  checked_by: Audit Trail Agent; sysadmin:dlm-sysadmin

### Independence

R07:
  rule: >
    The Learning Synthesizer executing synthesis for a given CI cycle must
    be a different agent instance from the KB Agent that contributed KB
    entries in that same cycle, per Verification Independence Policy
    (DLMS-2026-0014). An agent that contributed entries to the KB during
    cycle N may not run synthesis for cycle N. If only one agent instance
    is available for both roles, synthesis must be deferred until an
    independent instance is available; sysadmin:dlm-sysadmin must be
    notified of the deferral.
  test: >
    For each learning-synthesis-completed event for cycle N: the
    performing_agent_id does not match the contributing_agent_id of any
    kb-record-contributed event for the same cycle N. A match is a Tier 2
    Verification Independence violation per DLMS-2026-0014.
  checked_by: Audit Trail Agent; Agent Behaviour Analyst

### Context_Boundary

R08:
  rule: >
    Learning Synthesizer's reads list during a synthesis task is confined
    to the kb/ directory — all KB entries within the synthesis window
    defined by R03. Learning Synthesizer must not read individual learning
    records outside the KB, corpus policy documents, stage artefact
    templates, the audit log, or any other system artefact directly during
    a synthesis task. All data required for synthesis must be available
    from KB entries alone.
  test: >
    All reads by Learning Synthesizer during a synthesis task are confined
    to the kb/ directory. Any read outside this directory during a
    synthesis task is a context boundary violation per DLMS-2026-0016.
  checked_by: Audit Trail Agent; Agent Behaviour Analyst

### Audit

R09:
  rule: >
    Successful synthesis completion must produce a learning-synthesis-completed
    audit event. The event must contain: synthesis_artefact_id,
    CI_cycle_id, record_count_in_window (total entries in the synthesis
    window per R03), pattern_count (total number of patterns identified
    across all three types in R04), critical_escalations_triggered (count
    of direct sysadmin notifications sent per R06), and
    deferred_entries_remaining (count of non-synthesised entries
    accumulated for the next cycle).
  test: >
    For each completed synthesis cycle: a learning-synthesis-completed
    event with all seven required fields exists before the cycle is
    closed. Absence of this event, or an event with any required field
    null, is a Tier 3 audit failure per DLMS-2026-0015.
  checked_by: Audit Trail Agent; Quality Monitor

## EXCEPTIONS_PROCESS
Tier 3 exceptions are permitted on a time-limited basis with SysAdmin
approval. To request an exception to any rule in this policy: (1) The
requesting agent produces a policy-exception-request artefact addressed
to the SysAdmin directive queue, citing the rule reference, the reason
the rule cannot be satisfied, and proposed mitigating controls. (2)
sysadmin:dlm-sysadmin reviews and, if approved, issues a
policy-exception-grant directive specifying the rule, scope, expiry date,
and audit conditions. (3) The exception is logged as a policy-exception
audit event visible in the next CI cycle report. No exception may extend
beyond 90 days without renewal. No exception may waive R07 (independence
constraint) — independence failures are Tier 2 violations that no
Tier 3 exception process can waive.

## ENFORCEMENT
  primary_agent:    Learning Synthesizer; Audit Trail Agent
  gate_positions:
    - Per-CI-cycle, post-contribution: Learning Synthesizer is triggered
      after final kb-record-contributed event for the cycle
    - Per-synthesis-run: Audit Trail Agent validates R09 event
      completeness immediately after each synthesis completion
    - CI cycle close: Quality Monitor reviews all synthesis events and
      checks R07 independence compliance
  audit: >
    All learning-synthesis-completed events are logged per R09. Deferred
    synthesis events are logged per R02. Independence violations (R07
    breach) are logged as verification-independence-violation events per
    DLMS-2026-0014. Context boundary violations (R08 breach) are logged
    as context-boundary-violation events per DLMS-2026-0015.
  violation_type:   Tier 3 operational violation; R07 breaches are also
                    Tier 2 Verification Independence violations per
                    DLMS-2026-0014
  escalation: >
    Independence violations (R07 breach) are immediately escalated to the
    SysAdmin directive queue as Tier 2 violations per Policy Governance
    Policy (DLMS-2026-0001). Repeated synthesis omissions — R04 patterns
    present in the KB window but absent from artefacts across multiple
    cycles — trigger a SysAdmin review of Learning Synthesizer
    configuration.

## REVIEW_SCHEDULE
  interval_max:      6 months (Tier 3 maximum)
  trigger_conditions:
    - TMPL-learning-synthesis-001 (Wave 12) is drafted — mandatory
      trigger; R05 must be updated to reference the formal template and
      the interim format exception removed.
    - Knowledge Base Contribution Policy (DLMS-2026-0063) is amended in
      a way that changes the KB slot structure, entry schema, or severity
      values — R03, R04, and R09 must be reviewed for consistency.
    - TMPL-learnings-001 (DLMS-2026-0034) severity enum values or
      finding_type values are extended — R04 pattern definitions may
      need updating.
    - CI cycle reports consistently show deferred synthesis (R02 deferral
      rate > 50% of cycles), indicating the minimum threshold may be
      miscalibrated relative to actual KB contribution volumes.
