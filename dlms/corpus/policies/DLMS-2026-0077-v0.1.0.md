## SUMMARY
This policy defines when an impact assessment is required before a
document change or archival is executed, what the assessment must cover,
and how its findings must be recorded and acted upon. Its purpose is to
prevent unintended downstream harm when documents on which other
documents or distribution recipients depend are modified or retired.

## SCOPE

Applies to:
- Any change directive (CD-) that modifies, supersedes, or archives a
  DLMS document with one or more recorded dependencies
- Any archival action on a document with status: approved and active
  distribution recipients
- The agent or human initiating the change and the agent performing
  the assessment
- All DLMS document types that may appear in a dependencies block as
  defined in Document Dependency Policy (DLMS-2026-0020)

Excludes:
- Patch-level corrections (version x.x.PATCH) that do not alter
  normative content — defined as changes to spelling, formatting,
  or typographical errors only, where no rule, field, or section
  heading changes
- Internal draft-stage document changes (status: draft) with no
  approved downstream dependents
- New document creation (no prior dependents can exist)

## DEFINITIONS

impact assessment:
  A structured evaluation of the effects of a proposed change to a DLMS
  document on all documents that depend on it, and on all active
  distribution recipients of the document. The assessment traverses the
  full dependency graph, records findings, and must be completed before
  the change proceeds.

dependency graph:
  The directed graph of DLMS document relationships as recorded in each
  document's dependencies frontmatter block, governed by Document
  Dependency Policy (DLMS-2026-0020). The graph is traversed from the
  target document outward to all documents that reference it.

active dependency:
  A dependency relationship (is-governed-by, implements, references, or
  supersedes) in an approved or under_review document that names the
  change target as a dependency. A dependency in a draft-status
  document with no approved downstream dependents is not considered
  active for this policy's purposes.

affected document:
  Any document with an active dependency on the change target.

distribution recipients:
  Agents and human roles listed as active recipients in the most recent
  distribution log artefact (DLMS-2026-0054) for the target document.

## RULES

### Trigger Conditions

R01:
  rule: >
    An impact assessment is required before archiving any document that
    has one or more active dependencies — that is, any approved or
    under_review document that lists it as a dependency per Document
    Dependency Policy (DLMS-2026-0020). The archival action must not
    proceed until the impact assessment is complete and its findings are
    recorded.
  test: >
    IF target_document.status IN ["approved", "under_review"] AND
       EXISTS dep IN corpus WHERE dep.dependencies includes target_document.doc_id
    THEN impact_assessment.status == "complete" BEFORE archival proceeds
  checked_by: Archival Stage Agent; agent:ci-cycle-orchestrator

R02:
  rule: >
    An impact assessment is required before issuing any change directive
    (CD-) that modifies the normative content of a document — including
    rule changes, field additions or removals, schema changes, or status
    transitions to superseded — when that document has one or more active
    dependencies. Minor patches (version x.x.PATCH, non-normative only)
    are exempt.
  test: >
    IF change_target is normative change AND
       EXISTS active_dependency on change_target
    THEN impact_assessment.status == "complete" BEFORE CD- is issued
    IF change is patch AND no normative content changed:
      impact_assessment not required
  checked_by: agent:dlm-sysadmin-agent; Agent Format Validator

R03:
  rule: >
    An impact assessment is required before archiving any document that
    has active distribution recipients — that is, any document whose
    most recent distribution log artefact (DLMS-2026-0054) contains
    at least one recipient with status: active. The check must use the
    most recent distribution log for that document_id.
  test: >
    IF target_document.most_recent_distribution_log.active_recipients.count > 0
    THEN impact_assessment.status == "complete" BEFORE archival proceeds
  checked_by: Distribution Stage Agent; Archival Stage Agent

### Assessment Scope

R04:
  rule: >
    An impact assessment must traverse the full dependency graph of the
    change target, using the dependency relationships recorded in all
    corpus documents per Document Dependency Policy (DLMS-2026-0020).
    The assessment must identify every affected document at all depths
    of the graph — not only direct dependents.
  test: >
    impact_assessment.affected_documents includes ALL documents D where
      THERE EXISTS a path in the dependency graph from target to D
    (full transitive closure, not depth-1 only)
  checked_by: Agent performing assessment; CI Cycle Orchestrator

R05:
  rule: >
    For each affected document identified in the dependency graph
    traversal, the assessment must record: (a) the affected document's
    doc_id and current status; (b) the dependency relationship type
    (is-governed-by, implements, references, supersedes); (c) the
    assessed impact severity (none, minor, major, critical); and
    (d) the recommended action (no change required, update required,
    separate review required).
  test: >
    FOR each D in impact_assessment.affected_documents:
      D.doc_id non-null AND
      D.dependency_rel IN ["is-governed-by", "implements", "references",
                           "supersedes"] AND
      D.impact_severity IN ["none", "minor", "major", "critical"] AND
      D.recommended_action IN ["no-change-required", "update-required",
                               "separate-review-required"]
  checked_by: Agent Format Validator; Agent performing assessment

R06:
  rule: >
    If the target document has active distribution recipients, the impact
    assessment must additionally record the recipient list from the most
    recent distribution log (DLMS-2026-0054) and assess whether each
    recipient should be notified of the change.
  test: >
    IF R03 triggers impact assessment:
      impact_assessment.distribution_review.recipients non-empty AND
      FOR each recipient: {agent_id, notification_required: boolean}
  checked_by: Distribution Stage Agent; Agent performing assessment

### Recording and Gating

R07:
  rule: >
    Impact assessment findings must be recorded in the relevant stage
    artefact before the change proceeds. For archival — in the archival
    recommendation artefact (DLMS-2026-0055). For change directives —
    in the change directive (CD-) body under a dedicated IMPACT section
    or as an appended reference. The assessment is not optional and may
    not be completed after the change is implemented.
  test: >
    impact_assessment.findings recorded in stage artefact BEFORE
    change proceeds. stage_artefact.impact_assessment_ref non-null.
  checked_by: Archival Stage Agent; agent:dlm-sysadmin-agent

R08:
  rule: >
    If the impact assessment identifies any affected document with
    impact_severity: critical, the change must not proceed without
    explicit acknowledgement from sysadmin:dlm-sysadmin. A critical
    severity assessment must be included in the SysAdmin briefing for
    the current CI cycle.
  test: >
    IF any affected_document.impact_severity == "critical":
      sysadmin:dlm-sysadmin.acknowledgement_recorded == true BEFORE
      change proceeds.
  checked_by: agent:dlm-sysadmin-agent; agent:sysadmin-briefing-agent

### Independence

R09:
  rule: >
    The agent performing the impact assessment must differ from the agent
    initiating the change or authoring the change directive, in
    accordance with Verification Independence Policy (DLMS-2026-0014).
    agent:ci-cycle-orchestrator may not perform impact assessments for
    changes it initiates.
  test: >
    impact_assessment.assessed_by != change.initiated_by
  checked_by: Agent Format Validator; Audit Trail Agent

## EXCEPTIONS_PROCESS

Exceptions require Tier 3 exception approval from sysadmin:dlm-sysadmin:
1. Submitter must log the specific rule being excepted and business
   justification as an audit event before the change proceeds.
2. sysadmin:dlm-sysadmin approval must be recorded as an audit event
   within 12 hours.
3. Exceptions apply to a single change instance only; they do not
   create standing waivers.

The following cannot be excepted:
- R08 (critical-severity changes require SysAdmin acknowledgement)
- R09 (independence constraint — Tier 2 per DLMS-2026-0014)

## ENFORCEMENT

primary_agent:    agent:dlm-sysadmin-agent
secondary_agent:  Archival Stage Agent; Distribution Stage Agent
gate_positions:
  - Before any archival action on a document with active dependencies
    (R01)
  - Before any archival action on a document with active distribution
    recipients (R03)
  - Before a CD- is issued for normative changes with active dependencies
    (R02)
  - Before any change proceeds where assessment finds critical severity
    (R08)
violation_type:   Change blocked; audit event logged; sysadmin:dlm-sysadmin
                  notified. Critical-severity violations require explicit
                  SysAdmin acknowledgement before unblocking.
escalation_ref:   SysAdmin Escalation Policy (DLMS-2026-0080, Wave 13)

  - A new document type is added to the corpus that may create
    dependency relationships not covered by the current rules
