## SUMMARY
This policy governs the authoring, versioning, storage, loading, and update
lifecycle of all SKILL.md files used by DLMS agents. It enforces the
progressive disclosure pattern — skill file bodies are loaded on demand when
a task requires them, never at agent startup — directly enacting P7 (Context
Economy) and P9 (Narrow Context, Wide Knowledge). It defines the conditions
under which a skill file update constitutes a material change requiring
re-verification of the agent instruction file that references it.

## SCOPE
Applies to: all SKILL.md files referenced by any DLMS agent instruction file
across all tiers; all Tier 15B agents that author, update, or retire skill
files; any agent instruction file that declares a SKILL_REFS section.

Excludes: corpus documents that are read by agents as context packages (governed
by DLMS-2026-0016 and the Context Delivery Layer); agent instruction files
themselves (governed by DLMS-2026-0108 R08 and DLMS-2026-0111); prompt files
(.prompt.md) and workspace instruction files (.instructions.md).

## DEFINITIONS

material change:
  An update to a SKILL.md file that alters the structural organisation of its
  content: adding, removing, or renaming a top-level section heading; changing
  the format contract (e.g., switching from a table to a bullet list); or
  removing content that a consuming agent's instruction file explicitly
  references by heading name. Corrections to spelling, punctuation, or factual
  content within an existing section are not material changes.

progressive disclosure:
  The loading pattern where a skill file's body content is brought into an
  agent's context only when a specific task condition is met, not at agent
  invocation. The skill file's frontmatter description is always available;
  the body is loaded conditionally. This preserves context budget and enables
  prompt caching at the base instruction level.

skill file:
  A SKILL.md file containing supplementary task-specific content — rubrics,
  checklists, format specifications, lens definitions — that an agent loads
  on demand. A SKILL.md file is not an agent instruction file and is not a
  corpus document. It is a governed artefact maintained by the tier that owns
  the referencing agent, or by Tier 15B.

skill file version:
  A semver string (MAJOR.MINOR.PATCH) tracked independently from the version
  of any agent instruction file that references the skill file. Version
  increments follow the same rules as corpus documents: patch for corrections,
  minor for content changes within existing sections, major for structural
  changes (which are always material changes).

SKILL_REFS section:
  A declared section in an agent instruction file that lists the SKILL.md files
  the agent may load, the path to each, the load condition, and the skill file
  version pinned at instruction file creation time. Required for any agent
  instruction file that uses progressive disclosure.

## RULES

### Versioning

R01:
  rule: >
    Every SKILL.md file must carry an independent version string in its
    frontmatter. Skill file versions are not coupled to the version of the
    agent instruction file that references them. A skill file update that does
    not affect any referencing agent's behaviour increments the skill file
    version only; the referencing instruction file version is unchanged.
  test: >
    For every SKILL.md file: a version field exists in frontmatter AND the
    version string is valid semver (MAJOR.MINOR.PATCH) AND the version is
    incremented on every commit that modifies the file's content.
  checked_by: agent-instruction-author; agent-specification-verifier;
              CI agent-behaviour-monitor

R02:
  rule: >
    When a skill file update constitutes a material change — as defined in
    this policy's DEFINITIONS — the agent-instruction-author must produce an
    updated instruction file that references the new skill file version and
    submit it for re-verification by the agent-specification-verifier. The
    re-verification must confirm that the consuming agent's instruction file
    SKILL_REFS section correctly reflects the new skill file structure. No
    agent may run against an instruction file that references a skill file
    at a version that has undergone a material change without re-verification.
  test: >
    For every skill file at a version V that constitutes a material change from
    version V-1: all agent instruction files with a SKILL_REFS entry pinned
    to V-1 have been updated to pin V AND have a corresponding re-verification
    artefact recorded by agent-specification-verifier with timestamp after the
    skill file version V commit.
  checked_by: agent-specification-verifier; CI agent-behaviour-monitor

### Loading_Discipline

R03:
  rule: >
    Skill file bodies must never be loaded at agent startup or included in
    the base context of an agent invocation. An agent must load a skill file's
    body only when the specific task condition declared in the SKILL_REFS entry
    for that file is met during the current invocation. An agent that loads
    a skill file at startup — regardless of whether the task requires it —
    is in violation of P7 and this rule.
  test: >
    Agent instruction files must not contain the full body text of any SKILL.md
    file inline. The agent body must reference skill files via a SKILL_REFS
    section with a declared load condition per entry. An instruction file that
    embeds skill file body content fails verification.
  checked_by: agent-specification-verifier; agent-specification-reviewer

R04:
  rule: >
    Every SKILL_REFS entry in an agent instruction file must declare three
    fields: path (relative path to the SKILL.md file), condition (the task
    criterion that triggers loading), and pinned_version (the semver version
    of the skill file at instruction file authoring time). A SKILL_REFS entry
    missing any of these three fields is incomplete and fails specification
    review.
  test: >
    For every SKILL_REFS entry in any agent instruction file: path is a
    non-empty relative file path AND condition is a non-empty string
    describing a specific task state AND pinned_version is a valid semver
    string. Any SKILL_REFS entry missing path, condition, or pinned_version
    fails specification review and verification.
  checked_by: agent-specification-reviewer; agent-specification-verifier

### Content_Rules

R05:
  rule: >
    Skill files must not duplicate content that already exists in an approved
    DLMS corpus document. Where an agent requires access to corpus-governed
    content (policies, standards, templates, procedures), the agent instruction
    file must load that content via the context delivery layer or reference its
    doc_id — not reproduce it in a skill file. Skill files are for task-specific
    operational content (rubrics, lenses, checklists) that is not already
    governed by the corpus.
  test: >
    No SKILL.md file contains sections that reproduce the RULES, DEFINITIONS,
    or SCOPE content of any DLMS corpus document verbatim or in paraphrase.
    A skill file that duplicates corpus content fails review and must be
    refactored to reference the source corpus doc_id instead.
  checked_by: agent-specification-reviewer; CI agent-behaviour-monitor

R06:
  rule: >
    SKILL.md file body content must be structured using named headings and
    bullet lists or tables. Prose-only skill files are prohibited. Every
    section must be addressable by its heading name so that future material
    change assessment can be performed mechanically. A SKILL.md file whose
    content is entirely unstructured prose fails review.
  test: >
    Every SKILL.md file contains at least two top-level headings (## level).
    No SKILL.md file contains a section of more than 150 words without at
    least one sub-heading, bullet list, or table. A file failing either
    condition fails review.
  checked_by: agent-specification-reviewer

### Storage_and_Ownership

R07:
  rule: >
    SKILL.md files are stored in the same directory as the agent instruction
    file that references them. A skill file referenced by an instruction file
    in .github/agents/tier-15b/ must be located in .github/agents/tier-15b/.
    Skill files must not be stored in a shared global location accessible to
    agents that do not reference them; that would constitute over-permissioning
    of read access contrary to P9.
  test: >
    For every SKILL_REFS entry in any agent instruction file: the path field
    resolves to a location within the same directory as the instruction file.
    Any path that resolves outside the instruction file's directory fails
    structural review.
  checked_by: agent-specification-reviewer; agent-specification-verifier

R08:
  rule: >
    A SKILL.md file may only be updated by the agent-instruction-author acting
    on behalf of the tier that owns the referencing agent, or by Tier 15B in
    the course of a formal agent creation or update workflow. Ad-hoc edits
    to skill files outside a Tier 15B workflow are prohibited. Every skill file
    update must be traceable to either a Tier 15B workflow artefact or a
    SysAdmin directive.
  test: >
    For every skill file version increment: an agentcreation.writeInstruction
    audit event or a sysadmin.writeGovernanceDoc audit event exists with a
    timestamp that precedes the skill file commit and references the same
    role_id or instruction_path. A skill file version increment without a
    corresponding audit event is a traceability violation.
  checked_by: Audit Trail Agent; CI agent-behaviour-monitor

## EXCEPTIONS_PROCESS
Exceptions to rules in this policy require SysAdmin approval using the same
process defined in DLMS-2026-0108 EXCEPTIONS_PROCESS. R02 (re-verification
after material change) and R03 (no startup loading) are foundational to P7
and P9 and are not subject to exception. No exception may waive the
requirement that skill file bodies not be loaded at agent startup.

## ENFORCEMENT
  primary_agent:    agent-specification-reviewer; agent-specification-verifier;
                    CI agent-behaviour-monitor; Audit Trail Agent
  gate_positions:
    - Specification review (Stage 3): reviewer checks R03, R04, R05, R06,
      and R07 for every SKILL_REFS entry before the review passes
    - Verification (Stage 5): verifier confirms R01 (version field present),
      R03 (no inline skill content), and R04 (complete SKILL_REFS entries)
      before the verification artefact is submitted
    - CI cycle: agent-behaviour-monitor checks all deployed instruction files
      for skill file version drift (pinned_version != current skill file
      version after a material change)
  audit: >
    Skill file updates emitting agentcreation.writeInstruction events include
    the skill file path and version in the audit payload. Material change
    re-verifications are recorded with the old and new pinned_version values.
    R08 traceability violations are flagged in the CI cycle report.
  violation_type:   Tier 15B operational violation
  escalation: >
    R02 violations (agent running against unre-verified material change) are
    immediate SysAdmin escalation. R03 violations (startup loading) and R08
    violations (untraced update) are flagged in the CI cycle report and must
    be resolved before the affected agent class is re-deployed.

## REVIEW_SCHEDULE
  interval_max:     6 months
  trigger_conditions:
    - Agent Context Boundary Policy (DLMS-2026-0016) is amended in a way
      that changes the definition of what may be loaded into agent context
    - Agent Creation and Lifecycle Policy (DLMS-2026-0108) R08 (400-token
      instruction body limit) is amended, altering the threshold at which
      skill file offloading becomes mandatory
    - A systematic pattern of skill file version drift or startup loading
      violations is detected by Tier 13 CI across multiple agent classes
    - The progressive disclosure mechanism for a supported agent platform
      changes in a way that affects how SKILL_REFS entries are resolved
