## SUMMARY
This SLA governs the performance of the DLMS archival stage, defining
measurable latency targets for archival recommendation, archival action
execution, SysAdmin override response (where required), and DoD
verification. It establishes binding performance expectations for the
Archival Stage Orchestrator, including escalation paths for RC-permanent
documents requiring SysAdmin-authorised archival.

## SCOPE
Applies to: all DLMS archival operations for documents eligible for
archival (retention-expired, superseded, or manually-initiated with
SysAdmin approval); the Archival Stage Orchestrator; the DoD Verifier
(archival stage); sysadmin:dlm-sysadmin for escalated archival decisions.

Excludes: creation, review, storage, and distribution stage performance;
document content or metadata quality assessment (DLMS-2026-0043); the
retention evaluation process that determines eligibility (that is a
pre-archival-stage trigger, not part of this stage's measurement scope);
post-archival archive location maintenance.

Boundary conditions:
  M01 clock starts:  archival eligibility trigger audit event — one of:
                     retention-period-elapsed event (DLMS-2026-0039);
                     superseded event (doc gains non-null
                     superseded_by field); or manually-initiated-archival
                     request audit event
  M01 clock stops:   recommended_at in the Archival Recommendation
                     artefact (DLMS-2026-0055)
  M02 clock starts:  recommended_at in the Archival Recommendation
                     artefact
  M02 clock stops:   actioned_at in the Archival Log artefact
                     (DLMS-2026-0056)
  M02 note:          When recommended_action is escalate-to-sysadmin,
                     M02 clock does not stop until actioned_at is
                     recorded (which depends on M03 completing first)
  M03 clock starts:  escalate-to-sysadmin recommendation event
                     (the recommendation artefact created with
                     recommended_action: escalate-to-sysadmin)
  M03 clock stops:   sysadmin_override.approved_at in the Archival
                     Log artefact (DLMS-2026-0056)
  M03 applies:       only when recommended_action is escalate-to-sysadmin
  M04 clock starts:  Archival DoD record submission audit event
  M04 clock stops:   DoD Verifier produces verified Archival DoD record
                     (template DLMS-2026-0029)

## DEFINITIONS

archival eligibility trigger:
  The event that initiates the archival stage for a given doc_id.
  Valid triggers are: retention-period-elapsed audit event from the
  Retention Evaluator; a superseded event recorded when a document
  gains a non-null superseded_by field; or a manually-initiated-archival
  request audit event from an authorised operator. Triggers are defined
  in DLMS-2026-0040 R02.

breach:
  A metric value that equals or exceeds breach_threshold for that metric.
  A breach triggers the breach-level BREACH_RESPONSE and must be logged
  as an sla-breach audit event referencing the affected doc_id.

elapsed time:
  Clock time in hours between two defined events per the SCOPE Boundary
  conditions above. Measured from auditable timestamps in DLMS artefacts
  or audit log events only.

SysAdmin override response:
  The process by which sysadmin:dlm-sysadmin reviews an
  escalate-to-sysadmin archival recommendation and either approves or
  declines the archival action. Tracked in M03; measured by
  sysadmin_override.approved_at in the Archival Log artefact.

warning:
  A metric value exceeding warning_threshold but below breach_threshold.
  Logged and stage orchestrator notified; stage advancement not blocked.

## METRICS

M01:
  name:                 Archival recommendation latency
  description:          Elapsed time from an archival eligibility trigger
                        event to the Archival Stage Orchestrator producing
                        an Archival Recommendation artefact. Measures the
                        speed of the pre-archival assessment.
  unit:                 hours
  target:               <= 24h
  warning_threshold:    > 18h
  breach_threshold:     > 48h
  measurement_source:   archival eligibility trigger audit event;
                        recommended_at in Archival Recommendation
                        artefact (DLMS-2026-0055)
  measurement_frequency: per-archival-event

M02:
  name:                 Archival action execution latency
  description:          Elapsed time from the Archival Recommendation
                        artefact being produced to the archival action
                        being executed and recorded in the Archival Log
                        artefact. For escalated recommendations, this
                        clock includes the M03 SysAdmin override window.
  unit:                 hours
  target:               <= 24h
  warning_threshold:    > 18h
  breach_threshold:     > 48h
  measurement_source:   recommended_at in Archival Recommendation
                        artefact (DLMS-2026-0055); actioned_at in
                        Archival Log artefact (DLMS-2026-0056)
  measurement_frequency: per-archival-event
  constraints:
    - When recommended_action is escalate-to-sysadmin, a separate
      M03 warning and breach response applies first; the M02 breach
      clock runs concurrently with M03. M02 breach threshold is
      effectively overridden by M03 for escalated events when
      M03 target (72h) dominates M02 breach threshold (48h).

M03:
  name:                 SysAdmin override response latency (conditional)
  description:          Elapsed time from an escalate-to-sysadmin
                        archival recommendation to sysadmin:dlm-sysadmin
                        recording approval in the Archival Log artefact.
                        Applies only when recommended_action is
                        escalate-to-sysadmin (RC-permanent documents
                        with manually-initiated archival trigger, per
                        DLMS-2026-0040 R04 and DLMS-2026-0055 V06).
  unit:                 hours
  target:               <= 72h
  warning_threshold:    > 48h
  breach_threshold:     > 120h
  measurement_source:   escalate-to-sysadmin recommendation audit event;
                        sysadmin_override.approved_at in Archival Log
                        artefact (DLMS-2026-0056)
  measurement_frequency: per-escalated-archival-event (conditional)

M04:
  name:                 Archival DoD verification latency
  description:          Elapsed time from Archival DoD record submission
                        to the DoD Verifier producing a verified Archival
                        DoD record. Measures the DoD verification gate
                        speed for the archival stage. Formalises the 24h
                        provisional DoD threshold in DLMS-2026-0043 R09.
  unit:                 hours
  target:               <= 24h
  warning_threshold:    > 18h
  breach_threshold:     > 48h
  measurement_source:   Archival DoD record submission audit event;
                        DoD Verifier verified-dod-produced audit event
                        (template DLMS-2026-0029)
  measurement_frequency: per-document

## MEASUREMENT_METHOD

collection_agent:    Archival Stage Metrics Collector — collects raw
                     timestamps from Archival Recommendation artefacts,
                     Archival Log artefacts, DoD records, and associated
                     audit events per doc_id.

aggregation_agent:   Metrics Aggregator — receives raw per-event
                     measurements from Archival Stage Metrics Collector
                     and produces aggregated metric values (median,
                     95th percentile, breach rate) per CI cycle.
                     Must differ from collection_agent per Verification
                     Independence Policy (DLMS-2026-0014). M03 is
                     aggregated separately over escalated events only.

reporting_artefact:  TMPL-performance-report-001 (Wave 12, planned —
                     see NOTES). Until Wave 12 is complete, performance
                     data is reported through interim ad hoc report
                     artefacts maintained by the Metrics Aggregator.

reporting_frequency: per CI cycle

baseline_ref:        Provisional design-intent baseline established at
                     system activation; target values in this SLA are
                     the baseline. Archival events may be infrequent
                     in early operation; the Metrics Aggregator must
                     note low sample counts when reporting M01–M04.

## BREACH_RESPONSE

warning:
  trigger:               Any archival stage metric value exceeds its
                         warning_threshold for a given archival event
                         or doc_id.
  notification_targets:  [Archival Stage Metrics Collector,
                          Archival Stage Orchestrator]
  response_actions:
    - Archival Stage Metrics Collector logs a time-warning audit event
      with metric_id, elapsed_time, threshold_value, and doc_id.
    - Archival Stage Orchestrator reviews the in-flight archival event
      for risk of breach escalation.
    - For M03 warnings: Archival Stage Orchestrator also notifies
      sysadmin:dlm-sysadmin of the pending escalation review.
  resolution_sla:        24h

breach:
  trigger:               Any archival stage metric value equals or
                         exceeds its breach_threshold for a given
                         archival event or doc_id.
  notification_targets:  [Archival Stage Metrics Collector,
                          Archival Stage Orchestrator,
                          agent:sla-manager]
  response_actions:
    - Archival Stage Metrics Collector logs an sla-breach audit event
      with metric_id, elapsed_time, breach_threshold, and doc_id.
    - Archival Stage Orchestrator logs a stage-escalation event.
    - For M03 breaches: agent:sla-manager immediately notifies
      sysadmin:dlm-sysadmin regardless of resolution_sla.
    - agent:sla-manager acknowledges breach and initiates review per
      SLA Breach Response Policy (Wave 13, planned).
  resolution_sla:        8h

critical:
  trigger:               Any M02 breach on an RC-permanent document
                         (where archival requires SysAdmin approval);
                         or M03 breach_threshold (> 120h) exceeded on
                         any escalated archival event.
  notification_targets:  [agent:sla-manager,
                          sysadmin:dlm-sysadmin]
  response_actions:
    - agent:sla-manager produces a performance anomaly report with
      root cause analysis for the affected event and doc_id.
    - sysadmin:dlm-sysadmin is required to respond within the
      resolution_sla window with either an approval decision on the
      pending archival or a formal deferral directive with
      justification.
  resolution_sla:        2h

## REVIEW_SCHEDULE
  interval_max:      3 months
  trigger_conditions:
    - Any M03 breach (SysAdmin override > 120h) is itself a mandatory
      review trigger; it indicates the escalation pathway requires
      process adjustment.
    - DLMS-2026-0040 (Document Archival Policy) is amended in a way
      that changes archival triggers, eligibility criteria, or the
      actions available to the Archival Stage Orchestrator.
    - DLMS-2026-0039 (Document Retention Policy) is amended in a way
      that changes retention class definitions or retention periods,
      affecting the volume or timing of archival eligibility events.
    - Archival stage artefact templates DLMS-2026-0055 or DLMS-2026-0056
      are amended in ways that affect timestamp fields used as
      measurement sources.

## NOTES
reporting_artefact forward reference: TMPL-performance-report-001 is
planned for Wave 12 and does not yet exist in the corpus. Until Wave 12
is complete, performance reporting is conducted through interim ad hoc
report artefacts. This SLA must be reviewed after Wave 12 is drafted to
update the reporting_artefact reference in MEASUREMENT_METHOD.

M02/M03 interaction: When recommended_action is escalate-to-sysadmin,
both M02 and M03 run concurrently. The practical binding constraint is
M03 (72h SysAdmin response), since M02 breach threshold (48h) will
almost certainly be breached before M03 breach threshold (120h) is
reached. The separate M03 breach response, which directly routes to
sysadmin:dlm-sysadmin, serves as the operational escalation mechanism
in these cases. This design is intentional — M02 breach on an escalated
event signals normal latency, not a system failure.

Low sample volume: Archival events may occur infrequently in early
operation. The Metrics Aggregator must flag CI cycle reports during the
first 6 months if fewer than 5 archival events have occurred, as
statistical baselines will not be reliable at that sample size.
