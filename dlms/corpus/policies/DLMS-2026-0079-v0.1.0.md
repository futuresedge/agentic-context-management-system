## SUMMARY
This policy governs how change directives produced during the CI cycle
are validated, authorised, and executed as corpus changes. It defines
the mandatory steps between a change directive (CD-) being issued and
document changes taking effect, establishes verification requirements
before and after application, and specifies what constitutes an
unauthorised change.

## SCOPE

Applies to:
- All change directives (CD-) produced by agent:ci-synthesis-orchestrator
  using TMPL-change-directive-001 (DLMS-2026-0074)
- Changes to any document in the DLMS corpus derived from CD-
  recommendations (IMP-) using TMPL-recommendations-001 (DLMS-2026-0072)
- SysAdmin briefings (SAB-) using TMPL-sysadmin-briefing-001
  (DLMS-2026-0073) that accompany or inform CD- execution
- Agent:dlm-sysadmin-agent in its change execution role
- sysadmin:dlm-sysadmin in all authorisation and oversight roles
- Any CI cycle change window as defined by CI Cycle Policy
  (DLMS-2026-0076)

Excludes:
- Changes to documents governed by Status Transition Policy
  (DLMS-2026-0037) when status transition is the only modification
  (those are governed solely by DLMS-2026-0037)
- Hotfix changes initiated outside the CI cycle at sysadmin:dlm-sysadmin
  discretion (those are out-of-band and must be logged via a standalone
  audit entry with doc_id, change description, and rationale)
- Changes to agent instruction files in `.github/agents/` (governed by
  separate agent instruction governance, not this policy)

## DEFINITIONS

change directive (CD-):
  The CI synthesis artefact produced at the end of the synthesis chain
  using TMPL-change-directive-001 (DLMS-2026-0074). A CD- may contain
  zero or more recommended changes. A CD- with zero changes is a
  no-change directive and is valid; it closes the cycle with no
  modifications required.

recommendations artefact (IMP-):
  The artefact produced by agent:improvement-synthesizer using
  TMPL-recommendations-001 (DLMS-2026-0072), which informs the CD-.
  A CD- must be traceable to an IMP- from the same CI cycle.

SysAdmin briefing (SAB-):
  The artefact produced by agent:sysadmin-briefer using
  TMPL-sysadmin-briefing-001 (DLMS-2026-0073), dispatched concurrently
  with the CD- for all cycles where `escalation_carried_forward == true`
  or `time_sensitivity: immediate`.

change window:
  The period during a CI cycle designated for corpus changes to be
  applied. The change window opens when sysadmin:dlm-sysadmin
  authorises the CD- and closes when all changes are implemented and
  verified. No new cycle may begin until the change window is closed.

unauthorised change:
  Any modification to a corpus document that does not trace to a
  current-cycle authorised CD- or a logged out-of-band hotfix. An
  unauthorised change is a critical finding and triggers escalation
  to sysadmin:dlm-sysadmin under SysAdmin Escalation Policy
  (DLMS-2026-0080).

## RULES

### CD- Validation Before Execution

R01:
  rule: >
    Before agent:dlm-sysadmin-agent begins applying any change from a
    CD-, the CD- must pass the following validation checks: (a) CD- was
    produced by agent:ci-synthesis-orchestrator in the current CI cycle;
    (b) CD- references a valid IMP- from the same cycle; (c) no
    unacknowledged escalation is open for the current cycle under
    SysAdmin Escalation Policy (DLMS-2026-0080); (d) impact assessment
    was completed for any IMP- recommended change with active dependencies,
    per Impact Assessment Policy (DLMS-2026-0077). Failure of any check
    blocks change window from opening.
  test: >
    CD-.cycle_id == current_cycle AND
    CD-.imp_ref non-null AND CD-.imp_ref matches IMP-.artefact_id
      from same cycle AND
    no unacknowledged escalation open (from DLMS-2026-0080) AND
    FOR each change with active_deps == true:
      impact_assessment_ref non-null in CD- or IMP-
  checked_by: agent:dlm-sysadmin-agent; agent:ci-cycle-orchestrator

### SysAdmin Authorisation

R02:
  rule: >
    A CD- containing one or more recommended changes may not be applied
    until sysadmin:dlm-sysadmin issues explicit authorisation. For a
    no-change CD-, sysadmin:dlm-sysadmin must still acknowledge receipt.
    Authorisation or acknowledgement must be recorded as an audit event
    citing the CD- artefact_id. Authorisation must occur before the
    change window opens.
  test: >
    IF CD-.change_count >= 1:
      sysadmin_authorisation.recorded_at non-null AND
      sysadmin_authorisation.cd_ref == CD-.artefact_id AND
      authorisation.recorded_at < change_window.opened_at
    IF CD-.change_count == 0:
      sysadmin_acknowledgement.recorded_at non-null AND
      sysadmin_acknowledgement.cd_ref == CD-.artefact_id
  checked_by: Audit Trail Agent; agent:ci-cycle-orchestrator

### Change Application

R03:
  rule: >
    Each change in the CD- must be applied by agent:dlm-sysadmin-agent
    as a discrete, traceable action. For every change applied, an audit
    entry must be written citing: (a) the CD- artefact_id; (b) the
    specific change item reference within the CD-; (c) the target
    document doc_id; (d) the type of change (content / metadata /
    status-transition / new-document); (e) the agent that applied the
    change; and (f) the timestamp of application. Changes are applied
    sequentially in the order listed in the CD- unless the CD- explicitly
    marks items as parallel-safe.
  test: >
    FOR each change in CD-.changes:
      audit_entry.cd_ref == CD-.artefact_id AND
      audit_entry.change_item_ref non-null AND
      audit_entry.target_doc_id non-null AND
      audit_entry.change_type IN [content, metadata, status-transition, new-document] AND
      audit_entry.applied_by non-null AND
      audit_entry.timestamp non-null
  checked_by: Audit Trail Agent

R04:
  rule: >
    No change may be applied to a document that is not listed in the
    current cycle's CD-. Any modification outside an authorised CD— is
    an unauthorised change and must be flagged immediately to
    sysadmin:dlm-sysadmin per SysAdmin Escalation Policy
    (DLMS-2026-0080).
  test: >
    FOR each modification applied during change_window:
      modification.target_doc_id IN CD-.changes AND
      modification.cd_ref == current_cycle_CD-.artefact_id
  checked_by: Audit Trail Agent; agent:ci-cycle-orchestrator

### Post-Change Verification

R05:
  rule: >
    After all changes in the CD- are applied, a verification pass must
    be run by a verification agent that did not apply the changes. The
    verification must confirm: (a) each required change in the CD- was
    applied; (b) no document outside the CD- was modified; (c) all
    modified documents pass format validation for their doc_type. Results
    are recorded as a verification audit event closing the change window.
  test: >
    verifier.agent_id != applicator.agent_id AND
    verification_audit.all_cd_changes_applied == true AND
    verification_audit.no_off_cd_modifications == true AND
    verification_audit.format_validation_passed == true FOR all modified docs AND
    change_window.closed_at == verification_audit.timestamp
  checked_by: Verification agent (not agent:dlm-sysadmin-agent)

R06:
  rule: >
    If post-change verification fails (any of the three conditions in R05
    not satisfied), the change window is not closed. The failure is
    escalated to sysadmin:dlm-sysadmin within 1 hour; a corrective action
    must be authorised by sysadmin:dlm-sysadmin before the window can be
    closed or re-opened.
  test: >
    IF verification fails:
      escalation_to_sysadmin.dispatched_at - failure_detected_at <= 1h AND
      no change_window.closed_at set until corrective_action_authorised
  checked_by: agent:ci-cycle-orchestrator; Audit Trail Agent

### Separation of Roles

R07:
  rule: >
    The agent that produces a CD- (agent:ci-synthesis-orchestrator) must
    not be the same agent that applies changes from that CD-
    (agent:dlm-sysadmin-agent). The agent that applies changes must not
    be the same agent that verifies them (R05). This rule cannot be
    excepted (Tier 2 per DLMS-2026-0014).
  test: >
    CD-.produced_by != change_application.applied_by AND
    change_application.applied_by != verification.verified_by
  checked_by: Audit Trail Agent

## EXCEPTIONS_PROCESS

Exceptions require Tier 3 exception approval from sysadmin:dlm-sysadmin:
1. Exception request must cite the specific rule, the CD- artefact_id, and
   a documented rationale.
2. Exception must be recorded as an audit event before the affected change
   window opens.
3. Exceptions apply only to the specific CD- cited and do not create
   standing waivers.

The following cannot be excepted:
- R07 (separation of roles — Tier 2 per DLMS-2026-0014)
- R04 (no change outside authorised CD-)

## ENFORCEMENT

primary_agent:    agent:dlm-sysadmin-agent
secondary_agent:  agent:ci-cycle-orchestrator; Verification agents
gate_positions:
  - CD- validation before change window opens (R01)
  - sysadmin:dlm-sysadmin authorisation before change application (R02)
  - Post-change verification before change window closes (R05)
violation_type:   Unauthorised change — immediate escalation to
                  sysadmin:dlm-sysadmin; cycle halted.
                  Validation failure — change window blocked;
                  cycle declared incomplete until resolved.
escalation_ref:   SysAdmin Escalation Policy (DLMS-2026-0080, Wave 13)

## REVIEW_SCHEDULE

interval_max:     6 months

  - Any change application failure (R06) occurs in two consecutive CI
    cycles
  - TMPL-change-directive-001 (DLMS-2026-0074) is revised in a way
    that alters the change item structure
  - Any finding of an unauthorised change (R04) in a production cycle
