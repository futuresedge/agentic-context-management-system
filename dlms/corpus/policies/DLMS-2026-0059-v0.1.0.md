## SUMMARY
This SLA governs the performance of the DLMS storage stage, defining
measurable latency targets for version storage, access manifest issuance
for classified documents, and DoD verification. The storage stage covers
operations from approved status transition through confirmed document
storage and access control setup.

## SCOPE
Applies to: all DLMS document storage operations following an approved
status transition or approval decision; the Storage Agent; the Version
Control Agent; the Access Gatekeeper (manifest issuance operations);
the DoD Verifier (storage stage); the Storage Stage Orchestrator.

Excludes: creation stage and review stage performance; the Distribution
and Archival stages; document content or metadata quality assessment
(DLMS-2026-0043); access control enforcement operations at read/write
time (governed by DLMS-2026-0044 operationally, not by this SLA).

Boundary conditions:
  M01 clock starts:  status-transition-approved audit event for the
                     doc_id and doc_version being stored
  M01 clock stops:   entries[N].stored_at in the Version Log artefact
                     (DLMS-2026-0051), where N is the entry for the
                     version being stored
  M02 clock starts:  classification audit event where confidentiality_class
                     is set to C2 or C3 for a given doc_id
  M02 clock stops:   issued_at in the Access Manifest artefact
                     (DLMS-2026-0052) for that doc_id
  M02 applies:       only to documents with confidentiality_class C2 or C3
  M03 clock starts:  Storage DoD record submission audit event
  M03 clock stops:   DoD Verifier produces verified Storage DoD record
                     (template DLMS-2026-0027)

## DEFINITIONS

breach:
  A metric value that equals or exceeds breach_threshold for that metric.
  A breach triggers the breach-level BREACH_RESPONSE and must be logged
  as an sla-breach audit event referencing the affected doc_id.

classification event:
  The audit event generated when the confidentiality_class field of a
  document is assigned a value by the Classification Agent. For M02,
  the relevant classification event is the first event that sets
  confidentiality_class to C2 or C3 for a given doc_id.

elapsed time:
  Clock time in hours between two defined events per the SCOPE Boundary
  conditions above. Measured from auditable timestamps in DLMS artefacts
  or audit log events only.

status-transition-approved:
  The audit event generated by the Status Transition Agent confirming
  that a document's status transition is approved and the document is
  authorised to proceed to storage. This event initiates M01.

warning:
  A metric value exceeding warning_threshold but below breach_threshold.
  Logged and stage orchestrator notified; stage advancement not blocked.

## METRICS

M01:
  name:                 Version storage latency
  description:          Elapsed time from the status-transition-approved
                        audit event to the document version being recorded
                        in the Version Log artefact. Measures the Storage
                        Agent's speed in committing an approved version
                        to the corpus.
  unit:                 hours
  target:               <= 1h
  warning_threshold:    > 30 minutes
  breach_threshold:     > 4h
  measurement_source:   status-transition-approved audit event;
                        entries[N].stored_at in Version Log artefact
                        (DLMS-2026-0051)
  measurement_frequency: per-document per-version

M02:
  name:                 Access manifest issuance latency (conditional)
  description:          Elapsed time from a document being classified
                        as C2 or C3 to the production of its Access
                        Manifest artefact. Ensures that restricted and
                        confidential documents are access-controlled
                        before entering the review stage, as required
                        by DLMS-2026-0044 R07. Applies only to documents
                        with confidentiality_class C2 or C3.
  unit:                 hours
  target:               <= 4h
  warning_threshold:    > 2h
  breach_threshold:     > 8h
  measurement_source:   classification audit event (C2 or C3 assigned);
                        issued_at in Access Manifest artefact
                        (DLMS-2026-0052)
  measurement_frequency: per-document (conditional: C2 and C3 only)

M03:
  name:                 Storage DoD verification latency
  description:          Elapsed time from Storage DoD record submission
                        to the DoD Verifier producing a verified Storage
                        DoD record. Measures the DoD verification gate
                        speed for the storage stage. Formalises the 24h
                        provisional DoD threshold in DLMS-2026-0043 R09.
  unit:                 hours
  target:               <= 24h
  warning_threshold:    > 18h
  breach_threshold:     > 48h
  measurement_source:   Storage DoD record submission audit event;
                        DoD Verifier verified-dod-produced audit event
                        (template DLMS-2026-0027)
  measurement_frequency: per-document

## MEASUREMENT_METHOD

collection_agent:    Storage Stage Metrics Collector — collects raw
                     timestamps from Version Log artefacts, Access
                     Manifest artefacts, Storage DoD records, and
                     associated audit events per doc_id.

aggregation_agent:   Metrics Aggregator — receives raw per-document
                     measurements from Storage Stage Metrics Collector
                     and produces aggregated metric values (median,
                     95th percentile, breach rate) per CI cycle.
                     Must differ from collection_agent per Verification
                     Independence Policy (DLMS-2026-0014).

reporting_artefact:  TMPL-performance-report-001 (Wave 12, planned —
                     see NOTES). Until Wave 12 is complete, performance
                     data is reported through interim ad hoc report
                     artefacts maintained by the Metrics Aggregator.

reporting_frequency: per CI cycle

baseline_ref:        Provisional design-intent baseline established at
                     system activation; target values in this SLA are
                     the baseline. After 90 days of live operation the
                     Metrics Aggregator establishes an operational
                     baseline for the Anomaly Detector. M02 baseline
                     is computed only over C2 and C3 documents.

## BREACH_RESPONSE

warning:
  trigger:               Any storage stage metric value exceeds its
                         warning_threshold for a given doc_id.
  notification_targets:  [Storage Stage Metrics Collector,
                          Storage Stage Orchestrator]
  response_actions:
    - Storage Stage Metrics Collector logs a time-warning audit event
      with metric_id, elapsed_time, threshold_value, and doc_id.
    - Storage Stage Orchestrator reviews in-flight storage operations
      for risk of escalation to breach.
  resolution_sla:        24h

breach:
  trigger:               Any storage stage metric value equals or
                         exceeds its breach_threshold for a given doc_id.
  notification_targets:  [Storage Stage Metrics Collector,
                          Storage Stage Orchestrator,
                          agent:sla-manager]
  response_actions:
    - Storage Stage Metrics Collector logs an sla-breach audit event
      with metric_id, elapsed_time, breach_threshold, and doc_id.
    - Storage Stage Orchestrator escalates the affected storage task.
    - For M02 breaches: Storage Stage Orchestrator also notifies the
      Access Gatekeeper and logs an access-manifest-delayed event;
      the document must not advance to review stage until M02
      breach is resolved.
    - agent:sla-manager acknowledges breach and initiates review per
      SLA Breach Response Policy (Wave 13, planned).
  resolution_sla:        8h

critical:
  trigger:               M01 breach_threshold (> 4h) exceeded on five
                         or more documents in the same CI cycle; or
                         any M02 breach that causes a C2 or C3 document
                         to enter the review stage without a valid
                         Access Manifest artefact.
  notification_targets:  [agent:sla-manager,
                          sysadmin:dlm-sysadmin]
  response_actions:
    - agent:sla-manager produces a performance anomaly report with
      root cause analysis for the affected metric(s) and doc_ids.
    - For M02 critical breaches: sysadmin:dlm-sysadmin must issue an
      access-control directive and block the affected document from
      any further stage progression until the manifest is issued.
    - sysadmin:dlm-sysadmin reviews and issues a corrective directive
      within the resolution_sla window.
  resolution_sla:        2h

## REVIEW_SCHEDULE
  interval_max:      3 months
  trigger_conditions:
    - Sustained M02 sla-breach events across two consecutive CI cycles
      indicate systemic classification-to-manifest latency issues
      requiring SLA review — mandatory trigger.
    - DLMS-2026-0038 (Document Versioning Policy) is amended in a way
      that changes version storage procedures or Version Log fields.
    - DLMS-2026-0044 (Access Control Policy) is amended in a way that
      changes when access manifests must be present relative to stage
      progression.
    - Storage stage artefact templates DLMS-2026-0051 or DLMS-2026-0052
      are amended in ways that affect timestamp fields used as
      measurement sources.

## NOTES
reporting_artefact forward reference: TMPL-performance-report-001 is
planned for Wave 12 and does not yet exist in the corpus. Until Wave 12
is complete, performance reporting is conducted through interim ad hoc
report artefacts. This SLA must be reviewed after Wave 12 is drafted to
update the reporting_artefact reference in MEASUREMENT_METHOD.

M02 conditional measurement: M02 applies exclusively to documents
classified as C2 or C3. The Storage Stage Metrics Collector must filter
the full document corpus to C2 and C3 documents when computing M02.
C0 and C1 documents are excluded from M02 entirely; their absence from
M02 statistics is not a data gap.
