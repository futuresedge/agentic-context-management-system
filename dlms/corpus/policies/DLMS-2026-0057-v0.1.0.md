## SUMMARY
This SLA governs the performance of the DLMS creation stage, defining
measurable latency targets for context curation, problem analysis,
end-to-end document creation cycle time, and DoD verification. It
formalises the provisional creation stage time thresholds carried as
advisory-only values in Quality Threshold Policy (DLMS-2026-0043 R09)
and establishes a binding breach response process for creation stage
performance failures.

## SCOPE
Applies to: all new DLMS document creation cycles — from doc_id reservation
through first successful document storage; the Context Curator agent; the
Problem Analysis Agent; the Document Author Agent; the DoD Verifier
(creation stage); the Creation Stage Orchestrator.

Excludes: revision cycles for existing documents (version increments are
Storage stage events); document content quality assessment (governed by
DLMS-2026-0043); the review, storage, distribution, and archival stages;
CI cycle performance; human reviewer turnaround outside the creation stage.

Boundary conditions:
  M01 clock starts:  creation task assignment audit event for the doc_id
  M01 clock stops:   curated_at in the Creation Context artefact
                     (DLMS-2026-0046)
  M02 clock starts:  curated_at in the Creation Context artefact
  M02 clock stops:   analysed_at in the Problem Analysis artefact
                     (DLMS-2026-0047)
  M03 clock starts:  doc_id reservation audit event
  M03 clock stops:   entries[0].stored_at in the Version Log artefact
                     (DLMS-2026-0051)
  M04 clock starts:  Creation DoD record submission audit event
  M04 clock stops:   DoD Verifier produces verified Creation DoD record
                     (template DLMS-2026-0024)

## DEFINITIONS

breach:
  A metric value that equals or exceeds breach_threshold for that metric.
  A breach triggers the breach-level BREACH_RESPONSE and must be logged
  as an sla-breach audit event referencing the affected doc_id.

creation task assignment:
  The audit event generated when the Creation Stage Orchestrator assigns
  a document creation request to the Context Curator, marking the
  operational start of the creation stage for a given doc_id.

doc_id reservation:
  The audit event generated when a unique doc_id is reserved for a new
  document entering the creation stage. This is the earliest measurable
  start point for the end-to-end creation cycle (M03).

elapsed time:
  Clock time in hours between two defined events per the SCOPE Boundary
  conditions above. Measured from auditable timestamps in DLMS artefacts
  or audit log events only; estimated values are not permitted.

warning:
  A metric value that exceeds warning_threshold but is below
  breach_threshold. Logged and stage orchestrator notified;
  stage advancement is not blocked.

## METRICS

M01:
  name:                 Context curation latency
  description:          Elapsed time from creation task assignment to
                        production of the Creation Context artefact.
                        Measures the Context Curator's speed in assembling
                        a creation context package for a given doc_id.
  unit:                 hours
  target:               <= 4h
  warning_threshold:    > 3h
  breach_threshold:     > 8h
  measurement_source:   Creation task assignment audit event; curated_at
                        field in Creation Context artefact (DLMS-2026-0046)
  measurement_frequency: per-document

M02:
  name:                 Problem analysis latency
  description:          Elapsed time from Creation Context artefact
                        completion to completion of the Problem Analysis
                        artefact for the same doc_id. Measures the Problem
                        Analysis Agent's processing speed given a curated
                        context package.
  unit:                 hours
  target:               <= 4h
  warning_threshold:    > 3h
  breach_threshold:     > 8h
  measurement_source:   curated_at in Creation Context artefact
                        (DLMS-2026-0046); analysed_at in Problem Analysis
                        artefact (DLMS-2026-0047)
  measurement_frequency: per-document

M03:
  name:                 End-to-end creation cycle
  description:          Elapsed time from doc_id reservation to first
                        successful document storage in the Version Log.
                        Primary creation stage cycle time metric. Formalises
                        the 72h provisional creation threshold in
                        DLMS-2026-0043 R09.
  unit:                 hours
  target:               <= 72h
  warning_threshold:    > 60h
  breach_threshold:     > 96h
  measurement_source:   doc_id reservation audit event; entries[0].stored_at
                        in Version Log artefact (DLMS-2026-0051)
  measurement_frequency: per-document

M04:
  name:                 Creation DoD verification latency
  description:          Elapsed time from Creation DoD record submission to
                        the DoD Verifier producing a verified Creation DoD
                        record. Measures the DoD verification gate speed for
                        the creation stage. Formalises the 24h provisional
                        DoD threshold in DLMS-2026-0043 R09.
  unit:                 hours
  target:               <= 24h
  warning_threshold:    > 18h
  breach_threshold:     > 48h
  measurement_source:   Creation DoD record submission audit event;
                        DoD Verifier verified-dod-produced audit event
                        (template DLMS-2026-0024)
  measurement_frequency: per-document

## MEASUREMENT_METHOD

collection_agent:    Creation Stage Metrics Collector — collects raw
                     timestamps from Creation Context artefacts, Problem
                     Analysis artefacts, Version Log artefacts, DoD
                     records, and associated audit events per doc_id.

aggregation_agent:   Metrics Aggregator — receives raw per-document
                     measurements from Creation Stage Metrics Collector
                     and produces aggregated metric values (median,
                     95th percentile, breach rate) per CI cycle.
                     Must differ from collection_agent per Verification
                     Independence Policy (DLMS-2026-0014).

reporting_artefact:  TMPL-performance-report-001 (Wave 12, planned —
                     see NOTES). Until Wave 12 is complete, performance
                     data is reported through interim ad hoc report
                     artefacts maintained by the Metrics Aggregator.

reporting_frequency: per CI cycle

baseline_ref:        Provisional design-intent baseline established at
                     system activation; target values in this SLA are
                     the baseline. After 90 days of live operation the
                     Metrics Aggregator establishes an operational
                     baseline against which the Anomaly Detector compares
                     live metrics.

## BREACH_RESPONSE

warning:
  trigger:               Any creation stage metric value exceeds its
                         warning_threshold for a given doc_id.
  notification_targets:  [Creation Stage Metrics Collector,
                          Creation Stage Orchestrator]
  response_actions:
    - Creation Stage Metrics Collector logs a time-warning audit event
      with metric_id, elapsed_time, threshold_value, and doc_id.
    - Creation Stage Orchestrator reviews in-flight creation tasks for
      risk of escalation to breach.
  resolution_sla:        24h

breach:
  trigger:               Any creation stage metric value equals or
                         exceeds its breach_threshold for a given doc_id.
  notification_targets:  [Creation Stage Metrics Collector,
                          Creation Stage Orchestrator,
                          agent:sla-manager]
  response_actions:
    - Creation Stage Metrics Collector logs an sla-breach audit event
      with metric_id, elapsed_time, breach_threshold, and doc_id.
    - Creation Stage Orchestrator escalates the affected task and logs
      a stage-escalation audit event.
    - agent:sla-manager acknowledges breach and initiates review per
      SLA Breach Response Policy (Wave 13, planned).
  resolution_sla:        8h

critical:
  trigger:               M03 breach_threshold (> 96h) exceeded on three
                         or more documents in the same CI cycle; or any
                         single metric in breach state across two
                         consecutive CI cycles without resolution.
  notification_targets:  [agent:sla-manager,
                          sysadmin:dlm-sysadmin]
  response_actions:
    - agent:sla-manager produces a performance anomaly report with
      root cause analysis for the affected metric(s) and doc_ids.
    - sysadmin:dlm-sysadmin reviews the anomaly report and issues a
      corrective directive within the resolution_sla window.
  resolution_sla:        2h

## REVIEW_SCHEDULE
  interval_max:      3 months
  trigger_conditions:
    - A sustained pattern of M03 or M04 sla-breach events across two
      consecutive CI cycles indicates target values require
      recalibration — this is a mandatory SLA review trigger.
    - DLMS-2026-0035 (Document Creation Policy) is amended in a way
      that changes stage scope, agent assignment, or measurement
      event definitions.
    - DLMS-2026-0043 (Quality Threshold Policy) is amended with changes
      to creation stage time thresholds.
    - Creation stage artefact templates DLMS-2026-0046 or DLMS-2026-0047
      are amended in ways that affect timestamp fields used as
      measurement sources.
