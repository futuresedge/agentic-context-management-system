## SUMMARY
This policy establishes the normative four-level confidentiality classification
scheme for all DLMS documents, defines the authority and process for
classification assignment and reclassification, and specifies the retention
and downstream access implications of each level. The access control
implications of each classification level are defined in Access Control
Policy (DLMS-2026-0044). This is a Tier 3 Agent Behaviour policy.

## SCOPE
Applies to: all DLMS corpus documents regardless of doc_type; the Document
Author Agent (proposes classification); the Classification Agent (assigns
classification); the Audit Trail Agent; sysadmin:dlm-sysadmin (issues
reclassification directives); all documents from the point of creation.

Excludes: the rules governing what an agent may do with a document once
classified — those are defined in Access Control Policy (DLMS-2026-0045).
Excludes classification of non-corpus artefacts (audit events, system
logs, CI reports), which are not DLMS corpus documents. Excludes the four
Wave 1 bootstrap documents (DLMS-2026-0001 through DLMS-2026-0004), which
are classified C1 (internal) by declaration and are not subject to
Classification Agent assignment.

## DEFINITIONS

C0 (public):
  A document with no distribution restriction. Suitable for external
  distribution without additional controls. C0 must be explicitly assigned
  by the document author and justified in the audit trail. No document
  defaults to C0. C0 may only be assigned to documents whose content
  carries no risk of harm, competitive exposure, or access control conflict
  if publicly available.

C1 (internal):
  The default classification for all DLMS documents. Suitable for access
  by all registered DLMS agents but must not be distributed outside the
  DLMS system without explicit reclassification to C0. All policy,
  standard, taxonomy, template, and specification documents are at
  minimum C1.

C2 (restricted):
  A document whose content is sensitive to the operational integrity,
  security posture, or competitive position of the DLMS or its users.
  Access is restricted to agent classes explicitly listed in the document's
  access manifest on a need-to-know basis. Requires an access manifest at
  creation. Report documents are at minimum C2.

C3 (confidential):
  A document containing content whose unauthorised disclosure would cause
  significant harm — including, but not limited to, strategic decisions,
  security vulnerability data, or personally identifiable information. Access
  is restricted to sysadmin:dlm-sysadmin and agents explicitly named by
  SysAdmin directive. Requires a SysAdmin-signed access manifest at creation.
  C3 documents are RC-permanent regardless of doc_type.

Classification Agent:
  The agent responsible for evaluating the proposed classification from
  the Document Author and confirming or overriding it based on the criteria
  defined in this policy. The Classification Agent must be a distinct agent
  identity from the document author; it cannot confirm a classification it
  proposed.

reclassification:
  A change to a document's confidentiality_class field after the document
  has been created. Reclassification of an approved document requires a
  SysAdmin directive. Reclassification is always a PATCH version increment.

## RULES

### Classification_Scheme

R01:
  rule: >
    The DLMS confidentiality classification scheme consists of exactly four
    levels: C0 (public), C1 (internal), C2 (restricted), and C3
    (confidential). These four levels are the only valid values for the
    confidentiality_class field. No additional levels may be introduced
    without a formal amendment to this policy via a MINOR version increment.
    Level definitions are normative within this policy and in DLMS-2026-0021
    (Taxonomy / Controlled Vocabulary) where they are registered as controlled
    terms.
  test: >
    For all DLMS documents: confidentiality_class is one of [C0, C1, C2, C3].
    Any other value is invalid and triggers a classification-invalid audit
    event.
  checked_by: Classification Agent; Agent Format Validator

### Default_Classification

R02:
  rule: >
    All DLMS documents default to C1 (internal) at creation. If the
    Document Author does not propose a classification, the Classification
    Agent assigns C1. The classification field must be populated before a
    document exits the creation stage.
  test: >
    For each newly created document: confidentiality_class is non-null and
    is one of the four valid values before the creation-complete audit event
    is logged. Null or absent classification at creation-complete triggers
    a creation-blocked event.
  checked_by: Classification Agent; Agent Format Validator

R03:
  rule: >
    C0 (public) may only be assigned if the Document Author explicitly
    proposes C0 in the creation context and the Classification Agent
    confirms the proposal. The confirmation must be accompanied by a
    justification recorded in the classification-assigned audit event:
    a brief rationale explaining why no access restriction is required for
    this document's content. C0 is never assigned by default.
  test: >
    For each document assigned C0: classification-assigned audit event
    exists with non-null justification field. Absence of justification
    on a C0 assignment constitutes a classification-non-conformant condition
    and triggers a SysAdmin alert.
  checked_by: Classification Agent; Audit Trail Agent

### Classification_Authority

R04:
  rule: >
    The Document Author Agent proposes a classification level as part of
    the creation context. The Classification Agent evaluates the proposal
    against the level criteria in this policy and confirms or overrides it.
    If the Classification Agent overrides the proposal, it must record the
    override rationale in the classification-assigned audit event.
  test: >
    For each document: a classification-assigned audit event exists,
    authored by the Classification Agent identity (not the Document Author
    identity), with the confirmed classification level and, where applicable,
    override_rationale populated.
  checked_by: Classification Agent; Audit Trail Agent

R05:
  rule: >
    The Document Author Agent and the Classification Agent must be distinct
    agent identities per Verification Independence Policy (DLMS-2026-0014).
    The Document Author must not confirm its own proposed classification.
    The Classification Agent must not have contributed to authoring the
    document it is classifying.
  test: >
    classification-assigned event: authoring_agent_id ≠ document.created_by
    AND authoring_agent_id not present as a write event actor for this
    doc_id in the creation stage audit trail.
  checked_by: Audit Trail Agent; Approval Gate Agent

### Mandatory_Doc_Type_Overrides

R06:
  rule: >
    Documents of the following doc_types must be classified at minimum C1
    (internal), regardless of the author's proposal: policy, standard,
    template, taxonomy, specification. If an author proposes C0 for a
    document of these types, the Classification Agent must override to C1
    and record the override rationale.
  test: >
    For all documents where doc_type in [policy, standard, template,
    taxonomy, specification]: confidentiality_class in [C1, C2, C3].
    C0 assignment for these doc_types triggers a classification-override
    audit event.
  checked_by: Classification Agent

R07:
  rule: >
    Documents of doc_type: report must be classified at minimum C2
    (restricted). If an author proposes C0 or C1 for a report document,
    the Classification Agent must override to C2 and record the override
    rationale. Higher classification (C3) is permitted.
  test: >
    For all documents where doc_type == report: confidentiality_class in
    [C2, C3]. C0 or C1 assignment for report doc_type triggers a
    classification-override audit event.
  checked_by: Classification Agent

R08:
  rule: >
    No doc_type carries a mandatory maximum classification. A document of
    any type may be assigned C3 (confidential) if its content warrants it.
    The mandatory overrides in R06 and R07 specify minimum levels only.
  test: >
    No validation check rejects or overrides a classification solely because
    it is higher than the doc_type minimum. C3 assignment for a policy or
    template is valid if confirmed by the Classification Agent.
  checked_by: Classification Agent

### Reclassification

R09:
  rule: >
    Reclassification of a document that has reached approved status requires
    a SysAdmin directive issued by sysadmin:dlm-sysadmin. The directive must
    specify: doc_id, current classification, proposed classification, and
    justification. No agent other than sysadmin:dlm-sysadmin may initiate
    reclassification of an approved document.
  test: >
    For each reclassification of an approved document: a SysAdmin directive
    exists with all four required fields before the Classification Agent
    executes the reclassification.
  checked_by: Classification Agent; Audit Trail Agent

R10:
  rule: >
    Every reclassification, regardless of whether the document is draft or
    approved, constitutes a PATCH version increment per Document Versioning
    Policy (DLMS-2026-0038). The CHANGE_LOG must be updated to record the
    reclassification event with the before and after classification values.
  test: >
    For each reclassification: A new file version exists with the version
    field incremented at the PATCH position AND the CHANGE_LOG entry
    includes the previous and new classification values.
  checked_by: Version Control Agent; Classification Agent

R11:
  rule: >
    Every reclassification must produce a classification-changed audit event
    with: doc_id, previous classification (before_state), new classification
    (after_state), acting_agent_id, authorising_directive_ref (for approved
    documents), and timestamp. This event is permanent and may not be deleted.
  test: >
    For each reclassification: classification-changed audit event exists with
    all six required fields. Null before_state or after_state on this event
    type is non-conformant.
  checked_by: Audit Trail Agent

### Retention_Effect

R12:
  rule: >
    All C3 (confidential) documents are assigned retention class RC-permanent,
    regardless of their doc_type. Where a conflict exists between the
    doc_type-based retention assignment and the C3 classification, RC-permanent
    prevails. The Classification Agent must confirm RC-permanent is set in
    the frontmatter for any C3 document before the creation stage closes.
  test: >
    For all C3 documents: retention_class == 'RC-permanent'. A C3 document
    with any other retention_class value triggers a retention-conflict audit
    event and requires immediate correction before the creation stage closes.
  checked_by: Classification Agent; Agent Format Validator

### Context_Boundary

R13:
  rule: >
    The Classification Agent must operate within a strict context boundary
    per Agent Context Boundary Policy (DLMS-2026-0016). Its reads list must
    contain only: the document being classified (frontmatter and body) and
    the Taxonomy / Controlled Vocabulary (DLMS-2026-0021). The Classification
    Agent must not read access manifests, other documents' classification
    history, or prior reclassification directives for other documents.
  test: >
    All reads by Classification Agent during a classification task are
    confined to: target document AND DLMS-2026-0021. Any read outside this
    set is a context boundary violation per DLMS-2026-0016.
  checked_by: Audit Trail Agent; Agent Behaviour Analyst

### Downstream_Reference

R14:
  rule: >
    The access control implications of each classification level — which
    agents may read or write a classified document, under what conditions,
    and how access denial is handled — are defined entirely in Access Control
    Policy (DLMS-2026-0044). This policy does not define or repeat access
    control rules. Any conflict between classification criteria in this policy
    and access control rules in DLMS-2026-0044 is resolved in favour of
    the more restrictive control.
  test: >
    No access control rules, tool possession requirements, or agent permission
    specifications appear in this policy. Any such rule is non-conformant and
    must be relocated to DLMS-2026-0044.
  checked_by: Review Synthesizer (lens-accuracy)

### Audit_Requirements

R15:
  rule: >
    A classification-assigned audit event must be logged by the Audit Trail
    Agent at document creation, immediately after the Classification Agent
    confirms the classification. The event must include: doc_id, assigned
    classification, authoring_agent_id (Classification Agent identity), and
    timestamp. For C0 assignments, justification must additionally be
    non-null (per R03).
  test: >
    For each newly created document: classification-assigned event exists
    with doc_id, assigned_classification, authoring_agent_id, and timestamp
    all non-null. For C0: justification additionally non-null.
  checked_by: Audit Trail Agent

## EXCEPTIONS_PROCESS
Tier 3 exceptions are permitted on a time-limited basis with SysAdmin
approval. To request an exception to any rule in this policy: (1) The
requesting agent produces a policy-exception-request artefact addressed
to the SysAdmin directive queue, citing the rule reference, the reason
the rule cannot be satisfied, and the proposed mitigating controls.
(2) sysadmin:dlm-sysadmin reviews and, if approved, issues a
policy-exception-grant directive specifying the rule, scope, expiry date,
and audit conditions. (3) The exception is logged as a policy-exception
audit event and is visible in the next CI cycle report. No exception may
extend beyond 90 days without renewal. No exception may waive R01, R05,
or R12. The four-level classification scheme (R01), the independence
requirement (R05), and the C3 retention override (R12) are structural
constraints.

## ENFORCEMENT
  primary_agent:    Classification Agent; Audit Trail Agent;
                    Agent Format Validator
  gate_positions:
    - Creation stage: Classification Agent assigns and confirms
      classification before the creation-complete event; Agent Format
      Validator confirms confidentiality_class is populated and valid
    - C3 documents at creation: Classification Agent confirms
      RC-permanent before creation stage closes (R12)
    - Reclassification: Classification Agent executes only on SysAdmin
      directive for approved documents; Version Control Agent produces
      PATCH increment
  audit: >
    classification-assigned events are logged at creation per R15.
    classification-changed events are logged on reclassification per R11.
    classification-override events are logged when Classification Agent
    overrides a proposed level per R06–R07. Context boundary compliance
    for Classification Agent is logged per DLMS-2026-0015.
  violation_type:   Tier 3 operational violation
  escalation: >
    Classification independence violations (R05) are immediately escalated
    to sysadmin:dlm-sysadmin. Reclassification without SysAdmin directive
    (R09) is immediately escalated. Context boundary violations by
    Classification Agent (R13) are immediately escalated. C0 assignment
    without justification (R03) triggers a SysAdmin alert.

## REVIEW_SCHEDULE
  interval_max:      6 months (Tier 3 maximum)
  trigger_conditions:
    - A new classification level is proposed — requires MINOR version
      amendment with corresponding updates to DLMS-2026-0021 (Taxonomy)
      and DLMS-2026-0044 (Access Control Policy)
    - DLMS-2026-0021 (Taxonomy) is amended in a way that affects the
      registered controlled vocabulary terms for classification levels
    - DLMS-2026-0022 (Retention Schedule) is amended in a way that
      affects retention consequences for classification levels
    - Access Control Policy (DLMS-2026-0044) is amended in a way that
      changes the access implications of a classification level, requiring
      a consistency check against this policy's level definitions
    - Systematic classification-override patterns detected by CI —
      suggesting either the default assignment or doc_type override rules
      require calibration
