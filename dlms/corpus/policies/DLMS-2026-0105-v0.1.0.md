## SUMMARY
This document is the authoritative roster of all 9 agents in Tier 15 — the Nexus
Infrastructure team. It defines each agent's function, reads, writes, tools, and key
constraints. All Tier 15 .agent.md files, the Tool Access Registry (TAR-001), and
pipeline gate logic must be consistent with the declarations in this document.

## SCOPE
Applies to: all Tier 15 Nexus Infrastructure agents.
Excludes: Tier 14 SysAdmin agents (roster in dlms-agent-roster.md); Nexus MCP tool
  implementation files in nexus/src/ (those are outputs of the agents defined here,
  not governance documents).

## AGENT_ROSTER

### ORCHESTRATOR

| Field | Value |
|---|---|
| **Agent** | `Nexus Infrastructure Orchestrator` |
| **Role** | Routes infra work items through the complete plan→DoD→execute→review→verify pipeline. Enforces all gates defined in DLMS-2026-0104. |
| **Invoked by** | Human (FO); or DLM SysAdmin Agent (Tier 14) for maintenance tasks triggered by CI cycle recommendations |
| **Reads** | infra-routing-registry.md; nexus-phase-manifest.md |
| **Writes** | infra-routing-instructions-[phase].md |
| **tools** | `['agent']` only — delegates all substantive work |
| **Delegates to** | Infra Context Curator, Infra Planner, Infra DoD Agent, Infra Executor, Infra Code Reviewer, Infra Architecture Reviewer, Infra Verifier, Infra Metrics Agent, Infra Knowledge Curator |
| **Never** | Reads document or code content; holds any execution, write, or verification tool |

## PIPELINE_SEQUENCE

Standard sequence for a single infra_work_item. All gate conditions per DLMS-2026-0104.

```
Nexus Infrastructure Orchestrator
  │
  ├─ [STEP 1]  Invoke: Infra Context Curator
  │            Gate:   infra-context-[phase].md exists
  │
  ├─ [STEP 2]  Invoke: Infra Planner
  │            Gate:   infra-plan-[phase].md exists AND rollback_procedure != null
  │
  ├─ [STEP 3]  Invoke: Infra DoD Agent          (RC-standard work items only)
  │            Gate:   infra-dod-[phase].md exists
  │            Note:   For RC-high-impact and RC-critical work items, skip to
  │                    HIGH_IMPACT_PIPELINE below instead of this step.
  │
  ├─ [STEP 4]  Invoke: Infra Executor
  │            Gate:   implementation output path (per plan) exists
  │
  ├─ [PARALLEL STEP 5]
  │            Invoke:  Infra Code Reviewer
  │            Invoke:  Infra Architecture Reviewer  (concurrent)
  │            Gate:    BOTH review artefacts exist
  │
  ├─ [STEP 6]  Invoke: Infra Verifier
  │            Gate:   infra-verification-[phase].md exists AND result == 'VERIFIED'
  │
  └─ [POST-GATE — non-blocking]
               Invoke: Infra Metrics Agent
               Invoke: Infra Knowledge Curator
```

ON_GATE_FAIL:
  action:  halt pipeline
  write:   infra-routing-instructions-[phase].md with status: FAILED
  fields:  failed_step, failed_gate_condition, reason, phase_id, timestamp
  never:   advance past a failed gate; invoke Executor before infra_dod exists

## HIGH_IMPACT_PIPELINE

Alternate pipeline for RC-high-impact and RC-critical work items. Steps 1 and 2
are identical to the standard pipeline. Steps 3 and 4 differ. Steps 4-onwards
resume standard pipeline.

```
Nexus Infrastructure Orchestrator
  │
  ├─ [STEP 1]  Invoke: Infra Context Curator        (identical to standard)
  │            Gate:   infra-context-[phase].md exists
  │
  ├─ [STEP 2]  Invoke: Infra Planner                (identical to standard)
  │            Gate:   infra-plan-[phase].md exists AND rollback_procedure != null
  │                    AND impact_class declared in plan artefact
  │
  ├─ [PARALLEL STEP 3 — RC-high-impact]
  │            Invoke: Infra DoD Author (Completeness)
  │            Invoke: Infra DoD Author (Adversarial)  (concurrent)
  │            Input:  infra-plan-[phase].md path | infra-context-[phase].md path only
  │            Rule:   Neither author may read the other's draft output
  │            Gate:   infra-dod-draft-completeness-[phase].md AND
  │                    infra-dod-draft-adversarial-[phase].md BOTH exist
  │
  │  [Additional for RC-critical — extends PARALLEL STEP 3]
  │            Invoke: Infra DoD Author (Efficiency)   (concurrent with above two)
  │            Gate:   +infra-dod-draft-efficiency-[phase].md ALSO exists
  │
  ├─ [STEP 3b] Invoke: Infra DoD Synthesizer
  │            Input:  all infra-dod-draft-*-[phase].md paths for this phase_id
  │            Rule:   Synthesizer actor_id must differ from all draft author actor_ids
  │            Rule:   Apply Synthesizer Rules S01-S05 (+ S06 if security_overlay triggered)
  │            Gate:   infra-dod-[phase].md (canonical) exists AND impact_class field present
  │                    AND security_overlay field present (true or false explicitly declared)
  │
  ├─ [STEP 3c — RC-critical only]
  │            HUMAN REVIEW GATE: FO or delegate must review and explicitly approve
  │            infra-dod-[phase].md before Infra Executor is invoked.
  │            Gate:   human approval record exists for infra-dod-[phase].md
  │
  ├─ [STEP 4]  Invoke: Infra Executor               (resumes standard pipeline)
  │            Gate:   implementation output path (per plan) exists
```

ON_GATE_FAIL (HIGH_IMPACT_PIPELINE — additional conditions):
  parallel_draft_actor_intersection: halt if any draft author actor_id matches synthesizer
    actor_id; write gate failure with violation_type: HC06_violation
  missing_security_overlay_flag: halt if work item is security-boundary-adjacent and
    infra-dod-[phase].md has no security_overlay field; violation_type: HC09_violation
  human_gate_bypassed: halt if RC-critical work item proceeds to Executor without human
    approval record; violation_type: HC05_violation

## ARTEFACT_TYPES

| Artefact | Produced by | Consumed by | DoD gate? |
|---|---|---|---|
| `infra-context-[phase]` | Infra Context Curator | All pipeline agents | Yes — required by Steps 2–6 |
| `infra-plan-[phase]` | Infra Planner | Infra DoD Agent, Infra Executor, Infra Verifier | Yes — required by Steps 3–6 |
| `infra-dod-[phase]` | Infra DoD Agent (RC-standard) _or_ Infra DoD Synthesizer (RC-high-impact+) | Infra Verifier | Yes — required by Step 4 (Executor gate) |
| `infra-dod-draft-completeness-[phase]` | Infra DoD Author (Completeness) | Infra DoD Synthesizer | RC-high-impact and RC-critical only. Gate for Synthesizer invocation. |
| `infra-dod-draft-adversarial-[phase]` | Infra DoD Author (Adversarial) | Infra DoD Synthesizer | RC-high-impact and RC-critical only. Gate for Synthesizer invocation. |
| `infra-dod-draft-efficiency-[phase]` | Infra DoD Author (Efficiency) | Infra DoD Synthesizer | RC-critical only. Gate for Synthesizer invocation. |
| `infra-implementation-[phase]` | Infra Executor | Infra Code Reviewer, Infra Architecture Reviewer, Infra Verifier | Yes — required by Steps 5–6 |
| `infra-code-review-[phase]` | Infra Code Reviewer | Infra Verifier | Yes — required by Step 6 |
| `infra-arch-review-[phase]` | Infra Architecture Reviewer | Infra Verifier | Yes — required by Step 6 |
| `infra-verification-[phase]` | Infra Verifier | Nexus Infrastructure Orchestrator | Final gate output |
| `infra-learnings-[phase]` | Infra Verifier | Infra Knowledge Curator | Submitted to Knowledge Base after verification |
| `infra-metrics-[phase]` | Infra Metrics Agent | SysAdmin Briefing Agent (Tier 13/14) | Post-gate; informational |
