## SUMMARY
This policy governs the classification of all DLMS documents — the
assignment of tags drawn exclusively from the active Controlled Vocabulary
(DLMS-2026-0021), the minimum required tag set, the authority boundary
between author and Classification Agent, and the audit requirements for
every classification action. This is a Tier 3 Operational Lifecycle policy.

## SCOPE
Applies to: all DLMS documents and the tags[] frontmatter field in every
document; the Document Author Agent (tag proposal only); the Classification
Agent (tag assignment authority); the Taxonomy Validator (tag compliance
checking); the Tag Index Agent (corpus tag index maintenance); the Approval
Gate Agent (classification compliance as a pre-approval gate condition).

Excludes: internal agent state identifiers; file path strings; version
strings; doc_ids; and any other structured identifiers appearing in
non-tag fields. This policy governs tag values only. Free-text values
in body content fields are not governed by this policy.

Bootstrap exception: Documents DLMS-2026-0001 through DLMS-2026-0013 were
tagged before this policy and the taxonomy were formally approved. Their
existing tags are compliant by declaration. All documents from
DLMS-2026-0014 onwards must comply fully with this policy.

## DEFINITIONS

assigned tag:
  A tag value in a document's tags[] field that has been confirmed as
  present in the active terms of the Controlled Vocabulary (DLMS-2026-0021)
  and recorded in the Tag Index by the Tag Index Agent.

classification recommendation:
  A structured artefact produced by the Classification Agent at the
  Indexing stage that proposes a final tag set for a document. The
  recommendation is the agent's output — it does not directly modify
  the document's frontmatter. Frontmatter is updated by the Version
  Control Agent acting on an approved recommendation.

Classification Agent:
  The agent holding tag-assignment authority. The Classification Agent
  reads the target document and the Controlled Vocabulary only. It
  produces a classification recommendation artefact and does not hold
  direct write tools for document frontmatter.

proposed tag:
  A tag value in the tags[] field as written by the Document Author
  Agent at creation. Proposed tags are candidate values only — they
  are not confirmed until validated by the Taxonomy Validator and
  accepted by the Classification Agent in its recommendation.

retention_class default:
  The value RC-7 assigned by the Creation Orchestrator when no
  retention_class is specified by the Document Author at creation.
  An RC-7 default is flagged for SysAdmin review in the next CI cycle.

## RULES

### Tag_Source_Constraint

R01:
  rule: >
    All values in the tags[] field of any DLMS document must be drawn
    exclusively from the active terms in the current approved version
    of the Controlled Vocabulary (DLMS-2026-0021). No tag value may be
    used that does not appear in that document's TERMS list with
    status: active.
  test: >
    For all documents D and all tags T in D.tags:
    T exists in DLMS-2026-0021.TERMS AND
    DLMS-2026-0021.TERMS[T].status == 'active'
  checked_by: Taxonomy Validator; Approval Gate Agent

R02:
  rule: >
    Deprecated terms must not be applied to new documents. A deprecated
    term in the Controlled Vocabulary (status: deprecated) is not a
    valid tag value for any document created or updated after the
    deprecation event.
  test: >
    For all documents D created or version-incremented after deprecation_at
    of term T: T must not appear in D.tags.
  checked_by: Taxonomy Validator; Version Control Agent

### Minimum_Required_Tags

R03:
  rule: >
    Every DLMS document must carry at least two tags: one tag that
    matches the document's doc_type value (a D01 domain term) and one
    tag that identifies the DLMS development wave during which the
    document was authored (a D02 domain term).
  test: >
    D.doc_type IN D.tags AND
    at least one term from D02 domain IN D.tags
  checked_by: Taxonomy Validator; Agent Format Validator

R04:
  rule: >
    The doc_type tag must match the actual doc_type field value exactly.
    A policy document must carry the tag 'policy'; a template document
    must carry the tag 'template'; etc.
  test: >
    D.doc_type == tag_value where tag_value IN D.tags AND
    tag_value IN DLMS-2026-0021.D01.terms
  checked_by: Taxonomy Validator; Agent Format Validator

### Authority_Separation

R05:
  rule: >
    The Document Author Agent may propose tags at creation by populating
    the tags[] field. Proposed tags are not confirmed until validated
    by the Taxonomy Validator in the Indexing stage. The Document Author
    Agent does not hold tag-assignment authority.
  test: >
    Document Author Agent writes are confined to creating the document
    file. Tag assignment authority belongs to Classification Agent only.
    No classification-confirmed event exists authored by Document Author.
  checked_by: Audit Trail Agent; Agent Behaviour Analyst

R06:
  rule: >
    The Classification Agent must produce a classification recommendation
    artefact at the Indexing stage for every document. The recommended
    tag set must be confined to active terms in DLMS-2026-0021. The
    recommendation must not be authored by the same agent that created
    the document (Verification Independence, DLMS-2026-0014 R01).
  test: >
    A classification-recommendation artefact exists for this doc_id AND
    all tags in the recommendation are active terms in DLMS-2026-0021 AND
    recommendation.author != document.created_by.
  checked_by: Taxonomy Validator; Approval Gate Agent (independence check)

R07:
  rule: >
    The Classification Agent holds read-only tools scoped to the target
    document and DLMS-2026-0021 only (per DLMS-2026-0016). It must not
    read any other corpus document during a classification task.
  test: >
    All reads by Classification Agent during classification task are
    confined to: target document AND DLMS-2026-0021.
    Any read outside this set is a context boundary violation.
  checked_by: Audit Trail Agent; Agent Behaviour Analyst

### Taxonomy_Gap_Escalation

R08:
  rule: >
    If the Classification Agent's recommended tag set includes a concept
    not represented by any active term in DLMS-2026-0021, the agent must
    produce a taxonomy-term-proposal artefact addressed to the SysAdmin
    directive queue and flag the recommendation as pending-term-addition.
    The recommendation must not use an unapproved term as a placeholder.
  test: >
    No unapproved term appears in any classification recommendation.
    IF a concept gap is identified: a taxonomy-term-proposal audit event
    exists AND the recommendation status is pending-term-addition.
  checked_by: Taxonomy Validator; Audit Trail Agent

### Retention_Class_Assignment

R09:
  rule: >
    The retention_class field must be set to a valid class from
    DLMS-2026-0022 at creation. The Document Author Agent is responsible
    for selecting the appropriate class based on the document's doc_type
    and content. The Creation Orchestrator assigns the default RC-7 if
    the field is null at creation gate.
  test: >
    retention_class IN [RC-permanent, RC-1, RC-2, RC-3, RC-4,
    RC-5, RC-6, RC-7] at creation gate.
  checked_by: Agent Format Validator; Creation Orchestrator

R10:
  rule: >
    When the Creation Orchestrator assigns the RC-7 default, it must
    log a retention-default-applied audit event flagging the doc_id
    for SysAdmin review in the next CI cycle.
  test: >
    IF retention_class == RC-7 AND set_by == 'creation-orchestrator':
    audit event type: retention-default-applied exists for this doc_id.
  checked_by: Audit Trail Agent; CI Monitor Agent

### Audit_Requirements

R11:
  rule: >
    A classification-confirmed audit event must be logged by the Audit
    Trail Agent when a classification recommendation is accepted and
    the document's tag set is finalised. The event must include:
    doc_id, final tag set, Classification Agent ID, and a reference
    to the classification recommendation artefact.
  test: >
    classification-confirmed event exists for this doc_id with
    all four required fields populated.
  checked_by: Audit Trail Agent; Stage Verifier

## EXCEPTIONS_PROCESS
Tier 3 exceptions are permitted on a time-limited basis with SysAdmin
approval per the process defined in DLMS-2026-0001. To request an
exception to any rule in this policy: the requesting agent produces a
policy-exception-request artefact to the SysAdmin directive queue, citing
the rule reference, reason, and proposed mitigating controls.
sysadmin:dlm-sysadmin reviews and, if approved, issues a
policy-exception-grant directive with expiry date (maximum 90 days)
and audit conditions. No exception may waive R01 or R06.

## ENFORCEMENT
  primary_agent:    Taxonomy Validator; Classification Agent
  gate_positions:
    - Indexing stage: Taxonomy Validator checks R01–R04 for every
      document at the indexing stage gate
    - Pre-approval: Approval Gate Agent checks R01, R03, R06 before
      any status transition to approved
    - Post-creation: Agent Format Validator checks R09 at creation gate
  audit: >
    All tag validation outcomes are logged as tag-validation-pass or
    tag-validation-fail events. All classification recommendations are
    logged as classification-recommended events. All finalised
    classifications are logged as classification-confirmed events.
    All context boundary checks are logged per DLMS-2026-0015.
  violation_type:   Tier 3 operational violation
  escalation: >
    R08 violations (unapproved term usage) are immediately escalated to
    sysadmin:dlm-sysadmin. All other violations are captured in the CI
    cycle report for SysAdmin review within the CI resolution window.

## REVIEW_SCHEDULE
  interval_max:      6 months (Tier 3 maximum)
  trigger_conditions:
    - The Controlled Vocabulary (DLMS-2026-0021) is amended with a
      major version increment
    - A new doc_type is added requiring a new D01 term
    - A systematic tag non-compliance pattern is detected by CI
    - The Taxonomy Policy (DLMS-2026-0019) is amended in a way that
      affects the classification process
