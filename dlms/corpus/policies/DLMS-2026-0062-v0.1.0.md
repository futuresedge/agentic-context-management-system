## SUMMARY
This SLA governs the performance of the DLMS context delivery layer,
defining measurable targets for context package production latency,
package size compliance with token budget constraints, and required
policy coverage within delivered packages. It formalises the
performance expectations of the Context Curator agent as the primary
interface between the governance corpus and consuming stage agents.

## SCOPE
Applies to: all Creation Context artefacts produced by the Context
Curator agent; the Context Curator agent; the context delivery layer
as defined under Agent Context Boundary Policy (DLMS-2026-0016).

Excludes: stage-specific performance for consuming agents (measured by
the stage-specific SLAs DLMS-2026-0057 through 0061); document content
quality within the creation context package; the evaluation of whether
context packages produce correct downstream agent outputs
(a content-quality concern); non-creation context packages (if other
context package types are introduced in a future wave, a separate
SLA or amendment to this one is required).

Boundary conditions:
  M01 clock starts:  context delivery request audit event — the event
                     generated when a stage agent or orchestrator
                     submits a context delivery request to the
                     Context Curator
  M01 clock stops:   curated_at in the Creation Context artefact
                     (DLMS-2026-0046) produced in response to the request
  M02 measured:      per CI cycle — proportion of Creation Context
                     artefacts within the cycle that conform to the
                     token budget defined in DLMS-2026-0016 R04 or
                     equivalent context boundary constraint
  M03 measured:      per CI cycle — proportion of Creation Context
                     artefacts whose referenced_policies list contains
                     all policies required for the requested doc_type
                     per DLMS-2026-0016 and the applicable template
                     assignment

## DEFINITIONS

breach:
  A metric value that equals or exceeds breach_threshold for that metric.
  A breach triggers the breach-level BREACH_RESPONSE and must be logged
  as an sla-breach audit event. For rate metrics (M02, M03), a breach
  is the CI cycle rate value falling below breach_threshold.

context delivery request:
  The audit event generated when a stage agent or orchestrator submits
  a formal request for a context package from the Context Curator. This
  event initiates the M01 measurement clock.

elapsed time:
  Clock time in hours between the context delivery request and
  curated_at in the resulting Creation Context artefact (M01 only).
  Measured from auditable timestamps only.

package size compliance:
  The proportion of Creation Context artefacts produced in a given CI
  cycle whose total token count (as estimated by the Context Curator)
  falls within the token budget defined in DLMS-2026-0016 or the
  applicable constraint. A non-compliant package is one that exceeds
  the budget for its context type and consuming agent class.

required policy coverage:
  The proportion of Creation Context artefacts produced in a given CI
  cycle whose referenced_policies list includes all governance documents
  required for the requested doc_type. Required policies are determined
  by the template_assignment in the context package and the
  referenced_policies prescriptions for that doc_type.

warning (M01):
  M01 measured value exceeding warning_threshold but below
  breach_threshold. Logged and Context Curator notified.

warning (M02, M03):
  Rate metric falling below warning_threshold but above
  breach_threshold. Logged and Context Curator notified at CI cycle
  boundary.

## METRICS

M01:
  name:                 Context package production latency
  description:          Elapsed time from a context delivery request to
                        the Context Curator producing a Creation Context
                        artefact in response. Measures the core
                        responsiveness of the context delivery layer.
  unit:                 hours
  target:               <= 2h
  warning_threshold:    > 90 minutes
  breach_threshold:     > 4h
  measurement_source:   context delivery request audit event;
                        curated_at in Creation Context artefact
                        (DLMS-2026-0046)
  measurement_frequency: per-request

M02:
  name:                 Package size compliance rate
  description:          Proportion of Creation Context artefacts
                        produced in a CI cycle that conform to the
                        applicable token budget per DLMS-2026-0016.
                        Measures the Context Curator's discipline in
                        applying context boundary constraints.
  unit:                 percentage (% of packages in compliance)
  target:               >= 95%
  warning_threshold:    < 97%
  breach_threshold:     < 90%
  measurement_source:   Creation Context artefacts produced in the CI
                        cycle; token budget conformance flag logged by
                        Context Curator per artefact; audit log
  measurement_frequency: per-CI-cycle

M03:
  name:                 Required policy coverage rate
  description:          Proportion of Creation Context artefacts
                        produced in a CI cycle whose referenced_policies
                        list includes all mandatory governance documents
                        for the requested doc_type and template
                        assignment. A package missing required policies
                        is non-compliant regardless of size conformance.
  unit:                 percentage (% of packages with full coverage)
  target:               == 100%
  warning_threshold:    < 100%
  breach_threshold:     < 100%
  measurement_source:   referenced_policies lists in Creation Context
                        artefacts (DLMS-2026-0046); required policies
                        lookup per doc_type and template_assignment;
                        audit log
  measurement_frequency: per-CI-cycle
  constraints:
    - warning_threshold and breach_threshold are identical for M03 —
      any coverage gap, even a single missing policy in one package,
      is both a warning and a breach simultaneously. This reflects the
      zero-tolerance position on required policy coverage.

## MEASUREMENT_METHOD

collection_agent:    Context Delivery Metrics Collector — collects M01
                     timestamps from context delivery request events and
                     Creation Context artefacts; collects M02 token
                     budget conformance flags; collects M03 coverage
                     verification results per artefact per CI cycle.

aggregation_agent:   Metrics Aggregator — receives raw per-request and
                     per-cycle data from Context Delivery Metrics
                     Collector and produces M01 latency statistics
                     (median, 95th percentile, breach count) and M02/M03
                     compliance rates per CI cycle. Must differ from
                     collection_agent per Verification Independence
                     Policy (DLMS-2026-0014).

reporting_artefact:  TMPL-performance-report-001 (Wave 12, planned —
                     see NOTES). Until Wave 12 is complete, performance
                     data is reported through interim ad hoc report
                     artefacts maintained by the Metrics Aggregator.

reporting_frequency: per CI cycle

baseline_ref:        Provisional design-intent baseline: M01 ≤ 2h;
                     M02 100% (design target); M03 100% (design target).
                     After 90 days of live operation the Metrics
                     Aggregator establishes operational baselines.
                     M03 operational baseline is always 100% —
                     deviation from 100% is never an acceptable
                     operational norm.

## BREACH_RESPONSE

warning:
  trigger:               M01 exceeds warning_threshold (> 90 min) for
                         a given request; or M02/M03 rate falls below
                         warning_threshold in a CI cycle.
  notification_targets:  [Context Delivery Metrics Collector,
                          Context Curator agent]
  response_actions:
    - Context Delivery Metrics Collector logs a time-warning or
      coverage-warning audit event with metric_id and the affected
      doc_id or CI cycle identifier.
    - Context Curator reviews its context assembly procedure for
      the source of the warning.
  resolution_sla:        24h

breach:
  trigger:               M01 equals or exceeds breach_threshold (> 4h);
                         or M02 rate falls below breach_threshold (< 90%);
                         or M03 rate falls below 100% in any CI cycle.
  notification_targets:  [Context Delivery Metrics Collector,
                          Context Curator agent,
                          agent:sla-manager]
  response_actions:
    - Context Delivery Metrics Collector logs an sla-breach audit event
      with metric_id, the breach value, and affected doc_ids or cycle.
    - Context Curator examines the non-compliant or late packages and
      produces corrected artefacts where feasible.
    - agent:sla-manager acknowledges breach and initiates review per
      SLA Breach Response Policy (Wave 13, planned).
    - For M03 breaches: every non-compliant package must be identified
      by doc_id, and each consuming agent that received the
      non-compliant package must be notified to re-request context.
  resolution_sla:        8h

critical:
  trigger:               M03 rate below 100% for two consecutive CI
                         cycles; or M01 breach on more than 20% of
                         context delivery requests in a single CI cycle.
  notification_targets:  [agent:sla-manager,
                          sysadmin:dlm-sysadmin]
  response_actions:
    - agent:sla-manager produces a performance anomaly report with
      root cause analysis for the context delivery failure pattern.
    - sysadmin:dlm-sysadmin reviews the anomaly report and issues a
      corrective directive. For repeated M03 critical breaches, the
      directive must address the root cause of the policy coverage
      gap in the Context Curator's assembly logic.
  resolution_sla:        2h

## REVIEW_SCHEDULE
  interval_max:      3 months
  trigger_conditions:
    - Any M03 breach triggers a mandatory SLA review, as a policy
      coverage gap indicates a structural deficiency in the Context
      Curator's assembly logic that must be corrected before the
      next CI cycle.
    - DLMS-2026-0016 (Agent Context Boundary Policy) is amended in a
      way that changes token budget limits, reads boundaries, or the
      definition of required policy coverage.
    - The Creation Context Template (DLMS-2026-0046) is amended in a
      way that changes the referenced_policies schema or the template
      assignment field.
    - A new doc_type is formally registered in the DLMS that requires
      a distinct set of required policies — M03 measurement logic
      must be updated to include the new type.

## NOTES
reporting_artefact forward reference: TMPL-performance-report-001 is
planned for Wave 12 and does not yet exist in the corpus. Until Wave 12
is complete, performance reporting is conducted through interim ad hoc
report artefacts. This SLA must be reviewed after Wave 12 is drafted to
update the reporting_artefact reference in MEASUREMENT_METHOD.

M03 zero-tolerance design: warning_threshold and breach_threshold are
deliberately identical for M03 (both < 100%). This reflects the
principle that any context package missing required policies exposes a
consuming agent to governance gaps. A single missing policy in a single
package is treated as a breach, not a warning, because the downstream
impact (an agent operating without a required governance constraint in
context) is not recoverable post-hoc — the work may need to be redone.
This is consistent with DLMS-2026-0016 R04 which makes the reads list
exhaustive and explicit.

M01 measurement boundary note: the clock starts at the formal context
delivery request event, not at any earlier human-initiated trigger. If
there is a gap between a human initiating a creation task and the formal
request event being generated, that gap is not within this SLA's scope.
