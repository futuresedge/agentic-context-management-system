## SUMMARY
This SLA governs the performance of the DLMS review stage, defining
measurable latency targets for per-lens review, synthesis, approval gate
evaluation, DoD verification, and human approval when required. It
formalises the provisional review stage thresholds in Quality Threshold
Policy (DLMS-2026-0043 R09) and establishes a binding breach response
process for review stage performance failures.

## SCOPE
Applies to: all DLMS document review cycles for documents entering the
review stage after creation stage DoD has passed; all Perspective Reviewer
agents; the Review Synthesizer agent; the Approval Gate Agent; the DoD
Verifier (review stage); the Review Stage Orchestrator; human approvers
where human_approval_required is true.

Excludes: creation stage performance (DLMS-2026-0057); storage, distribution,
and archival stage performance; document content quality assessment
(DLMS-2026-0043); revision cycles re-entering the review stage after a
return-for-revision verdict (these are tracked as new review cycles with
new artefacts but measured under the same metrics).

Boundary conditions:
  M01 clock starts:  reviewer task dispatch audit event from Review
                     Stage Orchestrator to the applicable Perspective
                     Reviewer for a given doc_id, doc_version, and lens
  M01 clock stops:   reviewed_at in the Review Perspective artefact
                     (DLMS-2026-0048) for that lens
  M02 clock starts:  the latest reviewed_at timestamp across all required
                     Perspective artefacts for the current review session
  M02 clock stops:   synthesized_at in the Review Synthesis artefact
                     (DLMS-2026-0049)
  M03 clock starts:  synthesized_at in the Review Synthesis artefact
  M03 clock stops:   evaluated_at in the Approval Status artefact
                     (DLMS-2026-0050)
  M04 clock starts:  Review DoD record submission audit event
  M04 clock stops:   DoD Verifier produces verified Review DoD record
                     (template DLMS-2026-0025)
  M05 clock starts:  evaluated_at in the Approval Status artefact where
                     human_approval_required is true
  M05 clock stops:   human_approved_at in the same Approval Status
                     artefact; M05 applies only when
                     human_approval_required is true

## DEFINITIONS

breach:
  A metric value that equals or exceeds breach_threshold for that metric.
  A breach triggers the breach-level BREACH_RESPONSE and must be logged
  as an sla-breach audit event referencing the affected doc_id.

elapsed time:
  Clock time in hours between two defined events per the SCOPE Boundary
  conditions above. Measured from auditable timestamps in DLMS artefacts
  or audit log events only.

human approval latency:
  The elapsed time from the Approval Gate Agent setting
  human_approval_required to true (recorded as evaluated_at in the
  Approval Status artefact) to a human approver recording
  human_approved_at. This metric (M05) applies conditionally — only
  for documents where human_approval_required is true.

review session:
  The set of Review Perspective artefacts produced for a single
  doc_id and doc_version in one review cycle. A document returned
  for revision and re-entering review is measured as a new review
  session with its own M01–M05 measurements.

warning:
  A metric value exceeding warning_threshold but below breach_threshold.
  Logged and stage orchestrator notified; stage advancement not blocked.

## METRICS

M01:
  name:                 Per-lens review latency
  description:          Elapsed time from reviewer task dispatch to
                        completion of a Review Perspective artefact for
                        a given doc_id, doc_version, and lens. Each lens
                        is measured independently. Formalises the 48h
                        provisional review threshold in DLMS-2026-0043 R09.
  unit:                 hours
  target:               <= 48h
  warning_threshold:    > 36h
  breach_threshold:     > 72h
  measurement_source:   Reviewer task dispatch audit event; reviewed_at
                        in Review Perspective artefact (DLMS-2026-0048)
  measurement_frequency: per-document per-lens

M02:
  name:                 Review synthesis latency
  description:          Elapsed time from completion of the last required
                        Perspective artefact in a review session to
                        completion of the Review Synthesis artefact.
                        Measures the Review Synthesizer's speed in
                        producing a synthesis given a complete set of
                        perspectives.
  unit:                 hours
  target:               <= 24h
  warning_threshold:    > 18h
  breach_threshold:     > 48h
  measurement_source:   Latest reviewed_at across all required Perspective
                        artefacts for the session; synthesized_at in
                        Review Synthesis artefact (DLMS-2026-0049)
  measurement_frequency: per-review-session

M03:
  name:                 Approval gate evaluation latency
  description:          Elapsed time from Review Synthesis artefact
                        completion to the Approval Gate Agent producing
                        an Approval Status artefact. Measures the gate
                        agent's evaluation speed.
  unit:                 hours
  target:               <= 4h
  warning_threshold:    > 3h
  breach_threshold:     > 8h
  measurement_source:   synthesized_at in Review Synthesis artefact
                        (DLMS-2026-0049); evaluated_at in Approval Status
                        artefact (DLMS-2026-0050)
  measurement_frequency: per-review-session

M04:
  name:                 Review DoD verification latency
  description:          Elapsed time from Review DoD record submission to
                        the DoD Verifier producing a verified Review DoD
                        record. Measures the DoD verification gate speed
                        for the review stage. Formalises the 24h
                        provisional DoD threshold in DLMS-2026-0043 R09.
  unit:                 hours
  target:               <= 24h
  warning_threshold:    > 18h
  breach_threshold:     > 48h
  measurement_source:   Review DoD record submission audit event;
                        DoD Verifier verified-dod-produced audit event
                        (template DLMS-2026-0025)
  measurement_frequency: per-document

M05:
  name:                 Human approval latency (conditional)
  description:          Elapsed time from the Approval Gate Agent
                        recording the evaluation (evaluated_at) with
                        human_approval_required true, to a human approver
                        recording human_approved_at in the Approval Status
                        artefact. Applies only when human_approval_required
                        is true; not measured for automated approvals.
  unit:                 hours
  target:               <= 72h
  warning_threshold:    > 48h
  breach_threshold:     > 120h
  measurement_source:   evaluated_at in Approval Status artefact where
                        human_approval_required is true; human_approved_at
                        in the same artefact (DLMS-2026-0050)
  measurement_frequency: per-document (conditional)

## MEASUREMENT_METHOD

collection_agent:    Review Stage Metrics Collector — collects raw
                     timestamps from Review Perspective artefacts,
                     Review Synthesis artefacts, Approval Status
                     artefacts, Review DoD records, and associated
                     audit events per doc_id and doc_version.

aggregation_agent:   Metrics Aggregator — receives raw per-session and
                     per-document measurements from Review Stage Metrics
                     Collector and produces aggregated metric values
                     (median, 95th percentile, breach rate) per CI cycle.
                     Must differ from collection_agent per Verification
                     Independence Policy (DLMS-2026-0014).

reporting_artefact:  TMPL-performance-report-001 (Wave 12, planned —
                     see NOTES). Until Wave 12 is complete, performance
                     data is reported through interim ad hoc report
                     artefacts maintained by the Metrics Aggregator.

reporting_frequency: per CI cycle

baseline_ref:        Provisional design-intent baseline established at
                     system activation; target values in this SLA are
                     the baseline. After 90 days of live operation the
                     Metrics Aggregator establishes an operational
                     baseline for the Anomaly Detector.

## BREACH_RESPONSE

warning:
  trigger:               Any review stage metric value exceeds its
                         warning_threshold for a given doc_id or
                         review session.
  notification_targets:  [Review Stage Metrics Collector,
                          Review Stage Orchestrator]
  response_actions:
    - Review Stage Metrics Collector logs a time-warning audit event
      with metric_id, elapsed_time, threshold_value, and doc_id.
    - Review Stage Orchestrator notifies the responsible agent and
      monitors for escalation to breach.
  resolution_sla:        24h

breach:
  trigger:               Any review stage metric value equals or
                         exceeds its breach_threshold for a given
                         doc_id or review session.
  notification_targets:  [Review Stage Metrics Collector,
                          Review Stage Orchestrator,
                          agent:sla-manager]
  response_actions:
    - Review Stage Metrics Collector logs an sla-breach audit event
      with metric_id, elapsed_time, breach_threshold, and doc_id.
    - Review Stage Orchestrator escalates the affected review task and
      logs a stage-escalation audit event.
    - agent:sla-manager acknowledges breach and initiates review per
      SLA Breach Response Policy (Wave 13, planned).
  resolution_sla:        8h

critical:
  trigger:               M01 breach_threshold (> 72h) exceeded for five
                         or more individual lens reviews in the same CI
                         cycle; or M05 breach (> 120h) persists without
                         resolution for two consecutive CI cycles.
  notification_targets:  [agent:sla-manager,
                          sysadmin:dlm-sysadmin]
  response_actions:
    - agent:sla-manager produces a performance anomaly report with
      root cause analysis for the affected metric(s) and doc_ids.
    - sysadmin:dlm-sysadmin reviews the anomaly report and issues a
      corrective directive within the resolution_sla window.
    - For M05 critical breaches: sysadmin:dlm-sysadmin may issue a
      directive appointing an alternate human approver.
  resolution_sla:        2h

## REVIEW_SCHEDULE
  interval_max:      3 months
  trigger_conditions:
    - Sustained M01 sla-breach events for a given Perspective Reviewer
      across two consecutive CI cycles indicate systemic capacity or
      configuration issues requiring SLA review.
    - DLMS-2026-0042 (Review Standards Policy) is amended in a way
      that changes required lenses, minimum perspective counts, or
      agent assignment rules.
    - DLMS-2026-0043 (Quality Threshold Policy) is amended with changes
      to review stage time thresholds or verification record standards.
    - Review stage artefact templates DLMS-2026-0048, 0049, or 0050
      are amended in ways that affect timestamp fields used as
      measurement sources.

## NOTES
reporting_artefact forward reference: TMPL-performance-report-001 is
planned for Wave 12 and does not yet exist in the corpus. Until Wave 12
is complete, performance reporting is conducted through interim ad hoc
report artefacts. This SLA must be reviewed after Wave 12 is drafted to
update the reporting_artefact reference in MEASUREMENT_METHOD.

M05 measurement dependency: M05 is only measurable for documents where
human_approval_required is true. The Metrics Aggregator must exclude
documents with human_approval_required false when computing M05 statistics.
Human approver capacity constraints are outside the scope of this SLA;
the 72h target assumes approver availability during normal operating
conditions. Planned maintenance windows must be declared in EXCLUSIONS
when that section is added.
