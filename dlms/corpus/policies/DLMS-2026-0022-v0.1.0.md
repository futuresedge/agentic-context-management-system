## SUMMARY
This document is the authoritative DLMS Retention Schedule. It defines
all eight retention classes — RC-permanent and RC-1 through RC-7 — that
appear in the retention_class frontmatter field of every DLMS document
and artefact. The Retention Evaluator consumes this schedule at the
Archival stage to determine how long each document must be kept and what
action is taken when its retention period expires.

## SCOPE
Applies to: all DLMS documents (as the source of retention_class definitions);
the Retention Evaluator agent that assigns and enforces retention classes;
the Archival Stage Orchestrator that acts on expired retention periods;
all stage artefacts, verification records, and audit trail entries produced
within the DLMS pipeline.

Excludes: retention requirements for non-DLMS artefacts held in external
systems; artefacts produced by non-DLMS agents that consume context packages
(their retention is governed by those agents' own systems); runtime agent
state that is ephemeral and never persisted to the DLMS file system.

## DEFINITIONS

deletion:
  The permanent, irrecoverable removal of a document or artefact from
  the DLMS file system at the end of its retention period. Deletion is
  the default end-of-retention action for classes RC-4 through RC-7.
  Deletion events are logged by the Audit Trail Agent and are themselves
  permanently retained as audit entries.

end-of-retention action:
  The action taken by the Retention Evaluator when a document's
  retention period expires. Three actions are defined: (1) retain —
  the document is kept indefinitely (RC-permanent); (2) archive-cold —
  the document is moved to cold storage, made queryable but not
  context-eligible, and retained for the specified additional period
  before deletion; (3) delete — the document is permanently removed.

retention period:
  The minimum length of time a document or artefact must be retained
  from its created_at timestamp before any end-of-retention action may
  be taken. A document may be retained longer than its class requires
  but never shorter.

retention class:
  One of eight values (RC-permanent, RC-1 through RC-7) assigned to
  every DLMS document in the retention_class frontmatter field.
  Determines the document's retention period and end-of-retention action.
  Assigned by the Retention Evaluator at the Archival stage gate.

Retention Evaluator:
  The agent responsible for assigning retention_class values to documents
  at the Archival stage, checking for expired retention periods at each
  CI cycle, and initiating end-of-retention actions for eligible documents.

## ENTRY_SCHEMA

class_id:
  field_name:   class_id
  field_type:   string
  required:     true
  nullable:     false
  description:  >
    The retention class identifier. Format: RC-permanent or RC-[1-7].
    This is the value that appears in the retention_class frontmatter
    field of documents assigned to this class.
  constraints:
    - Matches regex ^RC-(permanent|[1-7])$
    - Unique across all entries

retention_period:
  field_name:   retention_period
  field_type:   string
  required:     true
  nullable:     false
  description:  >
    The minimum duration from created_at before an end-of-retention
    action may be taken. Expressed as a human-readable period
    (e.g. "7 years", "Indefinite").
  constraints:
    - "Indefinite" is valid only for RC-permanent
    - All other values must be expressible as a duration in months or years

end_of_retention_action:
  field_name:   end_of_retention_action
  field_type:   enum
  required:     true
  nullable:     false
  description:  The action taken when the retention period expires.
  values:       [retain, archive-cold, delete]

mandatory_doc_types:
  field_name:   mandatory_doc_types
  field_type:   array of strings or null
  required:     true
  nullable:     true
  description:  >
    Doc_types for which this retention class is mandatory. These
    doc_types must always receive this class — the Retention Evaluator
    has no discretion. Null if no mandatory assignment applies.

applicable_artefact_types:
  field_name:   applicable_artefact_types
  field_type:   array of strings
  required:     true
  nullable:     false
  description:  >
    The types of documents and artefacts that typically receive this
    class. Includes doc_types (by discretionary assignment) and
    named artefact categories. Not exhaustive — the Retention Evaluator
    may assign this class to any artefact type not covered by a
    mandatory assignment elsewhere.

description:
  field_name:   description
  field_type:   string
  required:     true
  nullable:     false
  description:  >
    A precise statement of what this retention class covers, when it
    applies, and the rationale for its retention period.

cold_storage_period:
  field_name:   cold_storage_period
  field_type:   string or null
  required:     true
  nullable:     true
  description:  >
    For end_of_retention_action: archive-cold, the additional duration
    the document is held in cold storage before final deletion.
    Null for retain and delete actions.

deletion_authority:
  field_name:   deletion_authority
  field_type:   string or null
  required:     true
  nullable:     true
  description:  >
    The agent or role that must authorise the deletion or cold archival
    action. Null for RC-permanent (no deletion occurs).
  constraints:
    - For RC-1 and RC-2: must be sysadmin:dlm-sysadmin
    - For RC-3 through RC-7: may be agent:retention-evaluator
      acting under standing SysAdmin authorisation

## MAINTENANCE

add:
  operation:          add
  authority:          sysadmin:dlm-sysadmin via formal directive
  process: >
    A new retention class may only be added when an artefact type
    exists whose retention requirements cannot be satisfied by any
    existing class. The proposal must document: the artefact type,
    why no existing class applies, the proposed retention period
    and rationale, and the proposed end-of-retention action.
    SysAdmin approves via directive. The Retention Schedule receives
    a minor version increment. The Retention Evaluator specification
    is updated in the same wave to recognise the new class value.
    Note: adding a class also requires updating the retention_class
    enum in the Document Schema Policy (DLMS-2026-0004) and the
    Metadata Standard Policy (DLMS-2026-0018 R20).
  audit_requirement: >
    retention-class-added audit event citing the SysAdmin directive
    doc_id, the new class_id, and the artefact types it applies to.

update:
  operation:          update
  authority:          sysadmin:dlm-sysadmin via formal directive
  process: >
    Updates to an existing class (changing retention_period,
    end_of_retention_action, or applicable_artefact_types) require
    a SysAdmin directive. The directive must assess the impact on
    all documents currently assigned the class. If the period is
    shortened, documents already past the new expiry are flagged
    for immediate Retention Evaluator review. If the period is
    extended, no immediate action is required. The Retention Schedule
    receives a minor version increment for content changes or a
    patch increment for description corrections.
  audit_requirement: >
    retention-class-updated audit event citing the directive doc_id,
    the class_id, the changed field, the old value, and the new value.

retire:
  operation:          retire
  authority:          sysadmin:dlm-sysadmin via formal directive —
                      same authority as add
  process: >
    A retention class may only be retired if no document in the corpus
    currently carries that class_id in its retention_class field.
    The Retention Evaluator must produce a zero-assignment confirmation
    report before the retirement directive is issued. Retired classes
    are not deleted from this schedule — they remain as entries with
    a note field indicating retirement date and reason, to preserve
    the historical record. The class_id must not be reused.
  audit_requirement: >
    retention-class-retired audit event citing the directive doc_id,
    the class_id, and the zero-assignment confirmation report ref.

## NOTES
The decision to use eight classes rather than fewer reflects the genuine
spread of retention needs across DLMS artefact types. RC-permanent anchors
the permanent governance record. RC-1 and RC-2 cover formal operational
commitments and SysAdmin accountability. RC-3 and RC-4 cover intelligence
and verification artefacts. RC-5 and RC-6 cover operational reports at
different time horizons. RC-7 covers transient working artefacts.

The mandatory_doc_types field in RC-permanent is the mechanism that ensures
policies, templates, taxonomy, standards, and specifications are never
subject to the Retention Evaluator's discretion — they are assigned at
creation and the class is machine-validated by R20 of the Metadata Standard
Policy. All other classes are assigned by the Retention Evaluator at the
Archival stage gate based on doc_type, content, and operational context.

The cold_storage_period for RC-1 and RC-2 reflects sysadmin:dlm-sysadmin's
authority requirement for deletion of these artefacts. Cold archival gives
a SysAdmin review window before final deletion executes.
