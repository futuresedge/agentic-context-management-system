## SUMMARY
This template defines the structure of a Definition of Done completion record
for the Storage stage gate. The Storage Agent must produce a completed record
confirming that an approved document has been correctly persisted, indexed,
and registered before the lifecycle advances to Distribution. Failures at
this gate indicate file system, naming, or registration errors that must be
remediated before the document is treated as stored.

## TARGET_DOC_TYPE
dod-storage-record

## PURPOSE
The Storage DoD ensures that physical persistence of the approved document
is correct and verifiable. It confirms the file location matches the declared
agent_path, the version log is updated, the retention class is valid, the
doc_id is unique, and that an index entry has been produced. The Storage
Verifier (distinct from the Storage Agent) completes this record.

## RECORD_SCHEMA

### Header_Fields

FIELD_01:
  name:        dod_id
  type:        string
  required:    true
  nullable:    false
  format:      DOD-storage-{doc_id}-{version}
  example:     DOD-storage-DLMS-2026-0030-1.0.0
  description: Unique identifier for this DoD completion record. Immutable.

FIELD_02:
  name:        doc_id
  type:        string
  required:    true
  description: The DLMS doc_id of the document being evaluated.

FIELD_03:
  name:        doc_version
  type:        string
  required:    true
  format:      MAJOR.MINOR.PATCH
  description: The approved version of the document (e.g. 1.0.0).

FIELD_04:
  name:        stage
  type:        string
  required:    true
  value:       storage
  description: Fixed value. Identifies this as a Storage stage DoD record.

FIELD_05:
  name:        evaluated_by
  type:        string
  required:    true
  description: agent_id of the Storage Verifier completing this record.
  constraints:
    - Must differ from the Storage Agent that performed the storage action
      (DLMS-2026-0014)

FIELD_06:
  name:        evaluated_at
  type:        datetime
  required:    true
  format:      ISO 8601 with timezone
  description: Timestamp when the DoD evaluation was completed.

### Checklist_Items

Each item carries three sub-fields:
  result:    pass | fail
  mandatory: true | false   (fail on a mandatory item = hard block)
  notes:     string | null  (required when result is fail)

ITEM_01:
  id:          CI-STORAGE-01
  label:       File exists at the path declared in agent_path
  check:       The document file is accessible at the exact path declared
               in its agent_path frontmatter field.
  mandatory:   true
  governed_by: DLMS-2026-0003, DLMS-2026-0004

ITEM_02:
  id:          CI-STORAGE-02
  label:       Filename matches {doc_id}-v{version}.md exactly
  check:       The filename at the storage location matches the naming
               convention with no variant characters or extensions.
  mandatory:   true
  governed_by: DLMS-2026-0003 R02

ITEM_03:
  id:          CI-STORAGE-03
  label:       doc_id is unique in the corpus registry
  check:       No other document in the corpus shares this doc_id. Verified
               against the corpus registry at time of storage.
  mandatory:   true
  governed_by: DLMS-2026-0003 R01

ITEM_04:
  id:          CI-STORAGE-04
  label:       Version log updated with this version entry
  check:       A Version Log entry for this doc_id and doc_version has been
               created or appended at the time of storage.
  mandatory:   true
  governed_by: DLMS-2026-0004

ITEM_05:
  id:          CI-STORAGE-05
  label:       Access manifest created or updated
  check:       An Access Manifest artefact exists for this document and
               reflects the current approved version.
  mandatory:   true
  governed_by: DLMS-2026-0016

ITEM_06:
  id:          CI-STORAGE-06
  label:       retention_class confirmed against Retention Schedule
  check:       The document's retention_class value matches a valid class
               in DLMS-2026-0022 Retention Schedule.
  mandatory:   true
  governed_by: DLMS-2026-0022

ITEM_07:
  id:          CI-STORAGE-07
  label:       Index entry artefact produced for this version
  check:       A conforming Index Entry record (per DLMS-2026-0033) has
               been produced for this document version and is available
               to the corpus index.
  mandatory:   true
  governed_by: DLMS-2026-0033

ITEM_08:
  id:          CI-STORAGE-08
  label:       Storage audit event queued
  check:       A document-stored audit event has been prepared for the
               Audit Trail Agent and will be submitted on DoD passage.
  mandatory:   true
  governed_by: DLMS-2026-0015

### Attestation_Block

attestation:
  dod_id:          {value from Header FIELD_01}
  verdict:         pass | fail
  blocking_items:  list of ITEM IDs where result: fail AND mandatory: true
                   (empty list [] when verdict is pass)
  observations:    list of ITEM IDs where result: fail AND mandatory: false
                   (empty list [] when no non-mandatory items failed)
  signed_by:       agent_id — must match evaluated_by
  signed_at:       ISO 8601 datetime

## ADVANCEMENT_RULE

The document lifecycle advances to the Distribution stage if and only if:
  attestation.verdict == pass

A fail verdict is returned to the Storage Agent for remediation before
re-evaluation. Each re-evaluation produces a new DoD record.

## VALIDATION_RULES

V01: dod_id matches DOD-storage-{doc_id}-{version}.
V02: stage value is exactly "storage".
V03: verdict is "pass" or "fail" only.
V04: When verdict is "fail", blocking_items is non-empty.
V05: When verdict is "pass", blocking_items is an empty list [].
V06: All 8 checklist items are recorded.
V07: evaluated_by differs from the Storage Agent that performed storage.
