## SUMMARY
This template defines the structure of a Definition of Done completion record
for the Creation stage gate. The Creation Orchestrator must produce a
completed record for every document before it may advance to the Review stage.
A single fail verdict on any mandatory checklist item blocks advancement.

## TARGET_DOC_TYPE
dod-creation-record

## PURPOSE
The Creation DoD is a mandatory stage gate that confirms a draft document is
structurally and metadata-compliant before it enters the review pipeline.
It catches schema violations, naming errors, and missing content early —
before review effort is expended on a non-compliant artefact.

## RECORD_SCHEMA

### Header_Fields

FIELD_01:
  name:        dod_id
  type:        string
  required:    true
  nullable:    false
  format:      DOD-creation-{doc_id}-{version}
  example:     DOD-creation-DLMS-2026-0030-0.1.0
  description: Unique identifier for this DoD completion record. Immutable.

FIELD_02:
  name:        doc_id
  type:        string
  required:    true
  description: The DLMS doc_id of the document being evaluated.

FIELD_03:
  name:        doc_version
  type:        string
  required:    true
  format:      MAJOR.MINOR.PATCH
  description: The version of the document being evaluated at gate time.

FIELD_04:
  name:        stage
  type:        string
  required:    true
  value:       creation
  description: Fixed value. Identifies this as a Creation stage DoD record.

FIELD_05:
  name:        evaluated_by
  type:        string
  required:    true
  description: agent_id of the Creation Orchestrator completing this record.
  constraints:
    - Must differ from the doc's created_by value (DLMS-2026-0014 R01)

FIELD_06:
  name:        evaluated_at
  type:        datetime
  required:    true
  format:      ISO 8601 with timezone
  description: Timestamp when the DoD evaluation was completed.

### Attestation_Block

attestation:
  dod_id:          {value from Header FIELD_01}
  verdict:         pass | fail
  blocking_items:  list of ITEM IDs where result: fail AND mandatory: true
                   (empty list [] when verdict is pass)
  observations:    list of ITEM IDs where result: fail AND mandatory: false
                   (empty list [] when no non-mandatory items failed)
  signed_by:       agent_id — must match evaluated_by
  signed_at:       ISO 8601 datetime

## ADVANCEMENT_RULE

A document may advance from Creation to Review stage if and only if:
  attestation.verdict == pass
  (i.e. attestation.blocking_items is an empty list [])

A document with verdict: fail is returned to the Author Agent with the
blocking_items list as the remediation target. The Author Agent must address
all blocking items and trigger a new DoD evaluation. Each re-evaluation
produces a new DoD record; prior records are retained as audit evidence.

## VALIDATION_RULES

V01: dod_id is non-null and matches DOD-creation-{doc_id}-{version}.
V02: stage value is exactly "creation".
V03: verdict is exactly "pass" or "fail" — no other values permitted.
V04: When verdict is "fail", blocking_items list is non-empty.
V05: When verdict is "pass", blocking_items is an empty list [].
V06: All 12 checklist items are recorded (no items may be skipped).
V07: evaluated_by differs from the document's created_by field value.
