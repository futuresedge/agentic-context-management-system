## SUMMARY
This template defines the schema of a final metadata record, produced
post-classification once the Classification Agent has assigned tags and
confirmed the full metadata set. The final record extends the raw record
(DLMS-2026-0031) with classification-derived fields including the confirmed
tag list (validated against DLMS-2026-0021), retention class, and context
eligibility. It is the authoritative metadata snapshot for indexing and
distribution.

## TARGET_DOC_TYPE
metadata-final-record

## PURPOSE
A final metadata record is produced by the Classification Agent after tag
assignment and metadata enrichment are complete. It is consumed by the
Tag Index Agent (to update the corpus index), the Storage Agent (to confirm
retention handling), and the Distribution Agent (to check context_eligible).
The final record supersedes the raw record for all downstream use.

## SCHEMA

### Fields

All fields from DLMS-2026-0031 (Metadata Raw Template) are inherited with
the same definitions and constraints unless explicitly overridden below.
Additional enrichment fields follow the inherited set.

--- INHERITED FROM DLMS-2026-0031 ---

FIELD_01:  record_id
  format:    MDF-{doc_id}-{version}   (prefix changes from MDR to MDF)
  example:   MDF-DLMS-2026-0030-1.0.0

FIELD_02:  capture_agent
  description: agent_id of the Classification Agent that produced this
               final record.

FIELD_03:  capture_timestamp
  description: When the final record was produced. Must be at or after the
               corresponding raw record's capture_timestamp.

FIELD_04–FIELD_14: doc_id, title, doc_type, status, version, created_at,
  created_by, template_id, template_ver, agent_path, audit_ref
  (same definitions as DLMS-2026-0031; values are re-confirmed at
  final capture and must match the document's current frontmatter)

--- ENRICHMENT FIELDS ---

FIELD_15:
  name:        tags
  type:        list of strings
  required:    true
  nullable:    false
  description: Final tag list as assigned by the Classification Agent.
               Every value must exist in DLMS-2026-0021 Controlled Vocabulary
               with status: active at the time of classification.
  constraints:
    - Minimum one tag
    - Must include the wave-N tag corresponding to the document's wave
    - Must include the doc_type tag (e.g. "policy", "template")
    - All values validated against DLMS-2026-0021 at time of capture

FIELD_16:
  name:        retention_class
  type:        string
  required:    true
  nullable:    false
  description: Confirmed retention class. Must match the document's
               frontmatter retention_class field and must be a valid class
               defined in the Retention Schedule (DLMS-2026-0022).

FIELD_17:
  name:        context_eligible
  type:        boolean
  required:    true
  nullable:    false
  description: Confirmed context eligibility. Must match the document's
               frontmatter context_eligible field, subject to any
               confidentiality classification override.

FIELD_18:
  name:        dependencies
  type:        list of dependency objects
  required:    true
  nullable:    false
  description: Final confirmed dependency list. Each object contains:
                 doc_id: string — the referenced document's doc_id
                 rel:    enum   — [is-governed-by, implements, references,
                                   supersedes]
               All declared doc_ids must resolve to existing corpus documents.
               All rel values must conform to DLMS-2026-0020.

FIELD_19:
  name:        supersedes
  type:        string
  required:    false
  nullable:    true
  description: The doc_id this document supersedes, if any. Null otherwise.
               Referenced doc_id must exist in the corpus.

FIELD_20:
  name:        taxonomy_version
  type:        string
  required:    true
  nullable:    false
  format:      MAJOR.MINOR.PATCH
  description: The version of the Controlled Vocabulary (DLMS-2026-0021)
               active at the time of classification. Required for
               reproducibility of tag validation.

FIELD_21:
  name:        classification_agent
  type:        string
  required:    true
  nullable:    false
  description: agent_id of the Classification Agent that assigned the tags.
               Must match FIELD_02 (capture_agent).

FIELD_22:
  name:        classification_timestamp
  type:        datetime
  required:    true
  nullable:    false
  format:      ISO 8601 with timezone
  description: When tag assignment was completed. Must match or be equal to
               capture_timestamp.

FIELD_23:
  name:        all_validation_passed
  type:        boolean
  required:    true
  nullable:    false
  description: True if all validation rules in this template pass at capture
               time. False if any rule fails. A final record with
               all_validation_passed: false must not be used as input to
               the Index Entry template (DLMS-2026-0033) until errors are
               resolved.

FIELD_24:
  name:        validation_errors
  type:        list of error objects
  required:    true
  nullable:    false
  description: Same structure as DLMS-2026-0031 FIELD_15. Empty list []
               when all_validation_passed is true.

## VALIDATION_RULES

V01: record_id matches MDF-{doc_id}-{version}.
V02: All inherited fields from DLMS-2026-0031 are present and non-null.
V03: tags is non-empty and every value exists in DLMS-2026-0021 with
     status: active.
V04: tags includes the wave-N tag for the document's wave and the
     doc_type tag.
V05: retention_class matches the document's frontmatter field and exists
     in DLMS-2026-0022.
V06: All dependency doc_ids resolve to existing corpus documents and all
     rel values conform to DLMS-2026-0020.
V07: taxonomy_version matches the version of DLMS-2026-0021 consulted
     during classification.
V08: classification_agent matches capture_agent.
V09: When all_validation_passed is true, validation_errors is empty [].
V10: When all_validation_passed is false, validation_errors is non-empty
     and each error names the failing field and the violated rule.
V11: capture_timestamp is not before the corresponding raw record's
     capture_timestamp.
