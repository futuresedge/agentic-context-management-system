## SUMMARY
This template defines the schema and structure of a performance report
artefact produced by the Metrics Aggregator at the end of each CI cycle.
It captures per-stage SLA compliance data, throughput metrics, and trend
indicators derived from the six SLA policies (DLMS-2026-0057 through 0062),
and is consumed by the Anomaly Detector, Bottleneck Analyst, and CI
Perspective Synthesizer.

## TARGET_DOC_TYPE
performance-report

## SCHEMA

### Fields

FIELD_01:
  name:        report_id
  type:        string
  required:    true
  nullable:    false
  format:      PR-{YYYY}-{NNNN}
  example:     PR-2026-0001
  description: Unique identifier for this performance report. NNNN is a
               zero-padded sequential integer scoped to the year.
               Immutable after assignment.

FIELD_02:
  name:        cycle_id
  type:        string
  required:    true
  nullable:    false
  format:      CYCLE-{YYYY}-{NNNN}
  description: The CI cycle this report belongs to.

FIELD_03:
  name:        generated_by
  type:        string
  required:    true
  nullable:    false
  format:      agent:[agent-role-slug]
  constraints:
    - Must be agent:metrics-aggregator
    - Must differ from the collection agents and from verified_by
      (Verification Independence Policy DLMS-2026-0014)

FIELD_04:
  name:        period_start
  type:        datetime
  required:    true
  nullable:    false
  format:      ISO 8601 with timezone offset
  description: Start of the reporting period (inclusive).

FIELD_05:
  name:        period_end
  type:        datetime
  required:    true
  nullable:    false
  format:      ISO 8601 with timezone offset
  constraints:
    - period_end must be >= period_start

FIELD_06:
  name:        prior_report_ref
  type:        string or null
  required:    true
  nullable:    true
  description: >
    The report_id of the most recent prior performance report. Null for the
    first report. Enables trend comparison across CI cycles.

FIELD_07:
  name:        stages_covered
  type:        array of strings
  required:    true
  nullable:    false
  description: >
    Lifecycle stages included in this report's measurement scope.
  values:      [creation, review, approval, storage, distribution, archival,
               indexing, context-delivery]
  constraints:
    - Minimum 1 entry
    - Each entry must be a valid stage from the values list above

FIELD_08:
  name:        sla_compliance
  type:        array of objects
  required:    true
  nullable:    false
  description: >
    SLA compliance data per stage. One entry per stage in stages_covered.
    Each entry references the governing SLA policy and provides per-metric
    statistics aggregated across the cycle period.
  item_schema:
    stage:
      type:        string
      description: Stage name; must match an entry in stages_covered.
    sla_ref:
      type:        string
      description: >
        doc_id of the governing SLA policy for this stage.
        Must be one of DLMS-2026-0057 through DLMS-2026-0062.
    metrics:
      type:        array of metric objects
      description: One entry per metric defined in the cited SLA policy.
      metric_schema:
        metric_id:    string — metric identifier from the SLA (M01, M02, …)
        metric_name:  string — human-readable metric name from the SLA
        target:       string — target value from the SLA
        median:       number — median observed value this cycle
        p95:          number — 95th-percentile observed value this cycle
        breach_count: integer — documents breaching the SLA target
        breach_rate:  number — breach_count / documents_in_scope; decimal 0–1
        trend:        enum [improving, stable, degrading, insufficient-data]

FIELD_09:
  name:        throughput
  type:        object
  required:    true
  nullable:    false
  description: Document throughput counts for the reporting period.
  structure:
    documents_completed: integer — documents that exited all stages successfully
    documents_started:   integer — documents that entered at least one stage
    documents_failed:    integer — documents blocked at a stage gate; count
                         is cumulative (not cleared between cycles)

FIELD_10:
  name:        overall_performance_status
  type:        enum
  required:    true
  nullable:    false
  values:      [passing, warning, critical]
  derivation_rules:
    critical: >
      Any metric in sla_compliance[*].metrics has breach_rate exceeding
      the breach_threshold defined in the governing SLA policy.
    warning: >
      No critical breach AND any metric breach_rate exceeds the SLA's
      warning_threshold.
    passing: >
      All metrics for all stages within SLA warning thresholds.

## REQUIRED_SECTIONS

SUMMARY:
  heading:     ## SUMMARY
  required:    true
  position:    1
  constraints:
    - Exactly 2–3 sentences
    - Must state overall_performance_status value
    - Must state whether escalation was triggered (yes/no)
    - Must name the cycle_id and stages_covered

SCOPE:
  heading:     ## SCOPE
  required:    true
  position:    2
  constraints:
    - Must list source artefact types consumed (stage metrics logs,
      SLA policy documents)
    - At least one Covers: statement; at least one Excludes: statement
    - Must reference the governing SLA policies by doc_id

PERIOD:
  heading:     ## PERIOD
  required:    true
  position:    3
  required_fields:
    period_start:    Timestamp — must mirror FIELD_04
    period_end:      Timestamp — must mirror FIELD_05
    stages_covered:  Array — must mirror FIELD_07
    prior_report_ref: Report ID or null — must mirror FIELD_06
    context_notes:   >
      Operational events affecting metric interpretation
      (e.g. bootstrap phase, SLA revision mid-cycle). Null if none.

FINDINGS:
  heading:     ## FINDINGS
  required:    true
  position:    4
  description: >
    One finding per stage-metric combination showing warning or critical
    status, plus findings for throughput and overall trend.
    Findings are factual only.
  finding_schema:
    id:            string — F prefix + two-digit sequential number (F01, F02…)
    category:      string — stage name or metric identifier
    finding:       string — quantified observed fact; present tense
    trend:         enum — [improving, stable, degrading, insufficient-data]
    severity:      enum — [info, warning, critical]
    evidence_refs: array of strings — EV ids supporting this finding
  constraints:
    - Minimum 1 finding
    - Any breach_rate exceeding an SLA critical threshold → severity: critical
    - F ids sequential from F01 with no gaps

EVIDENCE:
  heading:     ## EVIDENCE
  required:    true
  position:    5
  evidence_schema:
    id:              string — EV prefix + two-digit sequential number
    source_artefact: string — metrics log path or SLA doc_id
    data_type:       enum — [metrics-log, stage-timing, audit-event-count,
                     sla-threshold]
    value:           string — extracted metric or threshold value
    period:          string — time period this evidence covers
  constraints:
    - Minimum 1 entry
    - EV ids sequential from EV01 with no gaps
    - Every finding's evidence_refs must resolve to valid EV ids

ANALYSIS:
  heading:     ## ANALYSIS
  required:    true
  position:    6
  analysis_schema:
    finding_ref:          string — F id being analysed
    interpretation:       string — significance and root cause if known
    contributing_factors: array of strings — optional
    pattern_ref:          string or null — KB pattern doc_id or null
  constraints:
    - Every finding with severity: warning or critical requires an
      analysis entry
    - Must note whether the trend is consistent with the prior period
      when prior_report_ref is non-null

RECOMMENDATIONS:
  heading:     ## RECOMMENDATIONS
  required:    true
  position:    7
  recommendation_schema:
    id:              string — R prefix + two-digit sequential number
    finding_refs:    array of strings — F ids motivating this recommendation
    recommendation:  string — present tense, actionable, specific
    directed_to:     string — agent:[slug] or sysadmin:dlm-sysadmin
    priority:        enum — [low, medium, high, immediate]
    expected_impact: string — quantified improvement expected
  constraints:
    - May be empty [] if no actionable findings arise
    - If escalation_required == true, at least one recommendation must
      have priority: immediate

ESCALATION:
  heading:     ## ESCALATION
  required:    true
  position:    8
  required_fields:
    escalation_required: >
      Boolean. True if overall_performance_status == critical OR any
      finding has severity: critical.
    escalation_basis:    >
      Array of F ids triggering escalation. Empty [] when
      escalation_required == false.
    escalation_target:   >
      The agent or role to notify. Null when escalation_required == false.
      Must be sysadmin:dlm-sysadmin for critical escalations.
    notification_sent:   Boolean. True once notification dispatched.

CHANGE_LOG:
  heading:     ## CHANGE_LOG
  required:    true
  position:    last
  format:      "- v[version] | [YYYY-MM-DD] | [agent_id] | [change summary]"

## OPTIONAL_SECTIONS

NOTES:
  heading:      ## NOTES
  description:  Non-normative commentary or baseline-establishment notes.
  when_to_include: >
    Bootstrap-phase baseline caveats or mid-cycle SLA revision impacts
    not captured in ANALYSIS.
  position:     After CHANGE_LOG

## VALIDATION_RULES

V01:
  rule:     report_id is non-null, matches PR-{YYYY}-{NNNN}, and is unique
            for the year.
  test:     >
    report_id != null AND
    report_id matches regex ^PR-\d{4}-\d{4}$ AND
    no other performance report for the same year shares this id.
  checked_by: CI Cycle Orchestrator; Audit Trail Agent

V02:
  rule:     generated_by must be agent:metrics-aggregator.
  test:     generated_by == "agent:metrics-aggregator"
  checked_by: CI Cycle Orchestrator

V03:
  rule:     period_end must be >= period_start.
  test:     period_end >= period_start
  checked_by: CI Cycle Orchestrator

V04:
  rule:     sla_compliance must contain exactly one entry per stage listed
            in stages_covered. Each entry's sla_ref must be one of
            DLMS-2026-0057 through DLMS-2026-0062.
  test:     >
    len(sla_compliance) == len(stages_covered) AND
    for each E in sla_compliance:
      E.stage IN stages_covered AND
      E.sla_ref IN [DLMS-2026-0057, DLMS-2026-0058, DLMS-2026-0059,
                    DLMS-2026-0060, DLMS-2026-0061, DLMS-2026-0062]
  checked_by: Agent Format Validator; CI Cycle Orchestrator

V05:
  rule:     Each metric in sla_compliance[*].metrics must have a metric_id
            that corresponds to a metric defined in the cited sla_ref policy.
  test:     >
    For all E in sla_compliance: for all M in E.metrics:
      M.metric_id exists in the metrics block of E.sla_ref document.
  checked_by: Agent Format Validator

V06:
  rule:     overall_performance_status must be correctly derived from the
            sla_compliance data per the FIELD_10 derivation rules.
  test:     >
    IF any sla_compliance[*].metrics[*].breach_rate exceeds the SLA's
       breach_threshold
      THEN overall_performance_status == "critical"
    ELSE IF any breach_rate exceeds the SLA's warning_threshold
      THEN overall_performance_status == "warning"
    ELSE overall_performance_status == "passing"
  checked_by: Metrics Aggregator; Agent Format Validator

V07:
  rule:     escalation_required must be true when overall_performance_status
            is critical or any finding has severity: critical.
  test:     >
    IF (overall_performance_status == "critical" OR
        any FINDINGS[*].severity == "critical")
    THEN escalation_required == true
  checked_by: CI Cycle Orchestrator; Audit Trail Agent

V08:
  rule:     All nine required sections must be present and appear in the
            prescribed order.
  test:     >
    Sections SUMMARY, SCOPE, PERIOD, FINDINGS, EVIDENCE, ANALYSIS,
    RECOMMENDATIONS, ESCALATION, CHANGE_LOG all present and in sequence.
  checked_by: Agent Format Validator; Template Validator
