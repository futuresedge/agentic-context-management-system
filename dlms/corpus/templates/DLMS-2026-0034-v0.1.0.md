## SUMMARY
This template defines the schema of a learning record — a structured
artefact produced when a Verifier Agent, Stage Orchestrator, or SysAdmin
identifies a finding that has systemic improvement value beyond the current
document. Learning records feed the Knowledge Base and are the primary input
to the Knowledge Base Contribution process governed by Wave 11 policies.
Each record captures one discrete finding, its root cause, and a
recommendation.

## TARGET_DOC_TYPE
learning-record

## PURPOSE
A learning record externalises knowledge gained during a DLMS process event
into a structured, retrievable artefact. It is not a log entry — it is an
improvement signal. Learning records are produced from verification outcomes
(linking to verification_id), stage gate failures, or SysAdmin observations.
They convert point-in-time findings into persistent institutional knowledge.

## SCHEMA

### Fields

FIELD_01:
  name:        learning_id
  type:        string
  required:    true
  nullable:    false
  format:      LRN-{doc_id}-{NNNN}
  example:     LRN-DLMS-2026-0030-0001
  description: Unique identifier for this learning record. doc_id is the
               document that triggered the learning. NNNN is a zero-padded
               sequential integer scoped to the source document. Immutable.

FIELD_02:
  name:        source_doc_id
  type:        string
  required:    true
  nullable:    false
  description: The doc_id of the DLMS document that triggered this learning.

FIELD_03:
  name:        source_doc_version
  type:        string
  required:    true
  nullable:    false
  format:      MAJOR.MINOR.PATCH
  description: The version of the source document at the time the learning
               was identified.

FIELD_04:
  name:        stage
  type:        enum
  required:    true
  nullable:    false
  values:      [creation, review, approval, storage, distribution, archival,
               indexing, system]
  description: The lifecycle stage during which this learning was identified.

FIELD_05:
  name:        linked_verification_id
  type:        string
  required:    false
  nullable:    true
  format:      VER-{doc_id}-{version}-{NNNN}
  description: The verification_id of the verification record from which
               this learning originates. Null for learnings that originate
               from stage gate failures or SysAdmin observations rather
               than from a verification record.

FIELD_06:
  name:        finding_type
  type:        enum
  required:    true
  nullable:    false
  values:      [schema-violation, process-gap, dependency-error,
               content-issue, taxonomy-issue, agent-behaviour,
               process-improvement]
  description: The category of the finding.
  value_guidance:
    schema-violation:   A field value, format, or structural rule was violated
    process-gap:        A step in a procedure was absent or undefined
    dependency-error:   A dependency was incorrectly declared or unresolved
    content-issue:      The document body had a substantive content problem
    taxonomy-issue:     A tag was used that did not exist in the vocabulary
    agent-behaviour:    An agent acted outside its defined context boundaries
    process-improvement: An observation about how a process could be improved

FIELD_07:
  name:        finding
  type:        string
  required:    true
  nullable:    false
  description: Concise description of what was observed. Must be specific
               enough to reproduce the finding without reading the source
               document. Present tense. Maximum 300 characters.
  constraints:
    - Maximum 300 characters
    - Must not be a vague general statement (e.g. "quality was poor")
    - Must identify the specific element, field, step, or agent involved

FIELD_08:
  name:        root_cause
  type:        string
  required:    false
  nullable:    true
  description: One-sentence diagnosis of why the finding occurred. Null
               when the root cause cannot be determined without further
               investigation. When provided, must be causal (explains why,
               not what).
  constraints:
    - Maximum 200 characters when non-null

FIELD_09:
  name:        recommendation
  type:        string
  required:    true
  nullable:    false
  description: Actionable improvement recommendation derived from this
               finding. Must specify what should change, not just that
               change is needed. May reference a policy, template, or
               agent instruction that should be updated.
  constraints:
    - Maximum 400 characters
    - Must be a concrete action, not a vague suggestion

FIELD_10:
  name:        severity
  type:        enum
  required:    true
  nullable:    false
  values:      [critical, major, minor, observation]
  description: The assessed severity of this finding.
  value_guidance:
    critical:     Finding would cause a process failure or data integrity
                  violation if not addressed; immediate escalation required
    major:        Finding represents a significant gap; should be addressed
                  within the current or next CI cycle
    minor:        Finding is a quality concern but does not block process;
                  address in next available maintenance window
    observation:  Informational finding with no required action; stored for
                  pattern analysis

FIELD_11:
  name:        created_by
  type:        string
  required:    true
  nullable:    false
  description: agent_id of the agent that produced this learning record.

FIELD_12:
  name:        created_at
  type:        datetime
  required:    true
  nullable:    false
  format:      ISO 8601 with timezone
  description: When this learning record was produced.

FIELD_13:
  name:        status
  type:        enum
  required:    true
  nullable:    false
  values:      [open, actioned, dismissed]
  description: Current status of this learning.
  transitions:
    open:      [actioned, dismissed]
    actioned:  []   (terminal — reopen only via SysAdmin directive)
    dismissed: []   (terminal — reopen only via SysAdmin directive)

FIELD_14:
  name:        actioned_by
  type:        string
  required:    false
  nullable:    true
  description: agent_id of the agent that actioned or dismissed this
               learning. Null when status is open.

FIELD_15:
  name:        actioned_at
  type:        datetime
  required:    false
  nullable:    true
  format:      ISO 8601 with timezone
  description: When this learning was actioned or dismissed. Null when
               status is open.

## VALIDATION_RULES

V01: learning_id matches LRN-{source_doc_id}-{NNNN}.
V02: source_doc_id resolves to an existing corpus document.
V03: stage is one of the eight valid enum values.
V04: finding_type is one of the seven valid enum values.
V05: finding is non-null and does not exceed 300 characters.
V06: recommendation is non-null and does not exceed 400 characters.
V07: severity is one of the four valid enum values.
V08: When linked_verification_id is non-null, it matches a VER-* format
     and references a verification record that exists for the source_doc_id.
V09: status is one of the three valid enum values.
V10: When status is actioned or dismissed, actioned_by and actioned_at
     are both non-null.
V11: When status is open, actioned_by and actioned_at are both null.
