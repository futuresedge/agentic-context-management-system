## SUMMARY
This template defines the canonical structure for all policy documents in
the DLMS corpus. Every policy except the four Wave-1 bootstrap documents must
be authored using this template. It enforces the section schema, field
constraints, and validation rules required for a compliant policy document.

## TARGET_DOC_TYPE
policy

### Additional_Fields

tier:
  name:        tier
  type:        enum
  required:    true
  nullable:    false
  position:    immediately after audit_ref
  values:
    1: Meta-Governance — apex policy; only DLMS-2026-0001 may hold this value
    2: Principles-Derived — directly enforces one or more system design principles
    3: Operational Lifecycle — governs document lifecycle stages and agent behaviour
    4: Technical Standards — governs structural and format standards
    5: SLA and Performance — governs performance targets and operational SLAs
  constraints:
    - tier: 1 is reserved for DLMS-2026-0001 exclusively
    - tier value must be consistent with the tier assignment in
      DLMS-2026-0001 (Policy Governance Policy) HIERARCHY section
    - tier is immutable after first approved version
    - tier is set by the Document Author and validated by
      Perspective Reviewer (lens-accuracy) against DLMS-2026-0001

principles_enforced:
  name:        principles_enforced
  type:        array of integers or empty array []
  required:    true
  nullable:    false
  position:    after tier
  description: >
    The system design principle numbers (1–11) that this policy
    enforces. Use [] if no direct principle enforcement applies.
  constraints:
    - All Tier 2 policies must list at least one principle number
    - Values must be integers in the range 1–11
    - Tier 3–5 policies may reference principles but are not required to

## REQUIRED_SECTIONS

SUMMARY:
  heading:     ## SUMMARY
  required:    true
  position:    1
  description: >
    A dense, factual statement of what this policy governs, who it
    applies to, and its tier. No narrative.
  constraints:
    - Exactly 2–3 sentences
    - Must identify the policy's subject domain
    - Must be parseable without reading the body

SCOPE:
  heading:     ## SCOPE
  required:    true
  position:    2
  description: >
    Declares what this policy applies to and what it explicitly excludes.
    All policy scope is positive (applies to X) and negative (excludes Y).
  constraints:
    - Must contain at least one 'Applies to:' statement
    - Must contain at least one 'Excludes:' statement
    - If no exclusions are relevant, state: "Excludes: nothing within the DLMS"
    - Bootstrap exceptions, if any, are declared here

DEFINITIONS:
  heading:     ## DEFINITIONS
  required:    true
  position:    3
  description: >
    Definitions of all terms used in the RULES section that carry
    specific meaning within this policy's domain. Terms are listed
    alphabetically. Each definition is a single precise statement.
  constraints:
    - Only terms that are used in this policy's rules are defined here
    - Definitions must not contradict definitions in other approved policies
    - If no domain-specific terms are needed, state: "No domain-specific
      definitions. All terms carry their standard DLMS meaning."

RULES:
  heading:     ## RULES
  required:    true
  position:    4
  description: >
    The enumerated, testable rules that constitute this policy.
    Each rule is independently verifiable (pass/fail binary).
    Rules are numbered sequentially (R01, R02, …).
  rule_schema:
    id:
      type:     string
      format:   R prefix + two-digit sequential number (R01, R02, …)
      required: true
    rule:
      type:     string
      required: true
      description: >
        A declarative statement of what must be true. Written in
        present tense, active voice. "X must Y" or "No X may Y."
        Does not explain why or how — that belongs in a procedure.
    test:
      type:     string
      required: true
      description: >
        How compliance is verified. Must be agent-parseable.
        States the condition that, if true, means the rule is met.
    checked_by:
      type:     string
      required: true
      description: >
        The agent or process responsible for checking this rule.
  constraints:
    - Minimum 1 rule; no maximum
    - Rules are numbered sequentially with no gaps
    - Rules must be individually testable — compound rules that
      cannot be verified as a single binary check must be split
    - No rule may contradict a higher-tier policy
    - Tier 2 policy rules must cite the principle number they enforce
      in the rule text or a principles_ref field
    - Rules are grouped under ### subheadings where the rule domain
      warrants logical separation (e.g. ### Creation_Rules,
      ### Versioning_Rules); ungrouped policies use a flat list

EXCEPTIONS_PROCESS:
  heading:     ## EXCEPTIONS_PROCESS
  required:    true
  position:    5
  description: >
    The process by which a time-limited, approved deviation from a
    specific rule in this policy may be granted.
  constraints:
    - Tier 1 and Tier 2 policies must state:
      "No exceptions process applies to this policy."
    - Tier 3–5 policies must describe the exceptions process or
      explicitly defer to DLMS-2026-0001 exceptions process
    - The exceptions process must state which agent has approval
      authority and what artefacts are produced

ENFORCEMENT:
  heading:     ## ENFORCEMENT
  required:    true
  position:    6
  description: >
    Which agents monitor and enforce this policy's rules, at what
    points in the pipeline enforcement occurs, and how violations
    are escalated.
  required_fields:
    primary_agent:    The agent primarily responsible for rule enforcement
    gate_positions:   The pipeline stages at which enforcement checks occur
    audit:            How violations are captured in the audit trail
    violation_type:   The tier classification of a violation
    escalation:       The escalation path per SysAdmin Escalation Policy
  constraints:
    - Every policy must have at least one primary_agent
    - Every policy must specify at least one gate_position
    - Escalation must reference the SysAdmin Escalation Policy by doc_id

REVIEW_SCHEDULE:
  heading:     ## REVIEW_SCHEDULE
  required:    true
  position:    7
  description: >
    The maximum review interval for this policy and the conditions
    that trigger an unscheduled review.
  required_fields:
    interval_max:      >
      Maximum time between reviews. Must comply with the tier
      maximum interval defined in DLMS-2026-0001 REVIEW_SCHEDULE:
        Tier 1–2: 12 months maximum
        Tier 3–4: 6 months maximum
        Tier 5:   3 months maximum
    trigger_conditions: >
      Array of conditions that trigger an unscheduled review.
      Minimum 2 conditions for all tiers.
  constraints:
    - interval_max must not exceed the tier maximum
    - trigger_conditions must include at least one CI-related condition

CHANGE_LOG:
  heading:     ## CHANGE_LOG
  required:    true
  position:    last
  description: >
    Ordered record of all versions, newest first. One entry per version.
  format:      "- v[version] | [YYYY-MM-DD] | [agent_id] | [change summary]"
  constraints:
    - Newest version first
    - Every version has exactly one entry
    - Entries are immutable once written
    - Change summary sufficient to understand what changed without a diff

## OPTIONAL_SECTIONS

NOTES:
  heading:     ## NOTES
  description: >
    Non-normative rationale, design context, or guidance for
    policy consumers and maintainers. Does not constitute a rule.
  when_to_include: >
    When the policy contains design decisions, historical context,
    or cross-policy relationships that benefit from explanation.
  position:    After CHANGE_LOG

## VALIDATION_RULES

V01:
  rule:     All eight REQUIRED_SECTIONS must be present and appear
            in the prescribed order.
  test:     >
    Sections SUMMARY, SCOPE, DEFINITIONS, RULES, EXCEPTIONS_PROCESS,
    ENFORCEMENT, REVIEW_SCHEDULE, CHANGE_LOG are all present and
    appear in that sequence.
  checked_by: Template Validator

V02:
  rule:     doc_type must be 'policy'. The additional field 'tier'
            must be present with a value of 1–5.
  test:     >
    doc_type == 'policy' AND tier IN [1, 2, 3, 4, 5]
  checked_by: Template Validator; Agent Format Validator

V03:
  rule:     retention_class must be RC-permanent for all policy documents.
  test:     retention_class == 'RC-permanent'
  checked_by: Indexing Verifier; Metadata Standard Policy enforcement

V04:
  rule:     SCOPE must contain at least one 'Applies to:' statement
            and at least one 'Excludes:' statement.
  test:     >
    'Applies to:' appears in SCOPE body AND
    'Excludes:' appears in SCOPE body
  checked_by: Template Validator

V05:
  rule:     RULES must contain at least one rule. Every rule must
            have a non-null id, rule, test, and checked_by field.
            Rule IDs must be sequential with no gaps (R01, R02, …).
  test:     >
    len(RULES entries) >= 1 AND
    for all R: R.id != null AND R.rule != null AND
    R.test != null AND R.checked_by != null AND
    R.id matches regex ^R\d{2}$ AND
    IDs form a contiguous sequence from R01
  checked_by: Template Validator

V06:
  rule:     Tier 1 and Tier 2 policies must state that no exceptions
            process applies. Tier 3–5 policies must describe or defer
            to an exceptions process.
  test:     >
    IF tier IN [1, 2] THEN EXCEPTIONS_PROCESS body contains
    'No exceptions process applies'
    IF tier IN [3, 4, 5] THEN EXCEPTIONS_PROCESS body contains
    a process description OR a reference to DLMS-2026-0001
  checked_by: Template Validator; Perspective Reviewer (lens-accuracy)

V07:
  rule:     ENFORCEMENT must specify primary_agent, at least one
            gate_position, audit method, violation_type, and escalation.
  test:     >
    primary_agent != null AND len(gate_positions) >= 1 AND
    audit != null AND violation_type != null AND escalation != null
  checked_by: Template Validator

V08:
  rule:     REVIEW_SCHEDULE interval_max must not exceed the maximum
            defined in DLMS-2026-0001 for this policy's tier.
  test:     >
    IF tier IN [1,2] THEN interval_max <= 12 months
    IF tier IN [3,4] THEN interval_max <= 6 months
    IF tier == 5    THEN interval_max <= 3 months
  checked_by: Template Validator; Perspective Reviewer (lens-accuracy)

V09:
  rule:     dependencies[] must include a reference to DLMS-2026-0001
            with rel: is-governed-by.
  test:     >
    dependencies contains entry where doc_id == 'DLMS-2026-0001'
    AND rel == 'is-governed-by'
  checked_by: Dependency Index Updater; Indexing Verifier

V10:
  rule:     No rule in RULES may contradict any rule in a higher-tier
            policy. Tier 2 policies must cite the principle number
            they enforce.
  test:     >
    Perspective Reviewer (lens-accuracy) explicitly checks for
    contradiction against Tier 1 and Tier 2 policies as a
    mandatory review condition.
    IF tier == 2 THEN principles_enforced[] is non-empty.
  checked_by: Perspective Reviewer (lens-accuracy); Review Synthesizer

V11:
  rule:     CHANGE_LOG must contain exactly one entry per version,
            newest first, in the prescribed format.
  test:     >
    len(CHANGE_LOG entries) == len(version history) AND
    CHANGE_LOG[0].version == current version AND
    all entries match: "- v[semver] | [YYYY-MM-DD] | [agent_id] | [summary]"
  checked_by: Storage Verifier; Version Control Agent
