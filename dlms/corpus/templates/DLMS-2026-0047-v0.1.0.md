## SUMMARY
This template defines the schema of a problem analysis artefact produced by
the Problem Analysis Agent during the creation stage. It structures a
multi-perspective examination of the problem framing and approach before
the Document Author begins drafting, ensuring the document addresses the
correct problem from a well-considered position.

## TARGET_DOC_TYPE
problem-analysis

## PURPOSE
The problem analysis is an intermediate creation-stage artefact consumed
exclusively by the Document Author. It is produced by the Problem Analysis
Agent, which receives the creation context (DLMS-2026-0046) as its sole
input. The agent examines the problem from multiple cognitive orientations
(lenses) per Multi-Perspective Review Policy (DLMS-2026-0017), synthesises
key insights, and recommends an authoring approach. The Document Author uses
the problem analysis to make informed content and scope decisions before
producing the first draft. If analysis_verdict is 'escalate', the Creation
Orchestrator halts the creation task and surfaces uncertainty to the SysAdmin.

## SCHEMA

### Header_Fields

FIELD_01:
  name:        analysis_id
  type:        string
  required:    true
  nullable:    false
  format:      PA-{doc_type}-{YYYYMMDD}-{NNNN}
  example:     PA-policy-20260309-0001
  description: Unique identifier for this problem analysis artefact. NNNN
               is a zero-padded sequential integer scoped to the date and
               doc_type. Immutable after assignment.

FIELD_02:
  name:        context_ref
  type:        string
  required:    true
  nullable:    false
  description: The context_id of the creation context artefact (per
               DLMS-2026-0046) that was the sole input to this analysis.
               The Problem Analysis Agent must not have read any artefact
               other than the referenced creation context.

FIELD_03:
  name:        analysed_by
  type:        string
  required:    true
  nullable:    false
  description: agent_id of the Problem Analysis Agent producing this
               artefact.

FIELD_04:
  name:        analysed_at
  type:        datetime
  required:    true
  nullable:    false
  format:      ISO 8601 with timezone
  description: Timestamp at which the analysis was completed.

### Content_Fields

FIELD_05:
  name:        perspective_analyses
  type:        list of perspective objects
  required:    true
  nullable:    false
  description: Multi-perspective examination of the problem. Each entry
               represents one cognitive lens applied to the problem
               statement drawn from the creation context. A minimum of
               two distinct lenses must be applied for all doc_types; high-
               stakes or novel problem domains should use four or more.
  constraints:
    - Minimum 2 entries required
    - Each lens_name must be distinct within the list

  perspective_object:
    lens_name:
      type:        string
      required:    true
      nullable:    false
      description: Name of the cognitive lens applied (e.g. 'accuracy',
                   'completeness', 'edge-cases', 'structural', 'impact',
                   'audience'). Controlled vocabulary is at the discretion
                   of the Problem Analysis Agent but lens names must be
                   distinct and self-descriptive.
    insight:
      type:        string
      required:    true
      nullable:    false
      description: The key finding from this perspective. One to three
                   sentences. Specific and actionable, not general.
      constraints:
        - Maximum 500 characters
    edge_cases:
      type:        list of strings
      required:    true
      nullable:    false
      description: Edge cases, exceptions, or boundary conditions surfaced
                   by this lens. Empty list [] permitted when the lens
                   identifies no edge cases.
    confidence:
      type:        enum
      required:    true
      nullable:    false
      values:      [high, medium, low]
      description: The Problem Analysis Agent's confidence in this lens's
                   finding given the available creation context. Low
                   confidence contributes to open_uncertainties.

FIELD_06:
  name:        problem_framing
  type:        string
  required:    true
  nullable:    false
  description: A synthesised restatement of the problem as understood after
               multi-perspective analysis. This is the Problem Analysis
               Agent's considered view of what the document must actually
               solve — which may refine or sharpen the problem_statement
               from the creation context. Two to four sentences.
  constraints:
    - Maximum 1000 characters

FIELD_07:
  name:        key_constraints
  type:        list of strings
  required:    true
  nullable:    false
  description: The binding constraints that the authoring approach must
               respect. These may be drawn from the creation context's
               constraints field or identified through analysis. Each entry
               is a concrete, actionable constraint for the Document Author.
  constraints:
    - At least one entry required

FIELD_08:
  name:        assumptions
  type:        list of strings
  required:    true
  nullable:    false
  description: Stated assumptions the analysis rests on that are not
               directly confirmed by the creation context. Each assumption
               is a potential source of error. Empty list [] permitted
               when no assumptions were required.

FIELD_09:
  name:        recommended_approach
  type:        string
  required:    true
  nullable:    false
  description: The Problem Analysis Agent's recommended authoring approach
               for the Document Author, including structural suggestions,
               scope prioritisation, or content emphasis. Two to five
               sentences. Not binding — the Document Author may deviate
               with justification.
  constraints:
    - Maximum 1000 characters

FIELD_10:
  name:        open_uncertainties
  type:        list of strings
  required:    true
  nullable:    false
  description: Questions, gaps, or uncertainties identified during analysis
               that could not be resolved from the creation context alone.
               Empty list [] when no uncertainties remain. Non-empty list
               does not block authoring unless analysis_verdict is
               'escalate'.

FIELD_11:
  name:        analysis_verdict
  type:        enum
  required:    true
  nullable:    false
  values:      [sufficient, insufficient, escalate]
  description: >
    The Problem Analysis Agent's assessment of whether the creation context
    provides sufficient basis for authoring to proceed.
    sufficient:     Context is adequate; Document Author may proceed.
    insufficient:   Context has gap(s) but authoring may still proceed
                    cautiously; open_uncertainties must be non-empty and
                    the Document Author must resolve them during drafting.
    escalate:       Authoring must not proceed; the Creation Orchestrator
                    must surface the analysis to the SysAdmin before
                    continuing. open_uncertainties must be non-empty when
                    verdict is 'escalate'.

## VALIDATION_RULES

V01: analysis_id is non-null and matches format
     PA-{doc_type}-{YYYYMMDD}-{NNNN}.
V02: context_ref is non-null and resolves to an existing creation-context
     artefact id.
V03: perspective_analyses contains at least two entries with distinct
     lens_name values.
V04: Each perspective_object has non-null and non-empty lens_name, insight,
     and confidence.
V05: problem_framing is non-null and non-empty.
V06: key_constraints contains at least one entry.
V07: analysis_verdict is one of [sufficient, insufficient, escalate].
V08: When analysis_verdict is 'escalate': open_uncertainties is non-empty.
V09: analysed_by is non-null and non-empty.
V10: analysed_at is a valid ISO 8601 datetime with timezone.
