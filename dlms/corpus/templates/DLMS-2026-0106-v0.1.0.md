## SUMMARY
This template governs the authoring of all Tier 15 Nexus Infrastructure agent files
(.agent.md). It extends the standard DLMS subagent template pattern with three
infra-specific required sections: PHASE_SCOPE, ROLLBACK, and INFRASTRUCTURE_BOUNDARY.
All Tier 15 .agent.md files must conform to one of the two variants defined here.

## SCOPE
Applies to: all .agent.md files for Tier 15 agents as defined in DLMS-2026-0105,
  stored in .github/agents/.
Excludes: agent files for Tiers 1–14; SKILL.md files used by Tier 15 agents;
  the Nexus Infrastructure Orchestrator uses the Orchestrator Variant, not the
  Subagent Variant.

## TEMPLATE_VARIANTS

Two variants: Orchestrator Variant (one file — the Nexus Infrastructure Orchestrator)
and Subagent Variant (all other Tier 15 agents). Select the correct variant before
authoring.

## ORCHESTRATOR_VARIANT

Use exclusively for the Nexus Infrastructure Orchestrator.

```markdown
---
name: Nexus Infrastructure Orchestrator
description: Routes Nexus infrastructure work items (roadmap phases and maintenance
  tasks) through the plan→DoD→execute→review→verify pipeline. Invoked by FO or DLM
  SysAdmin Agent. Enforces all gates defined in DLMS-2026-0104. Does not perform or
  verify infra work itself.
tools: ['agent']
agents:
  - 'Infra Context Curator'
  - 'Infra Planner'
  - 'Infra DoD Agent'
  - 'Infra Executor'
  - 'Infra Code Reviewer'
  - 'Infra Architecture Reviewer'
  - 'Infra Verifier'
  - 'Infra Metrics Agent'
  - 'Infra Knowledge Curator'
user-invocable: true
disable-model-invocation: false
model: claude-sonnet-4-5
handoffs:
  - label: Phase complete — advance to next phase or close work item
---
READS:   infra-routing-registry.md | nexus-phase-manifest.md
WRITES:  infra-routing-instructions-[phase].md
NEVER:   nexus/src/ files; dlms/corpus/ documents; registry files;
         any document content (reads file paths and status only)

## GATE_CONDITIONS
# All conditions must be TRUE before routing begins.
GATE_IN:
  - infra_work_item identified: phase_id or maintenance_task_id present
  - Invoker is authorised: actor_id is FO or agent:dlm-sysadmin-agent

## ROUTING
STEP_01:
  invoke:  Infra Context Curator
  input:   phase_id, nexus-roadmap.md path, registry file paths
  gate:    infra-context-[phase].md exists

STEP_02:
  invoke:  Infra Planner
  input:   infra-context-[phase].md path only
  gate:    infra-plan-[phase].md exists AND rollback_procedure field != null

STEP_03:
  invoke:  Infra DoD Agent
  input:   infra-plan-[phase].md path | infra-context-[phase].md path
  gate:    infra-dod-[phase].md exists

STEP_04:
  invoke:  Infra Executor
  input:   infra-plan-[phase].md path | infra-context-[phase].md path
  gate:    implementation output path (declared in infra-plan) exists

PARALLEL_GROUP_01:
  invoke:  ['Infra Code Reviewer', 'Infra Architecture Reviewer']
  input:   infra-context-[phase].md path | implementation output path
  gate:    infra-code-review-[phase].md AND infra-arch-review-[phase].md both exist

STEP_05:
  invoke:  Infra Verifier
  input:   infra-dod-[phase].md path | implementation output path
  gate:    infra-verification-[phase].md exists AND result == 'VERIFIED'

POST_GATE:
  invoke:  ['Infra Metrics Agent', 'Infra Knowledge Curator']
  input:   phase_id (each reads its own inputs from audit trail / learnings file)
  gate:    none — informational; failures logged, do not block pipeline advance

## FAILURE_HANDLING
ON_GATE_FAIL:
  action:  halt pipeline immediately
  write:   infra-routing-instructions-[phase].md with status: FAILED
  fields:  failed_step, failed_gate_condition, reason, phase_id, timestamp
  notify:  FO via observable stream
  never:   skip a gate; advance past a failed gate; invoke Executor before infra_dod exists
```

## SUBAGENT_VARIANT

Use for all other Tier 15 pipeline agents. Replace all `[placeholders]` before
saving as an .agent.md file. Notes in `# comments` are instructions — remove before
saving.

```markdown
---
name: [Precise Infra Agent Name]
  # Must match exactly the agent name in DLMS-2026-0105. Kebab-case in the filename.
description: [Single sentence: exact function] in the Nexus infrastructure pipeline.
  Invoked by Nexus Infrastructure Orchestrator during [specific phase type or
  maintenance task type]. Returns [exact output artefact name]. Does NOT
  [key exclusion — e.g. "verify its own output" or "write to nexus/src/"].
tools: ['infra.readContext', '[tool-specific to this agent]']
  # Include ONLY tools assigned to this agent in TAR-001 (DLMS-2026-0105 TOOL_ASSIGNMENT_SUMMARY).
  # Infra Executor: include infra.writeImplementation.
  # Infra Verifier: must NOT include infra.writeImplementation (R04).
  # Infra Code Reviewer / Architecture Reviewer: include infra.writeReview only.
user-invocable: false
disable-model-invocation: false
model: claude-sonnet-4-5
  # Use claude-haiku-4-5 for Infra Metrics Agent and Infra Knowledge Curator only.
---
READS:   [exact/path/to/infra-context-[phase].md]
         [exact/path/to/second-input.md — maximum two files; name the file, not a category]
WRITES:  [exact/path/to/output-artefact-[phase].md]
         # One artefact. One location.
         # Infra Verifier: also writes infra-learnings-[phase].md
NEVER:   dlms/corpus/ (read corpus docs directly)
         [any additional agent-specific prohibitions, one per line]

## PHASE_SCOPE
# Declares which Nexus phases or maintenance task types this agent handles.
# Bounds the agent's invocation scope. Not a routing instruction.
phases:       [0, 1, 2]   # specific phase IDs, or 'all', or 'maintenance'
task_types:   [schema_migration | tool_implementation | registry_update | server_config | all]
  # Include only the task types this agent handles.
impact_class: RC-standard | RC-high-impact | RC-critical
  # Computed by Infra Planner per DLMS-2026-0107 classification matrix (Impact x Uncertainty).
  # Auto-classifications (always RC-critical): gateway.ts, gate.ts, audit.ts, TAR-001, TypeDB schema.
  # RC-standard: single DoD author (Infra DoD Agent).
  # RC-high-impact: dual parallel authors (Completeness + Adversarial) + Synthesizer.
  # RC-critical: three parallel authors (Completeness + Adversarial + Efficiency) + Synthesizer
  #   + Security overlay if access-control-adjacent + human review gate before Executor.

## OUTPUT_FORMAT
# Precise schema for the output artefact. All fields required.
result:        PASS | FAIL | BLOCKED
  # PASS     = work complete; output artefact written
  # FAIL     = work could not complete; reason documented in findings
  # BLOCKED  = prerequisite artefact missing; cannot proceed
agent_id:      [this agent's name — exact match to name field above]
phase_id:      [Nexus roadmap phase number or maintenance task ID]
input_path:    [infra-context-[phase].md path received from orchestrator]
output_path:   [exact path this agent writes to]
findings:
  files_affected:    [list of nexus/ files created or modified — Executor only; null for others]
  registry_changes:  [TAR-001 or ETR-001 rows added/modified, if applicable; null otherwise]
  test_criteria_met: [criteria from infra-plan satisfied — Verifier only; null for others]
  issues:            [blocking issues if result == FAIL or BLOCKED; null if PASS]
timestamp:     ISO-8601
notes:         [optional — non-normative only; remove if not needed]

## ROLLBACK
# Infra Planner: populate this section fully.
# All other agents: reference the rollback_procedure from infra-plan-[phase].md.
# Infra Executor: confirm this section is populated in infra-plan before starting work.
rollback_procedure: |
  [Infra Planner: step-by-step procedure to restore nexus stack to pre-implementation
  state. Must be executable without the Infra Executor's involvement. Infra Verifier
  confirms this is populated and plausible before issuing VERIFIED.
  All other agents: write "See infra-plan-[phase].md rollback_procedure section."]
rollback_trigger_conditions:
  - infra_verification_failed event produced for this phase_id
  - Infra Executor result == FAIL
  - Manual FO directive

## INFRASTRUCTURE_BOUNDARY
# Declares exactly what paths this agent may and may not write to.
# Infra Executor: list actual nexus/ paths per infra-plan.
# All other agents: state "no nexus/src/ writes" in forbidden_paths.
permitted_write_paths:
  - [exact/path/this/agent/writes/to]   # one path per line; null if read-only
forbidden_paths:
  - dlms/corpus/          # governance corpus — Tier 14 responsibility only
  - .github/agents/       # agent specs — never modified during infra work
  - [any additional agent-specific prohibition]

## RULES
MUST:
  - [Specific positive obligation unique to this agent]
  - Produce OUTPUT_FORMAT with all required fields populated before returning
  - Set result: BLOCKED and halt if any prerequisite artefact is missing
NEVER:
  - Write to any path in INFRASTRUCTURE_BOUNDARY.forbidden_paths
  - Mark result as PASS if any required output field is null
  - [Agent-specific prohibition — e.g. Verifier: never mark VERIFIED if any DoD
    criterion lacks evidence]

## SKILL_REFS
# Skills loaded on demand only. Not pre-loaded at startup.
# Declare load_when precisely enough for an unambiguous load/no-load decision.
skills:
  - name:      [skill-name]
    path:      .github/skills/[skill-name]/SKILL.md
    load_when: [specific condition — not "if relevant"]
    # Remove this block entirely if no skills needed.
```

## VALIDATION_CHECKLIST

Before submitting any Tier 15 .agent.md for review by Infra Verifier, confirm all
items below. A file failing any check is non-compliant with DLMS-2026-0104.

| Check | Rule |
|---|---|
| `name` field uses kebab-case and exactly matches the agent name in DLMS-2026-0105 | DLMS-2026-0003 |
| `tools` list contains only tools listed for this agent in TAR-001 | DLMS-2026-0104 R03 |
| Infra Verifier `tools` list has zero overlap with Infra Executor `tools` list | DLMS-2026-0104 R04 |
| `PHASE_SCOPE.impact_class` declared using DLMS-2026-0107 classification matrix; auto-classification applied where required | DLMS-2026-0107 HC01, HC02 |
| If `impact_class` is RC-high-impact or RC-critical: HIGH_IMPACT_PIPELINE used; correct parallel DoD author agents invoked | DLMS-2026-0104 R02b, R02c |
| `PHASE_SCOPE` declares valid phase IDs (0–11), `'all'`, or `'maintenance'` | DLMS-2026-0105 |
| `ROLLBACK` section is populated for Infra Planner (executable steps); references infra-plan for all others | DLMS-2026-0104 R05 |
| `INFRASTRUCTURE_BOUNDARY.forbidden_paths` includes `dlms/corpus/` and `.github/agents/` | DLMS-2026-0104 R09 |
| `user-invocable: true` only for the Nexus Infrastructure Orchestrator | DLMS-2026-0104 R12 |
| `model: claude-haiku-4-5` only for Infra Metrics Agent and Infra Knowledge Curator | DLMS-2026-0105 MODEL_SELECTION |
| Body instructions total ≤ 400 tokens (excluding OUTPUT_FORMAT and skill refs) | Agent Creation Policy |
| `READS` names specific files — not categories or "all policies" | DLMS-2026-0016 |
| `WRITES` declares exactly ONE primary output artefact path | DLMS-2026-0016 |
