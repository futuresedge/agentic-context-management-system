## SUMMARY
This template defines the schema of a version log artefact produced and
maintained by the Storage Agent. One version log exists per corpus document
and accumulates a storage-level record of every version stored, complementing
the embedded CHANGE_LOG within corpus documents with richer storage metadata.

## TARGET_DOC_TYPE
version-log

## PURPOSE
The version log is a standalone Storage stage artefact produced by the
Storage Agent when a document first enters the storage stage and updated
(appended) on every subsequent version storage. It records file-level
metadata — file path, hash, stored_by, and DoD reference — that is not
captured in the document's embedded CHANGE_LOG. It does not replace the
CHANGE_LOG in the corpus document, which remains the human-readable
change record within the document body. The version log is the machine-
readable storage audit record. It is consumed by the Version Control Agent
when checking storage completeness and by the CI Cycle for consistency
checks. The log_id is scoped to the doc_id; one log exists per document for
its entire lifecycle, with entries appended on each storage event.

## SCHEMA

### Header_Fields

FIELD_01:
  name:        log_id
  type:        string
  required:    true
  nullable:    false
  format:      VERSION-LOG-{doc_id}
  example:     VERSION-LOG-DLMS-2026-0030
  description: Unique identifier for this version log, scoped to the
               document it tracks. One version log exists per doc_id.
               The log_id is immutable. All version entries are appended
               to the same log rather than creating separate logs per
               version.

FIELD_02:
  name:        doc_id
  type:        string
  required:    true
  nullable:    false
  description: The DLMS doc_id of the document this version log tracks.

FIELD_03:
  name:        created_at
  type:        datetime
  required:    true
  nullable:    false
  format:      ISO 8601 with timezone
  description: Timestamp at which this version log was first created by
               the Storage Agent (corresponding to the first version stored).

FIELD_04:
  name:        maintained_by
  type:        string
  required:    true
  nullable:    false
  description: agent_id of the Storage Agent responsible for maintaining
               this log. Updated if the maintaining agent changes.

### Version_Entries

FIELD_05:
  name:        entries
  type:        list of version entry objects
  required:    true
  nullable:    false
  description: Ordered list of version storage records, one per version
               stored. Entries are appended in ascending version order;
               no entry may be modified or deleted after creation. The
               first entry corresponds to the initial storage of the
               document. Empty list [] is not valid — at minimum one entry
               exists when the log is created.
  constraints:
    - Must contain at least one entry
    - Entries must be in ascending version order
    - No version may be skipped between consecutive entries

  version_entry_object:
    version:
      type:        string
      required:    true
      nullable:    false
      format:      MAJOR.MINOR.PATCH
      description: The semver version of the document stored in this entry.
    stored_at:
      type:        datetime
      required:    true
      nullable:    false
      format:      ISO 8601 with timezone
      description: Timestamp at which this version was stored.
    stored_by:
      type:        string
      required:    true
      nullable:    false
      description: agent_id of the Storage Agent that stored this version.
    file_path:
      type:        string
      required:    true
      nullable:    false
      description: The canonical file path at which this version is stored,
                   matching the agent_path field in the document's
                   frontmatter.
      constraints:
        - Must match the agent_path value in the stored document's
          frontmatter
    file_hash:
      type:        string
      required:    false
      nullable:    true
      description: Content hash of the stored file (e.g. SHA-256). Nullable
                   where hashing is not supported by the storage
                   infrastructure. When populated, used by CI for integrity
                   checking.
    change_type:
      type:        enum
      required:    true
      nullable:    false
      values:      [major, minor, patch]
      description: The semver change type of this version relative to the
                   immediately preceding version. For the initial version
                   (first entry), change_type is 'minor' (first content
                   version) unless the initial version is a major release.
    change_summary:
      type:        string
      required:    true
      nullable:    false
      description: One sentence describing what changed in this version.
                   Derived from the document's CHANGE_LOG entry for this
                   version.
      constraints:
        - Maximum 300 characters
    preceded_by_version:
      type:        string
      required:    false
      nullable:    true
      format:      MAJOR.MINOR.PATCH
      description: The version immediately preceding this one. Null for the
                   first entry in the log.
    dod_passed_ref:
      type:        string
      required:    true
      nullable:    false
      description: The dod_id or audit event reference for the storage DoD
                   record (per DLMS-2026-0027) that was passed before this
                   version was stored.
    audit_event_ref:
      type:        string
      required:    true
      nullable:    false
      description: The audit event reference for the document-stored event
                   logged by the Audit Trail Agent when this version was
                   stored.

## VALIDATION_RULES

V01: log_id is non-null and matches format VERSION-LOG-{doc_id}.
V02: entries is non-empty.
V03: entries are ordered in ascending semver order with no version gaps
     between consecutive entries.
V04: For each entry: version, stored_at, stored_by, file_path, change_type,
     change_summary, dod_passed_ref, and audit_event_ref are all non-null.
V05: For each entry after the first: preceded_by_version equals the
     version of the immediately preceding entry.
V06: For the first entry: preceded_by_version is null.
V07: change_type for each entry matches the semver position that changed
     relative to preceded_by_version.
V08: file_path in each entry matches the agent_path in the corresponding
     stored document's frontmatter.
V09: stored_at is a valid ISO 8601 datetime with timezone for each entry.
V10: Existing entries must not be modified; only new entries may be appended.
