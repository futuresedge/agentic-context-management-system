## SUMMARY
This template defines the schema of a creation context artefact produced by
the Context Curator (Creation) at the start of every document creation task.
It is the minimum-sufficient information package delivered exclusively to the
Document Author and Problem Analysis Agent, scoped per Agent Context Boundary
Policy (DLMS-2026-0016).

## TARGET_DOC_TYPE
creation-context

## PURPOSE
The creation context is the single authorised intake artefact for the Document
Author Agent and Problem Analysis Agent during the creation stage. The Context
Curator (Creation) produces it by compressing all available intake material
into the minimum fields necessary for the authoring task. Nothing outside
this artefact may be consumed by the downstream creation-stage agents per
DLMS-2026-0016. Triggered by the Creation Orchestrator when a new document
creation request is received. One creation context is produced per creation
task. It is not a corpus document and is not subject to corpus lifecycle
governance.

## SCHEMA

### Header_Fields

FIELD_01:
  name:        context_id
  type:        string
  required:    true
  nullable:    false
  format:      CTX-creation-{doc_type}-{YYYYMMDD}-{NNNN}
  example:     CTX-creation-policy-20260309-0001
  description: Unique identifier for this creation context artefact. NNNN is
               a zero-padded sequential integer scoped to the date and
               doc_type. Immutable after assignment.

FIELD_02:
  name:        doc_type_requested
  type:        enum
  required:    true
  nullable:    false
  values:      [policy, standard, procedure, pattern, sla, reference,
               report, taxonomy, specification, template]
  description: The doc_type of the DLMS corpus document being created.

FIELD_03:
  name:        curator_agent
  type:        string
  required:    true
  nullable:    false
  description: agent_id of the Context Curator (Creation) producing this
               artefact. Must be distinct from the document_author agent_id
               where known, per DLMS-2026-0016.

FIELD_04:
  name:        curated_at
  type:        datetime
  required:    true
  nullable:    false
  format:      ISO 8601 with timezone
  description: Timestamp at which context curation was completed and this
               artefact was produced.

### Content_Fields

FIELD_05:
  name:        request_summary
  type:        string
  required:    true
  nullable:    false
  description: One to three sentence description of the creation request as
               understood by the Context Curator. Must be derived only from
               intake material — the curator must not add interpretation
               beyond what the intake material supports.
  constraints:
    - Maximum 500 characters

FIELD_06:
  name:        problem_statement
  type:        string
  required:    true
  nullable:    false
  description: A clear statement of the problem, gap, or need this document
               will address. One paragraph maximum. Derived directly from
               intake material.
  constraints:
    - Maximum 1000 characters

FIELD_07:
  name:        scope_boundaries
  type:        string
  required:    true
  nullable:    false
  description: What is explicitly within scope for the document to address.
               Used by the Document Author to bound the draft's content.
  constraints:
    - Maximum 500 characters

FIELD_08:
  name:        excluded_scope
  type:        string
  required:    true
  nullable:    false
  description: What is explicitly out of scope for this document. Must
               include at least one explicit exclusion derived from the
               intake context. Prevents scope creep during authoring.
  constraints:
    - Maximum 500 characters
    - Must contain at least one named exclusion (not just "none identified")

FIELD_09:
  name:        target_audience
  type:        string
  required:    true
  nullable:    false
  description: The primary consumer of the document being created. Typically
               an agent class or human role. The Document Author uses this
               to calibrate language and structural choices.
  constraints:
    - Maximum 200 characters

FIELD_10:
  name:        constraints
  type:        list of strings
  required:    true
  nullable:    false
  description: Binding constraints on the document's content, format, or
               scope — drawn from intake material, existing policies, or
               the gap register. Empty list [] is permitted only if no
               constraints exist; an explicit confirmation is required.
  constraints:
    - Each entry: maximum 300 characters

FIELD_11:
  name:        referenced_policies
  type:        list of dep objects
  required:    true
  nullable:    false
  description: Policies, standards, and templates the document must comply
               with, implement, or reference. Derived from intake context
               and the DLMS policy corpus. Each entry is a structured
               dependency object consistent with the DLMS dependency schema.
  dep_object:
    doc_id:       string — a valid DLMS doc_id
    rel:          enum — [is-governed-by, implements, references, supersedes]
    rationale:    string — one sentence explaining why this dependency applies
  constraints:
    - Empty list [] permitted only if genuinely no policy dependencies apply;
      a documented rationale is required in that case

FIELD_12:
  name:        template_assignment
  type:        string
  required:    true
  nullable:    false
  description: The template_id and doc_id of the content template to be used
               for the document being created. The Document Author must apply
               exactly the named template version. Determined by the
               doc_type_requested and the current template registry.
  constraints:
    - Format: "{template_id} / {doc_id}"
    - The referenced template must exist at draft status or above in corpus

## VALIDATION_RULES

V01: context_id is non-null and matches format
     CTX-creation-{doc_type}-{YYYYMMDD}-{NNNN}. NNNN is a four-digit
     zero-padded integer.
V02: doc_type_requested is one of the ten controlled enum values.
V03: curator_agent is non-null and non-empty.
V04: curated_at is a valid ISO 8601 datetime with timezone.
V05: request_summary, problem_statement, scope_boundaries, excluded_scope,
     and target_audience are all non-null and non-empty.
V06: excluded_scope contains at least one named exclusion (not "none").
V07: template_assignment is non-null and matches the format
     "{template_id} / {doc_id}" where the doc_id resolves to an existing
     corpus template.
V08: All doc_id values in referenced_policies exist in the DLMS corpus
     registry. All rel values are drawn from the four valid types defined
     in DLMS-2026-0020.
