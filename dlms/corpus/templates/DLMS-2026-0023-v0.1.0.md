## SUMMARY
This template defines the canonical schema for all audit event records in
the DLMS audit trail. Every auditable event captured by the Audit Trail Agent
must produce a record that conforms to this schema. It is the structural
realisation of the immutability and completeness requirements mandated by
the Audit Trail Policy (DLMS-2026-0015).

## TARGET_DOC_TYPE
audit-event

## SCHEMA

### Fields

FIELD_01:
  name:        event_id
  type:        string
  required:    true
  nullable:    false
  format:      AE-{YYYY}-{NNNNNN}
  description: Globally unique identifier for this audit event. YYYY is the
               year the event occurred; NNNNNN is a zero-padded sequential
               integer scoped to that calendar year. Assigned by the Audit
               Trail Agent at write time. Immutable after assignment.
  constraints:
    - Globally unique across all calendar years
    - Never reused, even for events related to archived documents
    - Gaps in sequence are permitted; duplicates are not

FIELD_02:
  name:        audit_ref
  type:        string
  required:    true
  nullable:    false
  format:      AUDIT-DLMS-{YYYY}-{NNNN} | AUDIT-SYSTEM-{YYYY}-{NNNNNN}
  description: Links this event to the DLMS document it concerns. Must match
               the audit_ref field of the document at the time of the event.
               System-level events not linked to a specific document use the
               AUDIT-SYSTEM-* format.
  constraints:
    - Document-scoped events: value must match a registered audit_ref in
      the DLMS document registry
    - System-level events: value must match AUDIT-SYSTEM-YYYY-NNNNNN

FIELD_03:
  name:        event_type
  type:        string (controlled)
  required:    true
  nullable:    false
  description: Category of auditable event. Must be a registered value from
               the Event Type Registry (/dlms/registry/event-type-registry.md).
               Free-text event types are prohibited per DLMS-2026-0015.
  constraints:
    - Value must exist in the Event Type Registry at the time of writing
    - New event types require SysAdmin approval before use
  examples:
    - document-created
    - status-transitioned
    - version-incremented
    - agent-context-accessed
    - verification-completed
    - approval-granted
    - dod-passed
    - dod-failed
    - document-archived
    - taxonomy-term-proposed

FIELD_04:
  name:        agent_id
  type:        string
  required:    true
  nullable:    false
  format:      {agent-role}:{instance-id} | sysadmin:{name} | bootstrap:{team}
  description: Identity of the agent that performed or triggered the event.
  constraints:
    - Must be a registerable agent identity
    - Cannot be null; use system:unknown if the originating agent cannot be
      determined (this value triggers an alert to the SysAdmin queue)

FIELD_05:
  name:        timestamp
  type:        datetime
  required:    true
  nullable:    false
  format:      ISO 8601 with timezone offset (YYYY-MM-DDTHH:MM:SS+HH:MM)
  description: Exact time the auditable event occurred. Immutable after write.
  constraints:
    - Must not be a future timestamp
    - Must be at or after the created_at of any document it references

FIELD_06:
  name:        doc_id
  type:        string
  required:    true
  nullable:    true
  format:      DLMS-{YYYY}-{NNNN}
  description: The DLMS document involved. Null only for system-level events
               that are not scoped to a specific document.
  constraints:
    - When non-null, must match a registered doc_id in the corpus registry

FIELD_07:
  name:        doc_version
  type:        string
  required:    false
  nullable:    true
  format:      MAJOR.MINOR.PATCH
  description: Version of the document at the time of the event. Null for
               system-level events or pre-versioning creation events.

FIELD_08:
  name:        stage
  type:        enum
  required:    true
  nullable:    false
  values:      [creation, review, approval, storage, distribution, archival,
               indexing, system]
  description: The lifecycle stage during which the event occurred.

FIELD_09:
  name:        before_state
  type:        string
  required:    false
  nullable:    true
  description: The state, field value, or condition that existed immediately
               before this event. Required for all state-transition events
               (e.g. status-transitioned, version-incremented). Null for
               non-transition events.

FIELD_10:
  name:        after_state
  type:        string
  required:    false
  nullable:    true
  description: The state or value that exists immediately after this event.
               Required for all state-transition events. Null for
               non-transition events.

FIELD_11:
  name:        outcome
  type:        enum
  required:    true
  nullable:    false
  values:      [success, failure, blocked, skipped]
  description: The result of the auditable action.
  constraints:
    - outcome: failure requires non-null error_detail
    - outcome: blocked requires non-null blocking_reason

FIELD_12:
  name:        action_detail
  type:        string
  required:    true
  nullable:    false
  description: One-sentence human-readable description of what occurred.
               Must be specific enough to diagnose the event without reading
               other fields. Must not duplicate the event_type value verbatim.
  constraints:
    - Maximum 200 characters
    - Must not contain internal agent reasoning or deliberation

FIELD_13:
  name:        error_detail
  type:        string
  required:    false
  nullable:    true
  description: Concise description of the error condition. Populated only
               when outcome is failure. Null otherwise.

FIELD_14:
  name:        blocking_reason
  type:        string
  required:    false
  nullable:    true
  description: Identifies what or who is blocking the action and why.
               Populated only when outcome is blocked. Null otherwise.

## VALIDATION_RULES

V01: event_id is non-null, matches AE-YYYY-NNNNNN, and is globally unique
     at time of write.
V02: audit_ref matches the document registry when doc_id is non-null, or
     matches AUDIT-SYSTEM-YYYY-NNNNNN when doc_id is null.
V03: event_type exists in the Event Type Registry at time of writing.
V04: timestamp is valid ISO 8601 and is not a future timestamp.
V05: stage is one of the eight valid enum values.
V06: outcome is one of the four valid enum values.
V07: When outcome is failure, error_detail is non-null.
V08: When outcome is blocked, blocking_reason is non-null.
V09: When event_type signals a state transition, before_state and
     after_state are both non-null.
V10: action_detail is non-null and does not exceed 200 characters.
