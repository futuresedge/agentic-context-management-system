## SUMMARY
This template defines the schema of a distribution log artefact produced by
the Distribution Orchestrator immediately after a distribution event
completes or fails. It is the authoritative record of distribution activity
for a specific document version, references an approved Distribution Plan,
and must be linked to at least one audit event per DLMS-2026-0015.

## TARGET_DOC_TYPE
distribution-log

## PURPOSE
The distribution log is the immutable post-distribution record of what
actually occurred during a distribution event. It is produced by the
Distribution Orchestrator after the event completes — whether fully
delivered, partially failed, or entirely failed — and references the
Distribution Plan (DLMS-2026-0053) that governed the event. The log captures
the outcome per recipient and generates references to audit events
(DLMS-2026-0015). One distribution log is produced per distribution event;
a redistribution event produces a new log referencing either the original or
a new plan. Log entries are immutable after creation; amendments are handled
by producing a subsequent distribution log with a new log_id.

## SCHEMA

### Header_Fields

FIELD_01:
  name:        log_id
  type:        string
  required:    true
  nullable:    false
  format:      DISTLOG-{doc_id}-{version}-{NNNN}
  example:     DISTLOG-DLMS-2026-0030-0.1.0-0001
  description: Unique identifier for this distribution log. NNNN increments
               per distribution event for the same doc_id and version.
               Immutable after the log is produced.

FIELD_02:
  name:        plan_ref
  type:        string
  required:    true
  nullable:    false
  description: The plan_id of the Distribution Plan (DLMS-2026-0053) that
               authorised this distribution event. Must reference an actual
               Distribution Plan artefact.

FIELD_03:
  name:        doc_id
  type:        string
  required:    true
  nullable:    false
  description: The DLMS doc_id of the document that was distributed.

FIELD_04:
  name:        doc_version
  type:        string
  required:    true
  nullable:    false
  format:      MAJOR.MINOR.PATCH
  description: The version of the document that was distributed.

FIELD_05:
  name:        distributed_by
  type:        string
  required:    true
  nullable:    false
  description: agent_id of the Distribution Orchestrator that executed the
               distribution event.

FIELD_06:
  name:        started_at
  type:        datetime
  required:    true
  nullable:    false
  format:      ISO 8601 with timezone
  description: Timestamp at which the distribution event began.

FIELD_07:
  name:        completed_at
  type:        datetime
  required:    true
  nullable:    false
  format:      ISO 8601 with timezone
  description: Timestamp at which the distribution event concluded,
               whether successful, partially successful, or failed.

### Outcomes

FIELD_08:
  name:        distribution_outcomes
  type:        list of outcome objects
  required:    true
  nullable:    false
  description: Per-recipient outcome records for the distribution event.
               Must include one entry for every recipient listed in the
               target_recipients of the referenced Distribution Plan.
               Must not contain entries for recipients not in the plan.
  constraints:
    - Minimum 1 entry required
    - Entry count must match target_recipients count in the linked plan

  outcome_object:
    recipient_id:
      type:        string
      required:    true
      nullable:    false
      description: agent_id, system identifier, or external party name
                   for the recipient. Must match a recipient_id in the
                   referenced Distribution Plan.
    status:
      type:        enum
      required:    true
      nullable:    false
      values:      [delivered, failed, pending]
      description: >
        delivered: Successfully delivered to this recipient.
        failed:    Delivery attempted but failed; failure_reason must be set.
        pending:   Delivery initiated but confirmation not yet received.
    delivered_at:
      type:        datetime
      required:    false
      nullable:    true
      format:      ISO 8601 with timezone
      description: Timestamp at which delivery was confirmed for this
                   recipient. Must be non-null when status is delivered.
                   Must be null when status is failed or pending.
    failure_reason:
      type:        string
      required:    false
      nullable:    true
      description: Description of why delivery failed. Required when
                   status is failed; must be null when status is delivered.
      constraints:
        - Maximum 500 characters

### Audit_Links

FIELD_09:
  name:        audit_event_refs
  type:        list of strings
  required:    true
  nullable:    false
  description: References to audit event identifiers generated during this
               distribution event, per DLMS-2026-0015 R03. Must contain at
               least one entry. Each entry is an audit event identifier
               (format: AUDIT-EVT-{YYYYMMDD}-{NNNN}).
  constraints:
    - Minimum 1 entry required
    - Each entry must match format AUDIT-EVT-{YYYYMMDD}-{NNNN}

## VALIDATION_RULES

V01: log_id is non-null and matches format
     DISTLOG-{doc_id}-{version}-{NNNN}.
V02: plan_ref references a valid Distribution Plan artefact (non-null).
V03: For each outcome with status: delivered, delivered_at is non-null.
V04: For each outcome with status: failed, failure_reason is non-null
     and delivered_at is null.
V05: distribution_outcomes count equals target_recipients count in
     the referenced Distribution Plan.
V06: All recipient_id values in distribution_outcomes correspond to
     recipient_id values in the referenced plan; no extra entries
     are permitted.
V07: audit_event_refs contains at least one entry; no null entries
     are permitted within the list.
V08: completed_at is not earlier than started_at.
V09: doc_version matches format MAJOR.MINOR.PATCH.
