## SUMMARY
This template defines the schema and structure of a learning synthesis
artefact (LSR) produced by the Learning Synthesizer once per CI cycle,
after the KB Agent has signalled contribution completion. It operationalises
the three pattern-detection categories defined in DLMS-2026-0064 R04 —
frequency spikes, cross-stage recurrences, and unactioned critical/major
entries — and satisfies the forward reference established in that policy.

## TARGET_DOC_TYPE
learning-synthesis

## SCHEMA

### Fields

FIELD_01:
  name:        report_id
  type:        string
  required:    true
  nullable:    false
  format:      LSR-{YYYY}-{NNNN}
  example:     LSR-2026-0001
  description: >
    Unique identifier for this learning synthesis artefact. NNNN is a
    zero-padded sequential integer scoped to the year. Format established
    in DLMS-2026-0064 NOTES. Immutable after assignment.

FIELD_02:
  name:        cycle_id
  type:        string
  required:    true
  nullable:    false
  format:      CYCLE-{YYYY}-{NNNN}
  description: The CI cycle this synthesis covers.

FIELD_03:
  name:        generated_by
  type:        string
  required:    true
  nullable:    false
  format:      agent:[agent-role-slug]
  constraints:
    - Must be agent:learning-synthesizer
    - Must differ from the KB Agent that made contributions in this cycle
      (Verification Independence Policy DLMS-2026-0014; enforced by
      DLMS-2026-0064 R07 — Tier 2 violation if breached; cannot be
      waived by Tier 3 exceptions process)

FIELD_04:
  name:        period_start
  type:        datetime
  required:    true
  nullable:    false
  format:      ISO 8601 with timezone offset
  description: Start of the CI cycle period covered by this synthesis.

FIELD_05:
  name:        period_end
  type:        datetime
  required:    true
  nullable:    false
  format:      ISO 8601 with timezone offset
  constraints:
    - period_end must be >= period_start

FIELD_06:
  name:        prior_synthesis_ref
  type:        string or null
  required:    true
  nullable:    true
  description: >
    The report_id (LSR-{YYYY}-{NNNN}) of the most recent prior learning
    synthesis artefact. Null for the first synthesis. Enables cross-cycle
    pattern comparison.

FIELD_07:
  name:        kb_scope
  type:        object
  required:    true
  nullable:    false
  description: Describes the KB data consumed for this synthesis.
  structure:
    stages_included:
      type:        array of strings
      description: Stage values from TMPL-learnings-001 FIELD_04 that
                   were included in synthesis.
    finding_types_included:
      type:        array of strings
      description: finding_type values from TMPL-learnings-001 FIELD_06
                   included in synthesis.
    entries_analysed:
      type:        integer
      description: Total KB entries read by the Learning Synthesizer.
    deferred_entries_included:
      type:        boolean
      description: >
        True when this synthesis includes accumulated deferred entries
        from prior cycles (per DLMS-2026-0064 R03).

FIELD_08:
  name:        entry_count_current_cycle
  type:        integer
  required:    true
  nullable:    false
  description: >
    Count of KB entries contributed during this CI cycle (status: actioned
    in the current cycle window). Does not include prior deferred entries.
  constraints:
    - Must be >= 0
    - When entry_count_current_cycle + entry_count_accumulated_deferred < 10,
      synthesis_status must be deferred-insufficient-entries per
      DLMS-2026-0064 R02

FIELD_09:
  name:        entry_count_accumulated_deferred
  type:        integer
  required:    true
  nullable:    false
  description: >
    Count of accumulated deferred KB entries from prior cycles that were
    not included in any previous synthesis. Zero when no deferred backlog exists.
  constraints:
    - Must be >= 0

FIELD_10:
  name:        pattern_count
  type:        integer
  required:    true
  nullable:    false
  description: >
    Total patterns detected across all three pattern sub-arrays in FIELD_13.
    Must equal the sum of len(frequency_spikes) + len(cross_stage_recurrences)
    + len(unactioned_critical_major).
  constraints:
    - Must be >= 0
    - When synthesis_status == deferred-insufficient-entries, must be 0

FIELD_11:
  name:        synthesis_status
  type:        enum
  required:    true
  nullable:    false
  values:      [complete, deferred-insufficient-entries]
  description: >
    complete: synthesis was performed; patterns field contains results.
    deferred-insufficient-entries: total entries < 10 threshold per
      DLMS-2026-0064 R02; synthesis deferred; patterns all empty.

FIELD_12:
  name:        deferred_reason
  type:        string or null
  required:    true
  nullable:    true
  description: >
    Human-readable reason for deferral. Required and non-null when
    synthesis_status == deferred-insufficient-entries (per DLMS-2026-0064
    R02). Must state the entry counts. Null when synthesis_status == complete.
  example: >
    "Insufficient entries: 6 current-cycle + 0 accumulated = 6 total,
     below the 10-entry minimum threshold."

FIELD_13:
  name:        patterns
  type:        object
  required:    true
  nullable:    false
  description: >
    Detected patterns across exactly three sub-fields per DLMS-2026-0064 R04.
    All three sub-fields are required and must be present. When
    synthesis_status == deferred-insufficient-entries, all three sub-arrays
    must be empty [].
  sub_fields:
    frequency_spikes:
      type:        array of objects
      description: >
        Stages+finding_type combinations where observed count exceeds
        mean + 1 standard deviation (DLMS-2026-0064 R04 criterion a).
      item_schema:
        id:
          format:      FS-{NN}
          description: Sequential from FS-01; no gaps.
        stage:
          type:        string
          description: Stage value from TMPL-learnings-001 FIELD_04.
        finding_type:
          type:        string
          description: finding_type value from TMPL-learnings-001 FIELD_06.
        count:
          type:        integer
          description: Observed count in the synthesis window.
        mean:
          type:        number
          description: Historical mean for this stage+finding_type combination.
        sigma_threshold_used:
          type:        number
          description: Standard deviation value used as detection threshold.
        kb_entry_refs:
          type:        array of strings
          description: learning_ids from TMPL-learnings-001 driving this spike.
    cross_stage_recurrences:
      type:        array of objects
      description: >
        finding_type values appearing in 2 or more distinct stages in the
        synthesis window (DLMS-2026-0064 R04 criterion b).
      item_schema:
        id:
          format:      CSR-{NN}
          description: Sequential from CSR-01; no gaps.
        finding_type:
          type:        string
        stages_affected:
          type:        array of strings
          description: Stage values where this finding_type was observed.
          constraints:
            - Minimum 2 entries
        occurrence_count:
          type:        integer
          description: Total KB entries for this finding_type across all stages.
        kb_entry_refs:
          type:        array of strings
    unactioned_critical_major:
      type:        array of objects
      description: >
        KB entries with severity critical or major that remain with
        status: open beyond the current cycle (DLMS-2026-0064 R04
        criterion c).
      item_schema:
        id:
          format:      UCM-{NN}
          description: Sequential from UCM-01; no gaps.
        finding_type:
          type:        string
        severity:
          type:        enum
          values:      [critical, major]
        age_in_cycles:
          type:        integer
          description: Number of CI cycles this entry has remained open.
        kb_entry_ref:
          type:        string
          description: Single learning_id of the unactioned entry.
        escalation_required:
          type:        boolean
          description: >
            True for severity: critical entries. Major entries set this
            false unless age_in_cycles exceeds 3.

## REQUIRED_SECTIONS

SUMMARY:
  heading:     ## SUMMARY
  required:    true
  position:    1
  constraints:
    - Exactly 2–3 sentences
    - Must state synthesis_status, pattern_count, and entry counts
    - Must state whether escalation was triggered (yes/no)
    - When deferred, must state deferred_reason

SCOPE:
  heading:     ## SCOPE
  required:    true
  position:    2
  constraints:
    - Must state kb_scope entries (stages, finding_types, entry counts)
    - Must note whether deferred entries were included
    - At least one Covers: statement and one Excludes: statement

PERIOD:
  heading:     ## PERIOD
  required:    true
  position:    3
  required_fields:
    period_start:                    Timestamp — mirrors FIELD_04
    period_end:                      Timestamp — mirrors FIELD_05
    entry_count_current_cycle:       Integer — mirrors FIELD_08
    entry_count_accumulated_deferred: Integer — mirrors FIELD_09
    prior_synthesis_ref:             LSR ID or null — mirrors FIELD_06
    context_notes:                   Null if none

FINDINGS:
  heading:     ## FINDINGS
  required:    true
  position:    4
  description: >
    One finding per detected pattern across all three categories in
    FIELD_13. When synthesis_status == deferred-insufficient-entries,
    one explicit 'synthesis-deferred' info finding with the deferred_reason.
  finding_schema:
    id:            string — F prefix + two-digit sequential number
    category:      enum — [frequency-spike, cross-stage-recurrence,
                   unactioned-critical-major, synthesis-deferred]
    finding:       string — factual pattern description; quantified
    trend:         enum — [improving, stable, degrading, insufficient-data]
    severity:      enum — [info, warning, critical]
    evidence_refs: array of strings — EV ids
  constraints:
    - F ids sequential from F01 with no gaps
    - Each unactioned_critical_major entry with severity: critical
      yields a finding with severity: critical
    - When deferred: exactly one finding with category: synthesis-deferred

EVIDENCE:
  heading:     ## EVIDENCE
  required:    true
  position:    5
  evidence_schema:
    id:              string — EV prefix + two-digit number
    source_artefact: string — KB slot path (kb/{stage}/{finding_type}/)
                     or learning_id
    data_type:       enum — [kb-entry, kb-aggregate, learning-record]
    value:           string — count, id, or description
    period:          string — cycles covered
  constraints:
    - Minimum 1 entry even when deferred (evidence of entry counts)
    - EV ids sequential from EV01 with no gaps
    - Every finding's evidence_refs must resolve to valid EV ids

ANALYSIS:
  heading:     ## ANALYSIS
  required:    true
  position:    6
  analysis_schema:
    finding_ref:          string — F id
    interpretation:       string — significance and systemic implications
    contributing_factors: array of strings — optional
    pattern_ref:          string or null — cross-reference to prior LSR
  constraints:
    - Every finding with severity: warning or critical requires an entry
    - When synthesis_status == deferred-insufficient-entries, one analysis
      entry must note the rollover count and next expected synthesis cycle

RECOMMENDATIONS:
  heading:     ## RECOMMENDATIONS
  required:    true
  position:    7
  description: >
    Routing recommendations per DLMS-2026-0064 R06. Two mandatory routing
    obligations must always be present: (a) all findings to SysAdmin briefing
    queue; (b) direct alert to sysadmin:dlm-sysadmin for critical entries.
  recommendation_schema:
    id:              string — R prefix + two-digit number
    finding_refs:    array of strings — F ids
    recommendation:  string — present tense, actionable
    directed_to:     string — agent:[slug] or sysadmin:dlm-sysadmin
    priority:        enum — [low, medium, high, immediate]
    expected_impact: string
  constraints:
    - Minimum 1 recommendation routing findings to SysAdmin briefing queue
    - When any unactioned_critical_major entry exists, an additional
      recommendation with priority: immediate directed to
      sysadmin:dlm-sysadmin is mandatory (per DLMS-2026-0064 R06)
    - Even when synthesis_status == deferred-insufficient-entries, a
      routing recommendation noting deferral must be present

ESCALATION:
  heading:     ## ESCALATION
  required:    true
  position:    8
  required_fields:
    escalation_required: >
      Boolean. True when any unactioned_critical_major entry in FIELD_13
      has escalation_required: true.
    escalation_basis:    >
      Array of UCM ids triggering escalation. Empty [] when
      escalation_required == false.
    escalation_target:   >
      Must be sysadmin:dlm-sysadmin when escalation_required == true.
      Null otherwise.
    notification_sent:   Boolean. True once notification dispatched.

CHANGE_LOG:
  heading:     ## CHANGE_LOG
  required:    true
  position:    last
  format:      "- v[version] | [YYYY-MM-DD] | [agent_id] | [change summary]"

## OPTIONAL_SECTIONS

NOTES:
  heading:      ## NOTES
  description:  Non-normative commentary on pattern detection methodology.
  when_to_include: >
    Bootstrap-phase baseline notes; sigma-threshold calibration rationale;
    inter-cycle deferred entry accumulation history.
  position:     After CHANGE_LOG

## VALIDATION_RULES

V01:
  rule:     report_id is non-null, matches LSR-{YYYY}-{NNNN}, and is unique
            for the year.
  test:     >
    report_id != null AND
    report_id matches regex ^LSR-\d{4}-\d{4}$ AND
    no other learning synthesis artefact for the same year shares this id.
  checked_by: CI Cycle Orchestrator; Audit Trail Agent

V02:
  rule:     generated_by must be agent:learning-synthesizer AND must differ
            from the KB Agent that contributed entries in this cycle.
            Breach is a Tier 2 violation per DLMS-2026-0064 R07.
  test:     >
    generated_by == "agent:learning-synthesizer" AND
    generated_by != kb_agent_for_this_cycle
  checked_by: CI Cycle Orchestrator; Agent Format Validator

V03:
  rule:     period_end must be >= period_start.
  test:     period_end >= period_start
  checked_by: CI Cycle Orchestrator

V04:
  rule:     patterns must contain exactly three sub-fields: frequency_spikes,
            cross_stage_recurrences, and unactioned_critical_major. No
            sub-field may be absent.
  test:     >
    patterns.frequency_spikes != null AND
    patterns.cross_stage_recurrences != null AND
    patterns.unactioned_critical_major != null
  checked_by: Agent Format Validator; Learning Synthesizer

V05:
  rule:     When synthesis_status == deferred-insufficient-entries: all three
            pattern sub-arrays must be empty [], pattern_count must be 0,
            and deferred_reason must be non-null.
  test:     >
    IF synthesis_status == "deferred-insufficient-entries" THEN
      len(patterns.frequency_spikes) == 0 AND
      len(patterns.cross_stage_recurrences) == 0 AND
      len(patterns.unactioned_critical_major) == 0 AND
      pattern_count == 0 AND
      deferred_reason != null
  checked_by: Agent Format Validator; Learning Synthesizer

V06:
  rule:     pattern_count must equal the sum of entries across all three
            pattern sub-arrays.
  test:     >
    pattern_count ==
      len(patterns.frequency_spikes) +
      len(patterns.cross_stage_recurrences) +
      len(patterns.unactioned_critical_major)
  checked_by: Agent Format Validator

V07:
  rule:     escalation_required in ESCALATION must be true when any entry
            in patterns.unactioned_critical_major has escalation_required: true.
  test:     >
    IF any patterns.unactioned_critical_major[*].escalation_required == true
    THEN ESCALATION.escalation_required == true
  checked_by: CI Cycle Orchestrator; Audit Trail Agent

V08:
  rule:     cross_stage_recurrences entries must each have stages_affected
            with a minimum of 2 distinct stage values.
  test:     >
    For all CSR in patterns.cross_stage_recurrences:
      len(set(CSR.stages_affected)) >= 2
  checked_by: Agent Format Validator; Learning Synthesizer

V09:
  rule:     All nine required sections must be present and appear in the
            prescribed order.
  test:     >
    Sections SUMMARY, SCOPE, PERIOD, FINDINGS, EVIDENCE, ANALYSIS,
    RECOMMENDATIONS, ESCALATION, CHANGE_LOG all present and in sequence.
  checked_by: Agent Format Validator; Template Validator

## NOTES
This template satisfies the forward reference declared in
DLMS-2026-0064 (Learning Synthesis Policy) under the NOTES section,
where interim LSR format was provisionally defined pending this template's
creation. The LSR-{YYYY}-{NNNN} identifier format was established in that
document and is authoritative.

The independence constraint in V02 (generated_by ≠ KB Agent) is not waivable
through the Tier 3 exceptions process — it is a Tier 2 constraint inherited
from DLMS-2026-0014 and enforced by DLMS-2026-0064 R07.
