## SUMMARY
This template defines the canonical structure of a verification record
produced by any Verifier Agent in the DLMS. Every verification action
at any lifecycle stage must produce a record conforming to this schema.
It is the structural realisation of independence and perspective requirements
from the Verification Independence Policy (DLMS-2026-0014) and the
Multi-Perspective Review Policy (DLMS-2026-0017).

## TARGET_DOC_TYPE
verification-record

## SCHEMA

### Fields

FIELD_01:
  name:        verification_id
  type:        string
  required:    true
  nullable:    false
  format:      VER-{doc_id}-{version}-{NNNN}
  example:     VER-DLMS-2026-0030-0.1.0-0001
  description: Unique identifier for this verification record. NNNN is a
               zero-padded sequential integer scoped to the doc_id+version
               pair. Immutable after assignment.
  constraints:
    - Unique per doc_id + version combination
    - Multiple verifications of the same document version each increment NNNN

FIELD_02:
  name:        doc_id
  type:        string
  required:    true
  nullable:    false
  description: The DLMS doc_id of the document being verified.

FIELD_03:
  name:        doc_version
  type:        string
  required:    true
  nullable:    false
  format:      MAJOR.MINOR.PATCH
  description: The version of the document being verified.

FIELD_04:
  name:        verifier_agent
  type:        string
  required:    true
  nullable:    false
  description: agent_id of the Verifier Agent producing this record.
  constraints:
    - Must differ from the document's created_by value (DLMS-2026-0014 R01)
    - Must differ from the document's approved_by value if known at this point

FIELD_05:
  name:        timestamp
  type:        datetime
  required:    true
  nullable:    false
  format:      ISO 8601 with timezone
  description: The time at which the verification was completed and this
               record was produced.

FIELD_06:
  name:        stage
  type:        enum
  required:    true
  nullable:    false
  values:      [creation, review, approval, storage, distribution, archival,
               indexing]
  description: The lifecycle stage during which this verification occurred.

FIELD_07:
  name:        verification_type
  type:        enum
  required:    true
  nullable:    false
  values:      [stage-gate, perspective-review, format-validation,
               schema-validation, independence-check]
  description: The category of verification being performed.

FIELD_08:
  name:        perspectives_applied
  type:        list of strings
  required:    true
  nullable:    false
  description: >
    Named list of lenses or verification dimensions applied. For
    perspective-review type, this lists each Perspective Reviewer lens
    per DLMS-2026-0017. For other types, lists the validation dimensions
    checked (e.g. ["schema", "naming", "frontmatter-fields"]).
  constraints:
    - Must contain at least one entry
    - For perspective-review type, must meet the minimum lens count per
      DLMS-2026-0017 for the document's doc_type

FIELD_09:
  name:        findings
  type:        list of finding objects
  required:    true
  nullable:    false
  description: One finding object per perspective or dimension applied.
               Empty list [] is not permitted — at minimum, a pass finding
               with no observations must be recorded per perspective.

  finding_object:
    perspective:   string — name of the lens or dimension this finding covers
    verdict:       enum — [pass, pass-with-observations, fail]
    observations:  list of strings — specific actionable findings; empty []
                   when verdict is pass; required when verdict is
                   pass-with-observations or fail
    severity:      enum | null — [critical, major, minor]; null when
                   verdict is pass

FIELD_10:
  name:        overall_verdict
  type:        enum
  required:    true
  nullable:    false
  values:      [pass, pass-with-observations, fail]
  description: >
    The aggregate verdict across all perspectives.
    Derivation rules:
      - If any finding has verdict: fail → overall_verdict: fail
      - If no fails but any finding has verdict: pass-with-observations
        → overall_verdict: pass-with-observations
      - If all findings have verdict: pass → overall_verdict: pass

FIELD_11:
  name:        blocking_findings
  type:        list of finding objects
  required:    true
  nullable:    false
  description: Subset of findings where verdict is fail. Empty list [] when
               overall_verdict is pass or pass-with-observations.
  constraints:
    - Must be empty [] when overall_verdict is pass or pass-with-observations
    - Must be non-empty when overall_verdict is fail

FIELD_12:
  name:        observations_summary
  type:        list of strings
  required:    true
  nullable:    false
  description: Flat list of all actionable observations across all findings
               where verdict is pass-with-observations or fail. Empty list []
               when overall_verdict is pass. Each observation must be
               independently addressable.

FIELD_13:
  name:        notes
  type:        string
  required:    false
  nullable:    true
  description: Free-text notes from the Verifier Agent. Nullable. Must not
               contain reasoning or deliberation — only structured
               observation or escalation notes.
  constraints:
    - Maximum 500 characters

## VALIDATION_RULES

V01: verification_id is non-null, matches VER-{doc_id}-{version}-{NNNN},
     and is unique for this doc_id + version pair.
V02: verifier_agent differs from the document's created_by.
V03: perspectives_applied contains at least one entry.
V04: findings contains exactly one entry per item in perspectives_applied.
V05: overall_verdict is correctly derived from the findings list per the
     derivation rules in FIELD_10.
V06: blocking_findings is empty [] when overall_verdict is pass or
     pass-with-observations.
V07: blocking_findings is non-empty when overall_verdict is fail.
V08: observations_summary is empty [] when overall_verdict is pass.
V09: Each observation in observations_summary is a discrete, addressable
     finding — not a general comment.
V10: For verification_type: perspective-review, perspectives_applied meets
     the minimum lens count for the doc_type per DLMS-2026-0017.
